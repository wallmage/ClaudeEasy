# 当前测试基线

本文件记录现行测试范围，不定义产品功能。产品要求见 `docs/superpowers/specs/2026-07-20-claude-easy-skill-design.md`、`claude-easy/references/policy-core.md` 及 `SKILL.md` 按任务路由到的模块策略。

## 必须通过

- 策略路由合同：七个策略文件必须齐全，旧单体策略不得继续存在；`SKILL.md` 必须要求所有任务先读共同策略，并分别写明 Diagnostics、Patch、订阅更新、备份恢复、平台和跨模块维护的读取组合。合同测试把七个文件作为一份完整策略检查现行规则，防止拆分漏掉内容。

- 双平台订阅更新说明：先为全部远程订阅创建更新前备份。macOS 使用 Foundation 原生请求，并从当前运行的 ClashX Meta 动态生成请求身份；Windows 使用 `curl -q --config -` 且不设置 User-Agent。两端都要完成候选检查、当前订阅加载、档位运行检查、失败恢复和自动更新关闭复查。

- 平台订阅更新说明：macOS 直接生成补丁候选；Windows 核对受管全局脚本，并通过 Clash Verge Rev 的重新激活订阅入口执行转换。两端共同覆盖下载候选解析、现行 Patch、YAML、二次转换一致性、Mihomo、整批写入、当前订阅加载、档位运行检查、失败恢复和自动更新关闭复查。

- Windows `profiles.yaml` 解析门禁：`items` 有内容却无法完整归属受支持块状项目时整批拒绝；`type` 只接受简单标量，订阅项目和 `option` 直属层级的复杂或转义键也必须在写入前拒绝，不能新增语义重复的 `option` 或 `allow_auto_update`。

- Ruby：macOS 三档用途、固定用途档位的单次安全读取与变更前一致性门禁、变更型公开 Ruby 入口共用外层锁、全部订阅共享的国内域名规则提供器、缺失、非列表或含 `system`/明文 DNS/旧版危险值的节点启动解析迁移到直连大陆 IP DoH 并保留安全列表值、名称冲突保护、普通安装整批预检与失败零写入、预检快照与事务提交逐份绑定、单次刷新后重新预检、连续刷新保留最新字节、安全更新提交前刷新清理未提交事务并允许后续重试、备份/比较/恢复且恢复写入前持全局操作锁并处理未完成事务、安全更新事务、远程订阅清单严格结构、HTTPS、文件唯一映射、ClashX Meta 原生请求、URL 不进入进程参数、UTF-8、AnyTLS 被 Shadowsocks 全量替换时拒绝覆盖、二次转换与 Mihomo 失败关闭；首次状态目录逐级创建并同步每个新目录及其父目录、失败重试重新同步已出现目录、版本化备份完整写入和权限设置后同步备份目录；订阅自动更新仅追加 `prepared`/`installed`/`released` 所有权事件、中断尾段恢复、语义释放和并发替换保护，首条记录通过私有临时文件、不可覆盖原子发布与父目录同步建立且在成功前不写 `defaults`，带截止时间的文件锁，事务记录绑定逻辑路径、目录内真实路径、原 inode 与原/候选完整字节，事务发布后、首次配置写入前同步父目录，完成时先同步 v3 已提交标记、再删除事务并同步父目录，原句柄截零写入，v2 只自动恢复同一原 inode 上的完整候选，空文件和任一原/候选截断前缀保持目标与事务并报告待恢复，最后核对后的外部原子刷新保持原路径和身份，批量更新期间的路径与文件身份变化，中途写入失败恢复，同一 inode 别名拒绝，指向配置根目录外的符号链接拒绝，空配置目录拒绝，运行刷新，恢复当前订阅时逐项复核缓存刷新、TUN、代理选择、国内与境外 DNS 和连通性，任一步失败都拒绝生效；运行回退已恢复当前文件时不做第二次回退，继续恢复其余订阅并单独报告运行内核仍未恢复；不同 inode 的外部刷新保持不动，只有运行内核仍需恢复时保留事务；加载候选后被强制结束时，下次安全更新在下载前恢复文件并重新加载原运行配置；文件与内核运行状态分别上报、YAML 1.2、Mihomo 校验，以及同时绑定源端口、TCP、新连接 ID、域名边界，并结合静态/provider 实际叶子类型拒绝直连或拒绝类终点的分流验证。
- 双平台 conformance：`tests/fixtures/main_group_cases.json` 由 macOS Ruby 与 Windows JavaScript 共用，覆盖 Mihomo 的全部代理组类型、只有 AI 分组和纯直连组的最终保底；每个案例用人工确认后的 `expected_config_sha256` 锁定完整结果，两端分别匹配后再做完整输出深比较，发生变化的案例再次执行后必须不再变化。档位 3 还锁定 AI 规则、AI 拒绝兜底、局域网 UDP、国内域名、国内 IP UDP、其余 UDP 和最终拒绝的相同顺序；恢复候选中间插入其他规则或更改国内规则提供器任一受管字段必须失败，局域网列表不得包含 Mihomo Fake-IP 网段。策略 v2 缺少或损坏任一必需字段时，两端都必须保持输入不变。三个用途档位逐项比较节点启动 DNS 输出，缺失、非列表、`system`、明文 DNS 和安全列表在两端必须得到相同结果。两端都原样保留 REALITY `short-id` 文本。DNS 静态安全判断不执行订阅提供的 `exclude-filter`；任何非空过滤器都让代理组改用受管 DoH，灾难性回溯样例和忽略此门禁的 mutation 必须失败。
- 覆盖率门槛：macOS 每个 Ruby 生产模块及其合计都必须达到 100% 行覆盖，全部模块的分支合计不得低于 75%；真实 Ruby 命令入口与缺依赖安装包在子进程中执行并断言公开输出，其 Coverage 按源码 SHA-256 合并回对应生产文件；Windows JavaScript 转换引擎必须达到 100% 行、100% 函数且分支不低于 80%。覆盖统计跟随拆分后的全部生产模块，并列出未覆盖行和未覆盖分支所在行。门槛只能上调；不得通过忽略正常生产行、无断言调用或删除防御代码凑数字。
- Shell/CMD 包装器：帮助、参数与退出状态、档位保存/复用、普通失败恢复旧档位、强杀后把新档位保留为下一次 Patch/安全更新的恢复意图、档位 3 降档前强制安全卸载、能力预检、卸载和备份保留等公开行为；macOS 用途档位文件固定在 ClaudeEasy 状态目录，外部环境变量不能让安装覆盖或让卸载删除其他用户文件；macOS 还验证安装失败和安全卸载都按所有权状态恢复自动更新，文件卸载与自动更新恢复属于同一可恢复事务，失败时必须同时保留用途档位、关闭自动更新并保留所有权，并以真实 Shell → 真实 Ruby 主程序 → 受控 Mihomo 可执行文件验证公开安装成功路径，不拿包装器逐行覆盖率冒充安全性。
- macOS 自动更新交接：三个档位都对已有 `prepared`/`installed` 记录原位续写。首次安装在关闭子进程前登记回退责任并暂存信号，后续 Patch 失败时恢复自动更新和旧档位；已有任一保存档位时保留关闭状态。回读或恢复失败返回 `partial`，按同一档位重试。订阅更新读取已保存档位，先处理未完成事务并关闭自动更新，更新结束后再次确认自动更新关闭。
- 品牌命名：产品展示名只允许 `ClaudeEasy`，Skill 与状态 slug 使用 `claude-easy`；全仓库的文件名、目录名、代码、测试和文档都不得出现已停用的项目名称。macOS 与 Windows 只使用当前状态目录、锁、事务、备份和托管配置标记。
- macOS 成功交接信号故障注入：普通 Patch 与安全更新的 fake Ruby 子流程写出提交标记后分别向父 Shell 和独立前台进程组发送 TERM，覆盖文本与 JSON 入口。父 Shell 信号且子流程确认成功时 JSON 返回 `partial/operation_committed_interrupted`；进程组信号同时终止子流程时返回 `partial/operation_interrupted_recovery_intent`，外层操作锁委托进程不得再输出第二份结果。两种情况都返回 143，保存档位保持 3，自动更新关闭状态和所有权保持不变，不能调用恢复自动更新；移除状态保留函数或外层信号委托的 mutation 必须失败。
- macOS 提交收据与结果传输故障注入：普通 Patch 与安全更新的 fake Ruby 子流程写出提交标记后，分别模拟 committed 收据后的 ENOSPC、收据发布失败仍为 pending、收据损坏及子进程被 KILL，覆盖文本与 JSON 入口。已确认提交或收据发布失败时返回 `partial/operation_committed_result_failed`；无法确认时返回 `partial/operation_result_unknown_recovery_intent`。全部路径都保留档位 3、自动更新关闭状态和所有权；有效 pending 加普通失败仍按原规则补偿。真实 Ruby CLI 还要在输出抛出 ENOSPC 前完成收据同步，并用专用内部退出状态报告收据发布失败；移除任一收据发布、Shell 识别、未知状态或错误映射的 mutation 必须失败。
- macOS 包装流程互斥：普通安装、安全更新、安全卸载和变更型 Ruby 入口共用跨进程操作锁，覆盖档位读取、自动更新所有权、订阅事务、卸载最终核对与提交；子流程验证继承描述符、固定锁身份和锁仍被持有，只有环境标志、错误描述符或未加锁的同 inode 描述符都必须拒绝。生产探针把卸载停在最终核对后、路径删除前；并发公开安装必须返回 `operation_in_progress`，卸载完成后重试才能发布新档位。另一个探针在 `READY` 后删除完成、自动更新恢复前强杀整个卸载进程组；下一次公开安装必须先完成安全卸载并验证收据，再写入新档位。分别移除安装端、卸载端的锁获取、继承锁验证或安装端的未完成卸载恢复时，mutation 必须稳定失败。
- macOS 卸载恢复幂等状态：生产探针在安装文件已经删除、自动更新恢复前强杀，重试时 fake Ruby 返回真实主程序的 `already_disabled_owned`。公开安装必须把它视为已拥有关闭状态并继续完成卸载恢复，不能永久卡在 staging；移除该状态分支时测试必须失败。
- macOS 卸载强杀与同步恢复：用途档位替换必须同步文件和父目录，失败时恢复旧档位；每份卸载暂存文件、元数据和 `READY` 都同步后才允许删除，删除后同步安装目录，任一同步失败都恢复全部文件。READY 前的不完整暂存直接丢弃且不得改动安装文件；READY 后恢复文件只能原子发布，恢复再次被强杀后下一次运行必须还原完整字节。对应故障注入和 mutation 删除任一同步边界或退回直接复制时都必须失败。
- macOS 卸载配置事务交接：公开 Patch 在候选写入和运行加载后被强杀，随后公开卸载必须先恢复原文件与原运行配置，再删除安装状态或恢复订阅自动更新。恢复失败时全部受保护状态保持原样；移除卸载前恢复调用的 mutation 必须失败。
- macOS 普通 Patch 运行恢复：故障注入在当前订阅加载候选、事务尚未完成时强杀进程；下一次运行必须恢复原文件和原运行配置，忽略只存在于候选中的临时选择器。强杀恢复或本次自动刷新回退被控制器拒绝时，都必须保留事务，并在新候选校验前停止；`--no-reload` 只能用于普通 Patch，且只能恢复文件和保留事务，不得校验新候选。事务完成先用完整临时文件原子替换并同步 v3 已提交标记，再删除记录；标记首次目录同步失败必须返回专用提交未知状态，让外层保留档位和恢复意图，删除后的父目录同步失败仍保持提交成功；标记重新出现时只能清理，不能回滚候选。`--dry-run`、`--no-reload` 与独立操作组合或多独立操作并存时必须在写入前拒绝。对应 mutation 移除运行恢复、让 `--no-reload` 绕过恢复或提前删除事务时，测试都必须失败。
- macOS 安全更新运行恢复：旧事务恢复必须从存储目录全部顶层配置识别活动项；活动 `config.yaml` 不在远程订阅目标时仍要通过控制器重新加载。重载后的联网重试必须给内核冷启动留出时间；候选、旧事务或失败回滚重载导致 TUN 偏离执行前状态时，必须通过控制器恢复后再检查。所有重载保留 Fake-IP 映射且只清 DNS 缓存；新候选检查国内 DNS 与实际境外 HTTPS，旧事务和失败回滚只要求原文件、TUN、代理选择、DNS 缓存操作与实际联网恢复，不能因旧配置本来存在的单项 DNS 限制永久保留事务。双平台生产代码都不得调用 Fake-IP 清理接口。其他运行检查失败时保留事务，并在下载或新写入前停止。故障注入断言控制器拒绝时记录仍存在；mutation 移除共享恢复入口或强制删除待恢复记录时必须失败。
- macOS 备份恢复事务：必须先读取有效的已保存用途档位，缺失或损坏时零写入；档位 3 备份必须包含当前策略的全部 AI 规则并位于宽泛规则前。旧 Patch 事务必须在备份哈希判断前恢复文件与运行配置，控制器拒绝时保留记录且不调用备份校验。备份替换后、当前订阅运行检查前的强杀由下一次 Patch 恢复；正常运行检查期间事务仍存在，文件已经与备份相同时也要留下可重试记录，运行回退未完成时继续保留。提交状态未知的机器结果必须标为 `restore_backup`。对应 mutation 移除备份事务、跳过相同文件事务、提前提交或在运行恢复失败时删除记录，测试都必须失败。
- macOS 客户端切换故障注入：普通 Patch、安全更新、备份恢复和未完成事务恢复在每次控制器加载前重新核对当前订阅和存储位置；校验、下载、写入或失败回退期间切换时绝不加载旧订阅。首次加载前发现变化会恢复整批文件，包括初始活动配置无需修改、用户切入另一份待更新订阅的批次；候选已加载后发现变化则不再加载旧路径并保留事务。测试分别覆盖订阅切换、本地/iCloud 存储切换、事务恢复和第一次加载后的回退窗口；删除任一共用提交检查的 mutation 必须失败。
- macOS 活动配置识别故障注入：缺少 `selectConfigName` 仍可识别默认 `config.yaml`，无关的合法日期、二进制等 plist 字段不影响目标字符串读取，但偏好读取失败（导出、XML 解析或目标字段类型失败）必须停止；当前目录零匹配或多匹配也不得写入或提交恢复。事务恢复在活动配置缺失时保留候选字节和事务，要求唯一活动配置的 mutation 必须被测试杀死。
- macOS 生产故障探针：独立 CI job 通过单一可执行入口在 Ruby 3.3 与系统 Ruby 下收集四组结果，任一失败都让 job 失败且不会遮住其余组；探针通过真实文件替换、精确同步闸门与 SIGKILL 检查提交后登记失败、普通批量和安全更新强杀恢复、同 inode 别名、校验调用方消失后的子进程与临时文件、卸载 staging 后目标被替换、卸载最终核对后并发安装被操作锁拒绝，以及删除完成后强杀的卸载由下一次安装先完成恢复；普通回归默认跳过这些已确认会失败的探针，契约行为测试和 mutation 同时锁定强制启用、完整执行与失败传播。
- Mihomo 集成：macOS CI 分别校验官方 v1.19.27 和 v1.19.29 的 arm64/amd64 压缩包 SHA-256，再用四个真实内核验证原始配置和档位 1、2、3 的补丁产物；独立 runner 必须确认每次恰好执行一个、断言非零且没有跳过的真实内核案例，并验收绑定内核 SHA-256、随机 nonce、三个档位及原始/补丁六次校验的完成凭据，测试名称漂移、零测试、提前返回或档位循环缩短都不能成功。Windows CI 校验同版本官方 amd64 zip 的 SHA-256，并让两个真实内核在 PowerShell 5.1 与 7 下分别通过公开安装入口、三档基础配置和完整订阅的 `Script.js` 转换产物复验；Windows 各档失败分别记录后统一报错，前一档不能遮住后两档；缺少指定内核时测试直接失败。

## 必须持续防止

- 退出、停止或重启 Clash。
- macOS 自动监听、自动重载、自动切换 TUN 或节点。
- 修改未启用的存储位置、旧 iCloud 容器、备份或废弃订阅。
- 用系统 DNS、明文 DNS、解析器域名或固定境外 DNS 覆盖节点启动解析。
- 自动创建额外安全代理组或替用户选择 AI 节点。
- 在第一、二档执行第三档泄漏检查、TUN/IPv6、WebRTC 或 AI 分组增强；共享国内域名基线不属于第三档增强。
- 把 Windows Computer Use 当成后台或锁屏能力，或在当前会话没有工具时假装完成界面验收。
- 让 Sub Agent 并行写配置、更新/恢复订阅、抢同一界面或同时制造测试流量。
- 并发刷新覆盖、重复代理组、非幂等转换、无限等待和泄露敏感信息。
