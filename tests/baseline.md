# 当前测试基线

本文件记录现行测试范围，不定义产品功能。产品要求见 `docs/superpowers/specs/2026-07-20-claude-easy-skill-design.md` 和 `claude-easy/references/patch-policy.md`。

## 必须通过

- Ruby：macOS 三档用途、固定用途档位的单次安全读取与变更前一致性门禁、变更型公开 Ruby 入口共用外层锁、全部订阅共享的国内域名规则提供器、名称冲突保护、普通安装整批预检与失败零写入、预检快照与事务提交逐份绑定、单次刷新后重新预检、连续刷新保留最新字节、安全更新提交前刷新清理未提交事务并允许后续重试、备份/比较/恢复且恢复写入前持全局操作锁并处理未完成事务、安全更新事务、远程订阅清单严格结构、HTTPS、文件唯一映射、curl 配置注入防护、UTF-8、二次转换与 Mihomo 失败关闭；首次状态目录逐级创建并同步每个新目录及其父目录、失败重试重新同步已出现目录、版本化备份完整写入和权限设置后同步备份目录；订阅自动更新仅追加 `prepared`/`installed`/`released` 所有权事件、中断尾段恢复、语义释放和并发替换保护，首条记录通过私有临时文件、不可覆盖原子发布与父目录同步建立且在成功前不写 `defaults`，带截止时间的文件锁，事务记录绑定逻辑路径、目录内真实路径、原 inode 与原/候选完整字节，事务发布后、首次配置写入前同步父目录，删除事务后再次同步父目录，原句柄截零写入，v2 只自动恢复同一原 inode 上的完整候选，空文件和任一原/候选截断前缀保持目标与事务并报告待恢复，最后核对后的外部原子刷新保持原路径和身份，批量更新期间的路径与文件身份变化，中途写入失败恢复，同一 inode 别名拒绝，指向配置根目录外的符号链接拒绝，空配置目录拒绝，运行刷新，恢复当前订阅时逐项复核缓存刷新、TUN、代理选择、国内与境外 DNS 和连通性，任一步失败都拒绝生效；运行回退已恢复当前文件时不做第二次回退，继续恢复其余订阅并单独报告运行内核仍未恢复；不同 inode 的外部刷新保持不动，只有运行内核仍需恢复时保留事务；加载候选后被强制结束时，下次安全更新在下载前恢复文件并重新加载原运行配置；文件与内核运行状态分别上报、YAML 1.2、Mihomo 校验，以及同时绑定源端口、TCP、新连接 ID、域名边界，并结合静态/provider 实际叶子类型拒绝直连或拒绝类终点的分流验证。
- 双平台 conformance：`tests/fixtures/main_group_cases.json` 由 macOS Ruby 与 Windows JavaScript 共用，覆盖 Mihomo 的全部代理组类型、只有 AI 分组和纯直连组的最终保底；每个案例用人工确认后的 `expected_config_sha256` 锁定完整结果，两端分别匹配后再做完整输出深比较，发生变化的案例再次执行后必须不再变化。两端都原样保留 REALITY `short-id` 文本。
- 覆盖率门槛：macOS 每个 Ruby 生产模块及其合计都必须达到 100% 行覆盖，全部模块的分支合计不得低于 75%；真实 Ruby 命令入口与缺依赖安装包在子进程中执行并断言公开输出，其 Coverage 按源码 SHA-256 合并回对应生产文件；Windows JavaScript 转换引擎必须达到 100% 行、100% 函数且分支不低于 80%。覆盖统计跟随拆分后的全部生产模块，并列出未覆盖行和未覆盖分支所在行。门槛只能上调；不得通过忽略正常生产行、无断言调用或删除防御代码凑数字。
- Shell/CMD 包装器：帮助、参数与退出状态、档位保存/复用、普通失败恢复旧档位、强杀后把新档位保留为下一次 Patch/安全更新的恢复意图、档位 3 降档前强制安全卸载、能力预检、卸载和备份保留等公开行为；macOS 用途档位文件固定在 ClaudeEasy 状态目录，外部环境变量不能让安装覆盖或让卸载删除其他用户文件；macOS 还验证安装失败和安全卸载都按所有权状态恢复自动更新，文件卸载与自动更新恢复属于同一可恢复事务，失败时必须同时保留用途档位、关闭自动更新并保留所有权，并以真实 Shell → 真实 Ruby 主程序 → 受控 Mihomo 可执行文件验证公开安装成功路径，不拿包装器逐行覆盖率冒充安全性。
- macOS 自动更新交接：档位 3 对已有 `prepared`/`installed` 记录原位续写；档位 1/2 升档时在关闭子进程前登记回退责任并暂存信号。关闭或后续 Patch 失败时先恢复自动更新，再恢复旧档位；恢复失败则保留档位 3 并返回 `partial`。档位 1/2 的普通 Patch 与安全更新在订阅写入前清理旧版本遗留所有权，失败时零配置写入。
- 品牌命名：产品展示名只允许 `ClaudeEasy`，Skill 与状态 slug 使用 `claude-easy`；全仓库的文件名、目录名、代码、测试和文档都不得出现已停用的项目名称。macOS 与 Windows 只使用当前状态目录、锁、事务、备份和托管配置标记。
- macOS 成功交接信号故障注入：普通 Patch 与安全更新的 fake Ruby 子流程写出提交标记后分别向父 Shell 和独立前台进程组发送 TERM，覆盖文本与 JSON 入口。父 Shell 信号且子流程确认成功时 JSON 返回 `partial/operation_committed_interrupted`；进程组信号同时终止子流程时返回 `partial/operation_interrupted_recovery_intent`，外层操作锁委托进程不得再输出第二份结果。两种情况都返回 143，保存档位保持 3，自动更新关闭状态和所有权保持不变，不能调用恢复自动更新；移除状态保留函数或外层信号委托的 mutation 必须失败。
- macOS 提交收据与结果传输故障注入：普通 Patch 与安全更新的 fake Ruby 子流程写出提交标记后，分别模拟 committed 收据后的 ENOSPC、收据发布失败仍为 pending、收据损坏及子进程被 KILL，覆盖文本与 JSON 入口。已确认提交或收据发布失败时返回 `partial/operation_committed_result_failed`；无法确认时返回 `partial/operation_result_unknown_recovery_intent`。全部路径都保留档位 3、自动更新关闭状态和所有权；有效 pending 加普通失败仍按原规则补偿。真实 Ruby CLI 还要在输出抛出 ENOSPC 前完成收据同步，并用专用内部退出状态报告收据发布失败；移除任一收据发布、Shell 识别、未知状态或错误映射的 mutation 必须失败。
- macOS 包装流程互斥：普通安装、安全更新、安全卸载和变更型 Ruby 入口共用跨进程操作锁，覆盖档位读取、自动更新所有权、订阅事务、卸载最终核对与提交；子流程验证继承描述符、固定锁身份和锁仍被持有，只有环境标志、错误描述符或未加锁的同 inode 描述符都必须拒绝。生产探针把卸载停在最终核对后、路径删除前；并发公开安装必须返回 `operation_in_progress`，卸载完成后重试才能发布新档位。另一个探针在 `READY` 后删除完成、自动更新恢复前强杀整个卸载进程组；下一次公开安装必须先完成安全卸载并验证收据，再写入新档位。分别移除安装端、卸载端的锁获取、继承锁验证或安装端的未完成卸载恢复时，mutation 必须稳定失败。
- macOS 卸载恢复幂等状态：生产探针在安装文件已经删除、自动更新恢复前强杀，重试时 fake Ruby 返回真实主程序的 `already_disabled_owned`。公开安装必须把它视为已拥有关闭状态并继续完成卸载恢复，不能永久卡在 staging；移除该状态分支时测试必须失败。
- macOS 卸载强杀与同步恢复：用途档位替换必须同步文件和父目录，失败时恢复旧档位；每份卸载暂存文件、元数据和 `READY` 都同步后才允许删除，删除后同步安装目录，任一同步失败都恢复全部文件。READY 前的不完整暂存直接丢弃且不得改动安装文件；READY 后恢复文件只能原子发布，恢复再次被强杀后下一次运行必须还原完整字节。对应故障注入和 mutation 删除任一同步边界或退回直接复制时都必须失败。
- macOS 卸载配置事务交接：公开 Patch 在候选写入和运行加载后被强杀，随后公开卸载必须先恢复原文件与原运行配置，再删除安装状态或恢复订阅自动更新。恢复失败时全部受保护状态保持原样；移除卸载前恢复调用的 mutation 必须失败。
- macOS 普通 Patch 运行恢复：故障注入在当前订阅加载候选、事务尚未完成时强杀进程；下一次运行必须恢复原文件和原运行配置，忽略只存在于候选中的临时选择器。强杀恢复或本次自动刷新回退被控制器拒绝时，都必须保留事务，并在新候选校验前停止；`--no-reload` 只能恢复文件和保留事务，不得校验新候选。对应 mutation 移除运行恢复、让 `--no-reload` 绕过恢复或提前删除事务时，测试都必须失败。
- macOS 安全更新运行恢复：旧事务恢复必须从存储目录全部顶层配置识别活动项；活动 `config.yaml` 不在远程订阅目标时仍要通过控制器重新加载。旧事务或本次安全更新回滚的运行检查失败时保留事务，并在下载或新写入前停止。故障注入断言控制器拒绝时记录仍存在；mutation 移除共享恢复入口或强制删除待恢复记录时必须失败。
- macOS 备份恢复事务：旧 Patch 事务必须在备份哈希判断前恢复文件与运行配置，控制器拒绝时保留记录且不调用备份校验。备份替换后、当前订阅运行检查前的强杀由下一次 Patch 恢复；正常运行检查期间事务仍存在，文件已经与备份相同时也要留下可重试记录，运行回退未完成时继续保留。对应 mutation 移除备份事务、跳过相同文件事务、提前提交或在运行恢复失败时删除记录，测试都必须失败。
- macOS 客户端切换故障注入：普通 Patch、安全更新、备份恢复和未完成事务恢复在每次控制器加载前重新核对当前订阅和存储位置；校验、下载、写入或失败回退期间切换时绝不加载旧订阅。首次加载前发现变化会恢复整批文件，包括初始活动配置无需修改、用户切入另一份待更新订阅的批次；候选已加载后发现变化则不再加载旧路径并保留事务。测试分别覆盖订阅切换、本地/iCloud 存储切换、事务恢复和第一次加载后的回退窗口；删除任一共用提交检查的 mutation 必须失败。
- macOS 活动配置识别故障注入：缺少 `selectConfigName` 仍可识别默认 `config.yaml`，无关的合法日期、二进制等 plist 字段不影响目标字符串读取，但偏好读取失败（导出、XML 解析或目标字段类型失败）必须停止；当前目录零匹配或多匹配也不得写入或提交恢复。事务恢复在活动配置缺失时保留候选字节和事务，要求唯一活动配置的 mutation 必须被测试杀死。
- macOS 生产故障探针：独立 CI job 通过单一可执行入口在 Ruby 3.3 与系统 Ruby 下收集四组结果，任一失败都让 job 失败且不会遮住其余组；探针通过真实文件替换、精确同步闸门与 SIGKILL 检查提交后登记失败、普通批量和安全更新强杀恢复、同 inode 别名、校验调用方消失后的子进程与临时文件、卸载 staging 后目标被替换、卸载最终核对后并发安装被操作锁拒绝，以及删除完成后强杀的卸载由下一次安装先完成恢复；普通回归默认跳过这些已确认会失败的探针，契约行为测试和 mutation 同时锁定强制启用、完整执行与失败传播。
- Mihomo 集成：macOS CI 分别校验官方 v1.19.27 和 v1.19.29 的 arm64/amd64 压缩包 SHA-256，再用四个真实内核验证原始配置和档位 1、2、3 的补丁产物；独立 runner 必须确认每次恰好执行一个、断言非零且没有跳过的真实内核案例，并验收绑定内核 SHA-256、随机 nonce、三个档位及原始/补丁六次校验的完成凭据，测试名称漂移、零测试、提前返回或档位循环缩短都不能成功。Windows CI 校验同版本官方 amd64 zip 的 SHA-256，并让两个真实内核在 PowerShell 5.1 与 7 下分别通过公开安装入口、三档基础配置和完整订阅的 `Script.js` 转换产物复验；Windows 各档失败分别记录后统一报错，前一档不能遮住后两档；缺少指定内核时测试直接失败。
- 发布包：macOS 按公开分发清单生成 tar 包，在带空格和中文的独立目录解压，再运行 Shell/Ruby 入口、Windows JavaScript 语法检查、Ruby 档位 1 演练，以及公开 Shell → 系统 Ruby → 受控 Mihomo 的真实档位 1 安装；Windows 从 zip 解压目录完成真实档位 1 安装，并注入缺模块包验证零改动失败。依赖路径 mutation 必须让 macOS 发布包测试失败。
- Node.js：Windows 全局扩展脚本与 macOS 策略一致；档位 1、2 只应用共享国内域名基线，档位 3 再应用完整增强。
- Windows `Script.js` 组合：私有 setup 在旧代码前捕获受管引擎、真实全局、内置对象及原型描述符；改名后的旧脚本仍在 Clash 的真实 `try`/Script 顶层执行，顶层 `var`、函数、`globalThis`、`this` 与开头 `"use strict"` 字符串保持客户端语义。旧顶层结束后先恢复内置对象，再把全局 `main` 封闭为不可配置的受管访问器；每次旧 `main` 执行后都在 `finally` 恢复内置对象，正常返回后才运行受管变换。模板字符串文本保持原样且表达式按代码检查；唯一入口声明之外的属性访问、别名、对象简写等裸 `main` 引用全部在写入前拒绝。安全更新要求整个受管区块外只有空白或注释，并逐字核对受管引擎与组合结构；重装会在组合检查通过后把区块外旧代码迁入专用原脚本边界并保留；`eval`、`Function`、点号函数构造器和值为 `constructor` 的计算属性字符串在任何事务写入前整批拒绝。
- PowerShell 5.1 与 7：两个独立 CI job 运行完整套件，避免一个版本失败后跳过另一个版本；父进程和实际子进程都必须自证 PSEdition 与主版本，完整套件只有执行到全部断言和清理之后才生成绑定运行时的完成凭据，CI 必须独立验收凭据；覆盖 Windows 三档用途、安装/卸载、失败时保持原档位、安全卸载后的真实降档、默认 AppHome 多候选时拒绝歧义、远程订阅自动更新的原值与原 `option` 形态所有权、重复安装不改写原状态、受管脚本区块外可执行代码拒绝（包括无分号字符串指令和模板字面量）、重装迁移区块外旧代码、已有脚本的唯一入口声明之外不得出现属性访问、别名、对象简写或其他裸 `main` 引用、严格状态结构与单次 snapshot、运行客户端且存在应用状态时整批零改动、写删重叠和重复目标预检、新建文件的空原内容必须可写入事务日志、全目标与父目录句柄先取得、文件身份与原字节双重核对、阻断读取/写入/改名/替换、句柄绑定删除、删除标记失败恢复、目录/重解析点/硬链接拒绝、父目录联接点竞态拒绝、坏备份先拒绝、内部状态恢复禁令、备份完整同步并设置私有权限后才原子发布正式名称且发布前强杀不可见、AppHome 的大小写、扩展路径和 SUBST 别名与改名不可绕过互斥，系统提供 8.3 短路径时还要验证备份身份一致；相对目录备份身份在路径别名和目录改名后保持一致、公共安装被强杀后由公共卸载恢复、公共卸载恢复再次被强杀后仍可继续、公共卸载被强杀后由公共安装恢复、公共备份恢复写到一半被强杀时不得留下截断文件、进程强杀后的批量写入与删除事务恢复、删除恢复缺失目标使用私有临时文件完整同步后原子发布、不同身份的完整原字节只确认而空内容/原文前缀/其他内容保留目标与事务、中断新建文件只删除本工具完整候选或候选前缀、恢复中的同身份原始字节前缀可以续写但其他内容与身份替换必须拒绝、损坏事务日志严格拒绝、失败恢复不覆盖并发内容、Mihomo 超时终止全部后代进程、候选配置公开前先启动调用方死亡清理监视且调用进程消失后不遗留候选配置，候选配置、事务日志和删除恢复临时文件都只允许当前用户和系统管理员读取、嵌套 `option` 层级、远程订阅清单严格结构与严格 UTF-8、安全更新校验字节绑定、受管全局脚本与当前安装包及保存档位一致、空代理组整批恢复、合法块状与行内自动代理组及只有 AI 分组的配置都可继续由 Mihomo 校验，以及从当前运行规则的最后一个 `MATCH` 绑定任意名称、任一受支持类型的主代理组，同时绑定源端口、TCP、目标域名和新连接 ID、域名边界、非代理终点拒绝和每次观察后清理挂起 curl 进程的分流验证；测试失败诊断只记录输出长度与 SHA-256，不回显子进程原文；全库通过 PowerShell AST 禁止在赋值、参数、循环、自增减或变量命令中写入只读自动变量。
