# ClaudeEasy 配置与诊断

## 必须遵守

1. **绝对不要退出、停止或重启 Clash 客户端。** 不得执行、建议或要求用户这样做。
2. 先只读检查，再修改。只按已保存用途档位切换 TUN 或 Clash 自己的系统代理；不得覆盖第三方代理，也不得切换订阅、代理组或节点。
3. 只处理 Clash 当前存储位置中的订阅。无法确认本地/iCloud 状态时停止，不猜。
4. 要求 Mihomo 1.19.27 或更高版本。找不到内核、版本过旧或 30 秒内没有响应时不修改。
5. 候选必须通过 YAML 重读、二次转换一致性检查和 Mihomo 校验；失败时保留原文件。
6. 所有用户消息使用简体中文，不显示订阅地址、密码、UUID、私钥、控制器密钥或完整节点地址。

开始前完整阅读 [references/patch-policy.md](references/patch-policy.md)。详细产品规则和全部状态以该文件为准。

## 模块选择

- **Patch 模块**：用户首次安装、改变用途档位或明确要求网络配置时使用；只应用满足该档位的最少改动。
- **Diagnostics 模块**：用户说网络不对劲、变慢、打不开、不稳定、分流异常或出现其他网络现象时使用。不能因为用户提到 Clash 就先运行补丁。

### AI 服务状态前置检查

用户报告 OpenAI、Anthropic 或其他 AI 服务无法连接、反复重连、流式响应中断、超时、明显变慢或服务错误时，在读取用途档位、检查本机配置、节点、DNS 或日志之前，第一步先确定服务提供商，并查询对应提供商的官方状态页和事件历史。OpenAI 查 [https://status.openai.com/](https://status.openai.com/)，Anthropic 查 [https://status.anthropic.com/](https://status.anthropic.com/)；其他服务只查它自己的官方状态渠道。

记录查询时间、故障时间窗、事件状态、受影响组件，以及事件与用户症状是否吻合。时间和组件都吻合只能标为“有力支持”，不能自动断定每次失败都来自服务端；官方没有记录也不能排除区域性、账号、模型或尚未公布的服务异常。查完再按 Diagnostics 做必要的本机核对；已有官方事件足以解释症状时，不因此修改本机配置。

用途档位同时约束 Patch 和 Diagnostics。Diagnostics 每次开始都先读取本机保存的档位；没有时先完成用途选择。档位决定诊断目标、允许检查和修改的范围，以及修复后的回归验收。故障本身不能自动升档；只有用户明确增加用途时才改档并重新确定范围。

## 用途档位

先读取本机保存的档位：macOS 运行 `bash scripts/install_macos.sh --show-profile`；Windows 运行 `.\scripts\install_windows.cmd -ShowUsageProfile`。没有已保存档位时，修改前必须问：**“你使用网络代理主要用于哪些用途？”**

1. **档位 1｜普通浏览**：Twitter、Facebook、YouTube 等。给当前存储位置中的全部订阅安装共同国内域名直连基线，关闭订阅自动更新，并确认 Clash 客户端的“设置为系统代理”已开启；不修改 TUN、IPv6、WebRTC、AI 分组或节点。用 Computer Use 测试国内站、Google、Twitter 和一个用户常用站点。
2. **档位 2｜海外 AI**：继承档位 1 的共同国内域名直连基线并保持订阅自动更新关闭；ChatGPT、Codex、Gemini、Perplexity 等，但不用 Claude。开启 TUN，并关闭 Clash 客户端自己的系统代理开关，避免同一流量被 Clash 重复接管；这不是为了隐藏代理。除下述 AdGuard for Mac 已知兼容路径外，不得关闭或覆盖第三方代理或 PAC；不增加 WebRTC 或 AI 分组补丁。测试国内站、Google、Twitter、ChatGPT 和 Gemini。
3. **档位 3｜Claude/Claude Code**：先完成档位 2，再应用完整增强：①配置 TUN、DNS 劫持与严格路由；②关闭 IPv6；③国内 DNS 直连大陆加密解析器；④普通国外与 AI DNS 按出站分开；⑤补全或创建 AI 分组；⑥补全 AI 规则；⑦所有 UDP 经 AI 分组并以拒绝兜底，防止 WebRTC 直连；⑧完成分流、DNS、两项 WebRTC 和下述 Claude 区域指纹验证。说明全局 UDP 会影响 QUIC、游戏、语音和视频；建议 AI 分组选择台湾家宽，其次日本家宽，但不得自动切换节点。

### 档位 3 的 Claude 区域指纹检查

档位 3 还要用随 Skill 安装的 `assets/claude-region-check.html` 做本地区域指纹检测。页面用 CSP 禁止 HTTP(S) 外联，不上传检测结果；WebRTC 项会访问 `stun:stun.l.google.com:19302`，第三方会看到浏览器发出的公网 IP。页面支持 Safari、Microsoft Edge 和 Google Chrome；给出的是区域信号参考分，不是 Claude 官方判定，也不能作为 Claude 是否可用的通过条件。网络补丁不会自动降低这项分数，原有分流、DNS 深度测试和两项 WebRTC 验收仍须分别通过。选择档位 3 已包含打开本地检测页和这一次 STUN 探测的授权，不另行中断初检。

1. **修改前基线：** 在任何设置或网络修改之前，从当前 Skill 根目录解析 `assets/claude-region-check.html` 的绝对路径，优先识别用户实际打开 Claude 的浏览器，并用 Computer Use 在同一浏览器中打开这个本地文件；无法确认时才使用系统默认浏览器并明确记录限制。正式支持 macOS 的 Safari 或 Chrome、Windows 的 Edge 或 Chrome；其他浏览器能正常完成初检就记录实际检测结果，不能运行时保持“未验证”，把兼容性限制纳入第一次授权。不得借用 Safari、Edge 或其他浏览器的信号，也不得合成一个现实中不存在的指纹；不得使用 Codex 内置浏览器或 `curl` 代替。路径含空格时必须作为完整本地文件地址打开，不能把 macOS 路径照搬到 Windows。点击“开始检测”，每 2–5 秒读取一次界面状态，最多等待 60 秒；超时后只刷新一次并重试，再次超时就写成“未验证：检测页超时”。本地文件缺失、不可读、JavaScript 被禁用或页面报错时写成“未验证：本地检测页不可用”。完成后向下滚动查看固定十项信号，记录时间、浏览器、参考分、风险等级、所有非零信号、“有限信息”和“无法读取”项；权重依次为系统时区 24、浏览器语言 18、浏览器可见中文字体 14、国产厂商字体 10、WebRTC IP 泄露 10、国产浏览器/WebView 8、国产品牌设备 6、Intl 区域设置 4、UTC+8 偏移 3、Emoji 平台推断 3。0–30 分为绿色“低风险”，31–60 分为橙色“中风险”，61–100 分为红色“高风险”。WebRTC 发现任何数字 IP 候选时沿用上游 0.5 分值、贡献 +5，但必须注明候选 IP 不等于真实 IP 泄露，不能替代两项专用 WebRTC 验收。“命中”只按信号分达到上游 `0.25` 门槛统计，低于门槛的非零贡献仍照实记录。Safari 没有 Chromium 的 `userAgentData`、Windows 桌面浏览器没有提供设备型号时，设备项显示“有限信息”不等于失败。无法读取项的贡献是“未知”，不能当成 `+0`；只要存在无法读取项，就记录页面给出的已知项合计和未知权重，不记录或比较一个不存在的总分。当前会话没有 Computer Use 时给出系统浏览器手动步骤，并把结果写成“未验证”。
2. **征得用户同意：** 浏览器语言只有一个检测结果；`zh-CN`、`zh-Hans` 或 `zh-Hans-CN` 这类中国大陆简体中文计分，英文、繁体中文、新加坡中文和其他语言不计分。系统时区、浏览器语言与 Intl 区域设置、当前用于 Claude 的国产浏览器/WebView 都是可选调整项。先保存四项修改前快照，只把本次命中的项目、旧值→建议值和实际影响向用户一次申请，不拆成多轮确认；明确说明“这些调整只降低参考分，不保证改变 Claude 判定；是否应用？”用户只回复“同意”、没有语言偏好时，默认使用繁体中文：系统时区改为 `Asia/Taipei`，浏览器语言改为 `zh-TW`，Intl 使用台湾区域设置。用户明确要求英文时，浏览器语言改为 `en-US`，Intl 使用美国区域设置，时区仍用 `Asia/Taipei`。设置浏览器语言时把目标语言排在第一位。台北与北京、上海同为 UTC+8，不会改变当前时间，但会改变时区标识；还要说明浏览器界面、网页语言可能变化，区域设置会影响系统和其他应用的日期/数字格式。检测到国产浏览器时，只说明当前用于 Claude 和检测的浏览器/WebView 会加分，安装着但未用于检测不会加分；可以建议改用 Safari、Chrome 或 Edge 打开 Claude，但不得仅为降低参考分修改系统默认浏览器。只有用户明确要求更改系统默认浏览器时才执行，不卸载原浏览器。用户拒绝的项目不修改，并保留在最终结果中。
3. **保留与端点检查：** 不得删除中文字体；浏览器可见中文字体和国产厂商字体都保留。国产品牌设备不改，也不得伪装设备或 User-Agent。`Asia/Taipei` 仍是 UTC+8，时区偏移不会因此改变；Emoji 平台推断只按 User-Agent/平台信息提示，不声称真的检测了渲染。只读分类 `ANTHROPIC_BASE_URL` 时先判断是否设置，再按 URL 解析结果依次判断：未设置为“默认端点”；解析失败、非 HTTPS 或包含 userinfo 为“端点配置异常”；只有 hostname 规范化后精确等于 `api.anthropic.com`、使用默认 443 端口且不得包含 userinfo 时才是“官方端点”；其余合法 HTTPS 地址为“自定义端点”。只报告类别，不得输出完整 hostname，也不得擅自更换用户的服务端点。
4. **执行与复测：** 逐项修改并回读用户已授权的设置。本批设置任一步或最终验收失败时，只在当前值仍等于本轮写入值时按修改前快照恢复；用户在期间继续修改过的值不得覆盖。随后运行平台安装程序，完成 TUN、DNS、WebRTC、分流和站点验收。最后回到修改前实际用于 Claude 的同一浏览器：原检测页仍在时直接点击“重新扫描”，不要先刷新；页面被关闭或必须重开时，重新打开本地页并点击当前可见的“开始检测”或“重新扫描”。按修改前基线的 60 秒规则等待；检测中不能重复点击。只有两次扫描都没有“无法读取”，或无法读取项集合完全相同，才比较数值；覆盖范围不同时分别报告已知项合计和未知权重。参考分不能用于宣布档位 3 成功或失败。

复测后按非零信号重新分类，只继续执行用户已同意且可恢复的修改；不得通过删字体、伪装设备、改 User-Agent 或改变实际时钟来追分。区域指纹页是环境提示，不替代 DNS、WebRTC、分流和 Claude 联网验证，也不参与这些网络验收的通过条件。

向小白用户展示以上三项及改动差异。用户可以随时改档；升档时只补新增能力。从档位 3 降到档位 1 或 2 时，先运行安全卸载：macOS 用 `bash scripts/uninstall_macos.sh`，Windows 用 `.\scripts\uninstall_windows.cmd`；再保存并执行新选择。卸载只能撤销能确认属于本工具且未被继续修改的设置，不能覆盖后来产生的用户改动；无法安全恢复的旧增强继续保留并说明。Windows 卸载返回 `partial` 时，本次没有修改整批保护文件，必须保留旧档位且不得继续降档，也不得要求用户退出、停止或重启客户端。保存并执行选择：macOS 用 `bash scripts/install_macos.sh --profile N`，Windows 用 `.\scripts\install_windows.cmd -UsageProfile N`。用户明确表达 `Claude` 或 `Claude Code` 的网络配置需求时，直接选择或升级为档位 3；明确表达其他海外 AI 时选择或升级为档位 2；仅提到某网站故障仍进入 Diagnostics，不借机改档。

Diagnostics 按保存档位工作：三个档位都维护共同国内域名直连基线。档位 1 只保障国内直连与普通境外网站、系统代理，不检查或修改 TUN，不做 DNS 泄漏、WebRTC、AI 分组或 Claude 检查。档位 2 增加 TUN、普通海外 AI 与 Agent 联网，但仍不做泄漏、WebRTC 或 AI 分组检查。档位 3 才维护其余完整增强；任何可能影响共同网络路径的修复都要复测相关第三档保护，不能为解决一个网站而破坏 DNS、分流或 WebRTC 防护。

**解决原始问题是 Diagnostics 的结束目标。** Diagnostics 默认只读，只表示第一阶段先取证；只读检查是第一阶段，不是交付结果。诊断结论不是完成，解释、建议或状态说明不能代替行动。只要仍有本机可安全执行、属于用户要求和当前档位的下一步，就继续修复、复测、继续迭代。不得以“已经找到原因”“给出方案”“需要观察”代替本机能够完成的修复。

代理不请求用户确认诊断方案，也不把计划、可能性列表或“请自行操作”当成交付。只有工具明确要求的操作时确认、缺少密码/MFA/实体操作、修改会超出当前档位或授权、存在不可恢复的数据风险，或外部条件确实阻止继续时，才提出一个精确的阻塞问题；先完成全部不需要确认的准备，说明将要执行的单一动作与恢复方法，用户授权后直接继续。不得把“请回复继续”当成常规收尾。

有 Computer Use 且症状能在界面看到时，必须在修改前复现原始症状；命令行结果不能代替用户实际使用的应用。再判断影响范围，按现场选择浏览器、应用、系统、DNS、连接、分流、传输质量和日志证据；不是每次全部检查。预计超过 10 分钟且存在彼此独立的只读证据来源时，可以使用多个 Sub Agent 并行取证；主代理仍串行完成所有写入和判断。配置缺陷不等于故障原因，只有同一原始症状的单变量对照和独立证据同时成立，才能修改并下结论。

### 因果判定门槛

把伴随事件、设置、进程、设备、节点或服务写成反复故障的“主要原因”前，必须验证原始事件、时间方向、候选事件命中率、故障覆盖率、正反例和单变量干预。候选事件命中率统计“候选事件后发生故障 ÷ 全部候选事件”；故障覆盖率统计“故障前存在候选事件 ÷ 全部故障”。必须同时统计“有候选事件但没有故障”和“没有候选事件却发生故障”，不能只展示吻合样本。日志解析先抽查原文，排除引用、摘要或诊断文本；同一个下游现象被多个日志重复记录，只能确认现象发生，不能自动算成指向上游原因的独立证据。机制解释只能说明为什么可能发生，不能补足实测证据。

以上全部门槛通过后才能写“主要原因”或“已确认”。单变量干预无法安全执行时，必须有直接记录上游失败的独立证据替代；否则保持“有力支持”或“尚未证实”，继续取证，不能为了给唯一答案而升级结论。

**结论措辞固定：** 全部门槛通过时写“已确认的主要原因：X”；未通过时写“下一项验证：X（有力支持/尚未证实）；尚缺门槛：……”；反证充分时写“已排除 X 作为反复故障的主要原因”。未确认的候选不能改写成“最可能的主因”“首要原因”，也不能用“不是 X 而是 Y”把另一个未确认候选包装成结论。

浏览器白屏、一直转圈或过很久突然显示时，必须把 DNS、主文档与关键资源的网络耗时、首次显示时间和加载结束时间分开记录。怀疑扩展、过滤器或共同网络组件时，除单站目标的开关对照外，还要测试至少两个健康对照：只有目标异常就修目标交互；健康对照也异常就修共同组件本身，不能继续逐站加例外。多个无关目标在内容开始传输前出现相同等待时，只盘点当前档位允许的接管层；档位 1 不检查 VPN/TUN。用时间线、日志与单变量切换证明重叠接管后再做职责分层，每层只保留一个透明接管者。无改善立即恢复原设置。不能因为单个目标的对照结果就停用或删除整个组件。

macOS 的档位 2、3 检测到 AdGuard for Mac 时直接检查其过滤模式；若它以 `Network Extension` 与 Clash TUN 重叠接管，就通过 Computer Use 在 AdGuard 自己的界面切到“自动代理”，保留 Clash TUN，并按详细策略复测。这是已知兼容路径，不是升档；Clash TUN 存在时不得把 AdGuard 改为 `Network Extension`。不得用 `networksetup` 或直接编辑设置，不得逐站添加例外，也不得停用、退出或卸载 AdGuard。禁止按应用调整 AdGuard 过滤范围。档位 1 和 Windows 不照搬该组合。仅检测到 AdGuard 不能证明当前故障由它造成；Diagnostics 仍用修改前后的原场景对照确认，无改善立即恢复。

### 已知故障快查

- **第一档已知故障：国内请求误走海外。** 国内网站或应用时好时坏，且目标属于国内数据集、实时连接却命中 `MATCH`/海外代理，而大陆 DoH 与直连稳定时，档位 1、2、3 都处理。把同一份受管 `cn.mrs` 写入全部订阅，让 DNS 与 `RULE-SET,...,DIRECT` 共用数据源；每天更新，安全更新后重应用，名称或缓存路径冲突时编号，不覆盖用户配置。用户显式域名规则和档位 3 AI 规则优先，受管规则位于宽泛规则前；不得给 Kimi、欧陆词典等单站加例外。诊断核对每份订阅的提供器、DNS/路由引用和实时 `DIRECT`；缺项就用已保存档位的 JSON 安装入口一次修复全部订阅，齐全但走错再查提供器、缓存和活动配置。当前无法复现时写“暂未复现”。
- **AdGuard 自动代理、证书故障与 Fake-IP 重用。** 日志出现 CFNetwork `uses proxy`、本机 AdGuard 端口、`-9802`/`CERTIFICATE_VERIFY_FAILED` 或浏览器关键资源证书错误时，不归入国内误分流。先检查系统代理所有权、PAC 查询中断和 Clash `ProxyConfigHelper` 活动；档位 2、3 只允许“Clash TUN 开、Clash 系统代理关、AdGuard 自动代理开”。Mihomo 使用 Fake-IP 时，把 AdGuard 故障日志中的目标域名和假地址，与 Mihomo 持久 Fake-IP 数据库只读快照的当前反向映射交叉核对；同一个地址现在映射到其他域名，才确认 **Fake-IP 被重新分配**。再三重确认当前 **Mihomo HTTP 代理端口**确由 Mihomo 监听，只通过 AdGuard 界面把 **AdGuard 出站代理**设为 HTTP、`127.0.0.1` 和该端口，让请求按域名交给 Mihomo；不得固定端口，不覆盖已有的非 Clash 出站代理。修改前记录全部原字段，原目标三次、至少三个无关目标、广告过滤、证书处理或当前档位能力任一失败，就恢复 AdGuard 原状态。不得点击“继续”，不添加 Apple/iCloud 或单站规则，不归咎于订阅节点，不全局关闭 HTTPS 过滤，也不改 Plist、PAC 或系统代理。禁止按应用调整 AdGuard 过滤范围；Clash TUN 存在时不得把 AdGuard 改为 `Network Extension`。

代理必须主动完成本机可完成且当前档位允许的检查。历史证据不足时建立有时间戳的观察窗口，不让小白用户决定该查哪个日志。一次失败不是停止条件：修复失败后恢复原状态、继续取证，再按新证据选择下一项单变量修复。两次假设或修改未改善原始症状后，必须做诊断重置：恢复全部未生效的试验，重列已确认、已排除和未知项；诊断重置后继续读取新证据，没有新的证据不得进行第三次修改。确认问题后执行最小、可恢复的修复，并用同一应用、目标和动作连续复测；涉及网络接管模式时还要验证当前档位要求的过滤、分流或安全能力。AI 服务连接故障按前置步骤先查官方状态；其他本机不能解决的问题再查当前官方方案。只有原始症状和相关回归项通过，或出现上述真实阻塞，才向用户收尾。最终用简体中文先报告结果，再简要说明证据、已做修复、复测结果和仍未确认之处。单项 Clash 配置修复仍留在 Diagnostics，只复用 Patch 的备份、候选校验、刷新和失败恢复机制；只有档位 3 执行其余完整策略与 Patch 专用验收，普通浏览器或应用问题不得顺手改 Clash。

## 事故防线

- 保留 `default-nameserver` 和 `proxy-server-nameserver` 的安全用户值；字段缺失或属于旧版危险固定值时按策略迁移。不得把节点启动解析改成 `1.1.1.1` 或 `8.8.8.8`。把 `direct-nameserver` 统一设为策略中的大陆 IP DoH，并关闭 `direct-nameserver-follow-policy`，让已判定为 `DIRECT` 的国内域名获得大陆 CDN。不得使用明文 DNS、`system` 或 ECS 作为直连域名解析器。
- 不得安装永久监听、LaunchAgent、`WatchPaths`、计划任务或目录监听。
- 每次写入配置前创建包含日期时间的版本化备份，保留修改前的版本；第一次运行另存初始快照。故障排查先做配置差异比较，需要回滚时先备份当前版本并校验预期 SHA-256。
- Windows 同一应用目录的公开操作由目录内独占锁文件串行执行，并在修改期间持有配置目录和目标父目录句柄；路径别名、目录改名或联接点替换不得产生第二个并发操作。批量文件事务开始前写入持久恢复记录；进程被强制结束后，下次操作必须先恢复原状态。备份目标身份使用相对应用目录的规范路径，不能因目录改名、大小写或扩展路径别名失效。
- Windows 所有写操作只使用当前应用目录中的 ClaudeEasy 锁；未完成事务必须先恢复，之后才能继续修改普通状态和备份。
- Windows 通过已锁定原文件句柄写入替换内容或失败恢复内容时，必须先截为零长度再写入并同步；强制中断只能留下空文件或目标内容前缀，不能留下新内容与旧尾部拼接的不可恢复状态。删除事务恢复缺失目标时，先在同目录私有临时文件中完整写入原字节并 `Flush(true)`，再次确认目标仍缺失后原子发布。不同文件身份只有完整原字节可以直接确认且不得改写；空内容、原文前缀或其他内容必须保留目标与事务并停止。
- Windows 新建目标必须在最终路径出现前发布私有准备记录；主事务记录发布前中断时，下次公开操作只删除记录中仍为空且核对期间未变化的新目标，遇到非空内容、链接或身份变化时拒绝继续。主事务发布并删除准备记录后才能写入新目标。安全更新验收失败时，整批订阅恢复与删除本次验收清单必须放进同一个可恢复事务；进程中断后不能把已经恢复的旧订阅误报为本次更新成功。
- Windows 三个档位安装、备份恢复和卸载中会改写当前配置的事务，都必须把客户端未运行作为文件事务的提交条件；全部目标句柄和原字节核对完成后、发布事务记录前再次检查。客户端在候选或备份生成期间启动时，不得修改任何受保护文件或恢复状态；卸载返回 `partial`，安装与恢复返回可重试失败。
- Windows 每次公开命令先检查中断的客户端敏感事务。事务记录和新建文件准备记录必须持久保存恢复权限；普通安装、卸载、备份恢复及旧版记录一律默认要求客户端停止，不能只凭目标路径猜测用途。恢复时必须先独占锁定并核对全部恢复目标，再次检查客户端，确认仍未运行后才批量恢复；客户端已运行或在恢复提交前启动时返回 `partial/transaction_recovery_pending`，保持中断字节和记录不变。以后运行公开命令时继续恢复，不能为了完成恢复而退出、停止或重启客户端。只有用户明确触发的安全更新可标记运行中恢复权限，且目标必须严格限定为 `profiles` 目录中的 `.yaml`/`.yml` 远程订阅和本次验收清单。
- Windows 安全卸载发现尚未验收的安全更新清单时，必须先返回 `safe_update_pending`，整批不改并保留清单、订阅、备份、全局脚本、用途档位及所有权状态。先完成 `-VerifySafeUpdate` 的验收或恢复，才能重试卸载。
- 两端都必须原样保留已有的 REALITY `short-id` 文本，不补齐、不截断、不猜测。macOS 读写 YAML 时显式保护容易被误判为数字的有效十六进制文本；Windows 的对象转换不得改变该字段。
- 任何候选都必须验证并再次转换；普通安装与安全更新必须先校验整批候选再写，任一份失败时不得留下部分改动。macOS 通过基础环境检查并建立初始快照后先保存用户明确选择的新档位，再修改自动更新和订阅；首次安装普通失败恢复旧档位和自动更新，已有任一档位时保留自动更新关闭状态。进程被强制结束则保留新档位作为恢复意图，下一次 Patch 或安全更新必须按它继续，不能读取旧档位降级处理。macOS 批量写入前保存持久事务记录，进程被强制结束时，下次 Patch 或安全更新先恢复未完成事务。Windows 自动查找 AppHome 时如果 Roaming 与 Local 候选同时存在，必须拒绝并要求明确指定当前目录，不能猜测选择。当前订阅只允许通过本地控制器自动刷新；刷新或运行检查失败时立即恢复原文件和原运行配置。三个档位都只在确实由本工具关闭自动更新时保存所有权状态；安全卸载把安装文件删除、自动更新恢复和所有权清理作为同一个可恢复事务，失败或中断时必须同时保留用途档位、关闭状态和所有权并报告。绝不退出 Clash。
- macOS 自动更新所有权使用仅追加的 `prepared`、`installed`、`released` 事件；`released` 表示已经没有所有权，状态文件仍可保留，Shell 必须通过 Ruby 的语义查询判断，不能按文件是否存在判断。最后一条事件中断时忽略残段，下次追加先截掉残段；追加失败不得重写已经同步的前缀。追加前后都核对同一文件身份，遇到并发替换就保留新文件并失败。首条记录先在同目录私有临时文件中完整同步，再以不可覆盖的原子改名发布并同步父目录；失败时正式路径只能不存在或保持完整，成功前不得写 `defaults`。
- macOS 三个档位重试都必须在现有 `prepared`/`installed` 记录上继续，不能先释放所有权再重建。首次安装时，Shell 在关闭自动更新子进程启动前登记回退责任并暂存信号；已有保存档位时则保留关闭状态。自动更新回读或恢复失败时返回 `partial`，按同一档位重试。
- macOS 配置事务在第一次写入前记录每个目标的真实路径、原文件身份、原字节和完整候选。首次建立私有状态目录时必须逐级创建并同步每个新目录及其父目录；中途失败后的重试先重新同步已经出现的目录，完成前不得写恢复状态、偏好或配置。版本化备份完整写入并设好权限后必须同步备份目录。事务发布前同时校验逻辑路径与真实路径仍位于同一个规范配置根目录，指向目录外的符号链接必须整批拒绝；允许的目录内符号链接仍写真实目标。写入、备份回退与运行加载前都必须仍匹配同一路径、同一身份和候选摘要。写入只通过已经锁定的原文件句柄执行：先截为零长度，再写入并同步。事务记录发布后、任何配置写入前必须同步记录所在目录，删除记录后也必须同步该目录；失败时停止。Clash 同时原子刷新或重指符号链接时，新目标始终保留，本次操作只处理事务拥有的旧目标并报告并发变化。v2 事务中，目标已经是完整原字节时只确认，只有同一原 inode 上的完整候选才自动恢复；空文件以及原字节或候选的任何截断前缀都无法判断来源，必须原样保留目标与事务并返回待恢复。不同 inode 一律视为外部刷新并保留。缺少文件身份的旧版事务不得自动覆盖候选。
- macOS 用途档位先通过私有临时文件替换，再同步文件和父目录；同步失败必须恢复旧档位。安全卸载在每份暂存文件、元数据和 `READY` 都完成同步前不得删除目标；删除后必须同步安装目录，失败时从已同步暂存恢复。删除后的文件恢复必须以原子、不可覆盖的方式发布，恢复过程再次被强制结束时允许下次继续，不能留下会被误判为外部修改的半文件。
- macOS 普通安装、安全更新、安全卸载和变更型 Ruby 入口必须共用同一个跨进程操作锁，从读取用途档位持续到最终提交。子流程必须验证继承的锁描述符、固定锁文件身份和锁仍被持有，不能只信任环境标志。并发写操作等待最多 5 秒后返回 `operation_in_progress`，不能让卸载在最终核对后按路径删除另一个安装刚发布的新档位或所有权状态。卸载在删除后中断时，下一次安装或安全更新先在锁内完成未完成的安全卸载；自动更新已经处于本工具拥有的关闭状态时，`already_disabled_owned` 必须视为幂等成功并继续恢复。恢复收据或状态无法确认时停止，不得绕过该事务写入新档位。
- macOS 所有内部状态路径都固定派生自 ClaudeEasy 当前状态目录，不接受环境变量把用途档位文件改到其他位置；普通 Patch 和安全更新的显式档位必须在副作用前与固定用途档位文件一致，自动更新修改命令只允许已验证外层锁的安装、卸载和恢复子流程调用。帮助、读取档位和无效请求不创建或修改状态。已有待恢复卸载时，先完成公开卸载恢复，再执行新安装的档位与环境检查。
- macOS 普通 Patch 与安全更新的最终 Ruby 子流程执行时必须暂存 TERM、HUP 或 INT。确认成功后先提交保存档位和订阅自动更新所有权，再返回 `partial/operation_committed_interrupted`；前台进程组信号同时终止子流程、无法确认提交状态时返回 `partial/operation_interrupted_recovery_intent`，保留新档位和自动更新关闭状态供下次继续。没有信号的普通失败仍恢复旧状态。
- macOS 最终 Ruby 子流程必须在输出文本或 JSON 前，把预分配的私有提交收据从 pending 原位改成 committed 并同步。提交后结果传输失败或收据自身无法发布时返回 `partial/operation_committed_result_failed`，保留新档位、自动更新关闭状态和所有权。收据损坏、不可读或子进程异常终止而无法确认提交状态时返回 `partial/operation_result_unknown_recovery_intent` 并保留恢复意图；只有收据仍为有效 pending 且子进程普通失败时才能补偿旧状态。
- macOS 安全卸载发现未完成的配置事务时，先恢复原文件并重新加载当前原订阅，完成缓存、TUN、代理组、DNS 和连接检查。恢复失败时，在删除安装文件、清除用途档位或恢复订阅自动更新之前停止，并保留配置事务、用途档位和自动更新所有权。
- macOS 当前订阅刷新成功后，必须通过本地控制器依次清除 Fake-IP 和 DNS 缓存，再做 DNS 与连接验证；缓存清理失败也要恢复原配置。
- macOS 普通 Patch 的未完成事务恢复不仅要还原文件；当前订阅可能已经加载候选时，必须先重新加载恢复后的原订阅并完成运行检查，成功后才能删除事务记录和处理新候选。运行检查只保留目标配置中仍存在的 Selector 选择；目标仍有的用户 Selector 丢失或改选必须失败。强杀恢复或本次自动刷新回退中的运行恢复失败时，都要保留事务并停止；本次使用 `--no-reload` 时也必须保留事务并停止处理新候选。
- macOS 安全更新恢复事务时，必须从当前存储位置的全部配置识别活动项，不能只在远程订阅目标中查找。旧事务恢复和本次安全更新回滚都要等原配置重新加载并通过运行检查后才能删除事务；代理组选择按将要加载的目标配置取交集，不能让已删除的旧自有分组阻止升级，也不能忽略目标仍保留的用户分组。运行恢复失败时保留记录并停止下载或下一轮写入。
- macOS 普通 Patch、安全更新、备份恢复和未完成事务恢复在每次控制器加载前重新核对当前订阅和存储位置。用户在候选校验、下载或文件写入期间切换时绝不加载旧订阅；首次加载前发现变化必须恢复本次文件批次，已经加载候选后才发现变化则恢复能确认的文件并保留事务，等待客户端状态稳定后继续。
- 当前订阅或存储偏好无法可靠读取、当前目录无法唯一匹配活动配置时必须停止；不得把读取失败当成默认 `config.yaml`，也不得在没有完成运行恢复时删除事务。
- `config.yaml` 是 ClashX Meta 的默认基础配置，不得删除；当前选择其他订阅时安静跳过它，不把它当成无效订阅报错。

## 配置历史、比较与恢复

第一次运行保存初始快照；以后每次实际写入前保存包含日期时间的修改前版本，不覆盖或自动删除旧备份。Windows 备份必须先在同目录临时文件中完整写入、同步并设置私有权限，再原子发布正式编号；中断的临时文件不能被列出、冒充初始快照或用于恢复。用户说某次改动后异常时，先列出备份，选择**症状出现前**最近的一份，再**先比较**、后判断；只报告变化字段、文件名和 SHA-256，不输出配置值。macOS 依次用 `--list-backups`、`--compare-backup ID`、`--restore-backup ID --expected-current-sha256 SHA256`；Windows 依次用 `-ListBackups`、`-CompareBackup ID`、`-RestoreBackup ID -ExpectedCurrentSha256 SHA256`。
只有配置差异与原始症状的证据相符、备份通过校验、目标仍是比较时的 SHA-256，才允许恢复。恢复前先备份当前版本，恢复后用原应用、原目标、原动作复测；无改善或验收失败时恢复回滚前版本。macOS 恢复备份前必须持有与 Patch、安全更新相同的操作锁并先处理未完成的配置事务；若事务恢复改变了当前字节，本次备份恢复按哈希冲突停止，重新比较后再试。macOS 恢复当前订阅后，必须通过本地控制器重新加载，保持恢复前的 TUN 开关和代理组选择，并完成缓存、DNS 与连接检查；任何一步失败都恢复回滚前版本。文件恢复但运行内核未恢复时必须单独报告，不能继续把原始症状复测写成已完成。恢复非当前订阅时只更新文件，不切换当前订阅。Windows 客户端正在运行时只做列出和比较，不停止客户端来强行恢复。

macOS 备份恢复遇到旧 Patch 事务时，必须在哈希判断前同时恢复文件和运行配置；运行恢复失败时保留事务并停止。备份文件替换前建立新的持久事务，并把提交后的真实路径与文件身份贯穿到运行加载和失败回退；相同字节的外部替换不得被覆盖。文件已经与备份相同时，当前订阅的运行检查也必须有事务保护。运行加载与检查在同一操作锁和事务内完成；只有运行检查成功，或失败后文件与运行配置都已恢复，才能删除事务记录。

| Windows + Clash Verge Rev | `.\scripts\install_windows.cmd -UsageProfile N` |

三个档位的安装程序都检查 Mihomo，关闭订阅自动更新，并把共同国内域名直连基线应用到当前存储位置中的全部订阅；档位 1、2 不增加 TUN、IPv6、WebRTC 或 AI 分组设置。客户端开关由 Computer Use 操作并复测。Windows Computer Use 只能操作当前会话的前台桌面，实际工具不可用时不得假装已操作。Windows 客户端正在运行时，三个档位都不修改用途档位、自动更新所有权、脚本或客户端配置；档位 3 返回 `client_running_profile_three_deferred`，档位 1、2 返回 `client_running_auto_update_deferred`。三个档位的安全卸载也必须等客户端未运行：只要有受保护文件或状态需要恢复、删除，客户端运行时返回 `partial/client_running` 并整批不改。不能只改磁盘后声称已经关闭当前会话的自动更新。macOS 当前订阅刷新后检查 TUN、DNS、外网连通性和目标配置仍保留的代理组选择，失败时自动恢复。Windows 三档都使用全局扩展脚本，档位 1、2 只包含共同基线；已有脚本只有唯一同步 `main`，且唯一入口声明之外没有任何裸 `main` 引用时才能组合，属性访问、别名、对象简写和额外绑定都必须拒绝。组合器先在私有 setup 中捕获引擎、真实全局和内置对象描述符；改名后的旧脚本仍直接位于 Clash 的真实 `try`/Script 顶层，保留顶层 `var`、函数、`globalThis`、`this` 与开头 `"use strict"` 字符串的客户端语义。旧顶层结束后先恢复内置对象，再把全局 `main` 封闭为不可配置的受管访问器；每次旧 `main` 执行都在 `finally` 恢复内置对象，正常返回后才执行受管变换。模板字符串表达式也必须按代码检查；使用 `eval`、`Function`、点号函数构造器或值为 `constructor` 的计算属性字符串时必须在写入前拒绝，不能报告安装成功。两个平台都保持 Clash 运行。Skill 调用脚本时优先使用 JSON v1（macOS `--json`、Windows `-Json`），按稳定 `code` 与 `operation` 判断，不解析中文；输出不得含订阅 URL、密钥、完整路径或节点名称。分流验证的中文输出也不得显示代理组名称、当前节点或连接链节点。

## 安全更新全部订阅

用户说“更新节点”“更新订阅”或同义表达时，进入安全更新，不把它当成只更新当前订阅：

用户已经说明服务商订阅开关已打开或倒计时仍有效时，立即执行安全更新。不得检查或操作服务商后台，不得用 Chrome、Browser 或 Computer Use 登录控制面板、查找开关或验证倒计时；这是用户自己完成的操作。必须先实际更新，不能先猜订阅开关有问题。有多份订阅时，逐一报告哪些订阅下载与校验成功、哪些失败；macOS 整批事务中，其他候选即使下载与校验成功，只要有一份失败就不写入，必须明确写成“下载与校验成功但未写入”。

只有更新确实失败、又没有明确的本机故障时，才提醒用户：“服务商可能设置了订阅开关。请登录服务商网站，在控制面板找到订阅开关并打开；开关关闭时无法更新。打开后请立即重试安全更新。”不得把可能性说成已确认原因。

1. 读取已保存档位和当前存储位置，列出全部远程订阅；不显示订阅地址。
2. 为每份当前配置创建带日期时间的修改前备份。macOS 运行 `bash scripts/install_macos.sh --safe-update`，一次下载全部远程订阅；全部下载、YAML 重读、二次转换和 Mihomo 校验成功后才统一替换。任何一份失败时尝试恢复全部文件；恢复本身失败必须逐份报告，不能误报全部保持原样。
3. 三个档位都对每份下载结果重新应用共同国内域名直连基线；档位 3 再应用完整补丁，档位 1、2 不增加第三档设置。更新后刷新当前订阅并复核运行状态，失败时整批回滚并重新加载原配置；订阅文件已恢复但运行内核未恢复时必须单独报告，不能写成全部保持原样。若上次安全更新在运行内核加载候选后被强制结束，下一次安全更新必须先恢复文件并重新加载恢复后的当前订阅；运行内核无法恢复时停止下载并报告待恢复。
4. Windows 先运行 `.\scripts\install_windows.cmd -SnapshotProfiles` 核对并备份全部远程订阅。快照从读取 `profiles.yaml` 起持有它和全部远程订阅的只读版本锁，当前每份订阅必须先有非空代理组并通过 YAML、Mihomo，再用锁内同一版本生成备份和清单；客户端“先写订阅、后写索引”的更新若已写出订阅但尚未保存索引，订阅必须先通过基线校验，索引只有在清单发布后重试成功才算本轮时间戳凭据。`updated: null` 表示客户端尚无更新时间，按空时间戳处理。再用 Computer Use 在 Clash Verge Rev 中执行“全部更新”，随后运行 `.\scripts\install_windows.cmd -VerifySafeUpdate`。每份订阅必须用文件 SHA-256 变化或更晚的客户端 `updated` 时间戳证明本轮已经刷新；内容不变但时间戳更新可以通过，两者都不变时返回 `safe_update_refresh_pending`，保留清单和文件，不能误报成功。验收还必须确认已安装的受管 `Script.js` 与当前安装包及保存档位一致，且受管区块外只有空白或注释；可执行前缀、后缀或额外 `main` 一律拒绝，重装则在组合检查通过后迁移并保留区块外旧代码。随后逐份确认 `proxy-groups` 是非空的块状或行内列表，再做 YAML、Mihomo 和自动更新状态检查；缺少代理组或列表为空时整批恢复，不能判成功。`profiles.yaml` 映射未变但订阅文件缺失时，从清单绑定的可信备份原子重建，并与清单删除一起提交；同一路径重新出现时不覆盖并保留清单。只有订阅内容缺失或检查失败，且索引与受管脚本仍是检查开始时的同一版本，才允许在持续锁住两者时恢复；索引、脚本或其他验收状态并发变化时返回 `safe_update_verification_retry_pending`，保留当前订阅和清单。旧版 v1 清单仍可凭内容变化完成验收；它不再依赖不会用于自动恢复的旧备份。若内容没变但当前订阅完整通过检查，则删除旧清单并返回 `safe_update_legacy_snapshot_required`，让后续操作重建 v2 快照。验收失败时不自动恢复来源无法确认的旧备份，而是返回 `safe_update_legacy_recovery_pending` 并保留当前订阅和清单。仍须把运行内核写成“未验证”并重新检查，不能把文件恢复冒充运行状态恢复。客户端没有“全部更新”时逐份触发，但必须覆盖清单中的每一份并逐份报告。
5. 三个档位都会关闭订阅自动更新。网络正常时不主动建议频繁更新；连接异常、服务商通知订阅变化，或距离上次更新已数月时，提示用户说：“请帮我安全更新全部订阅”。这是一次性授权：获取全部远程订阅、按已保存档位重新应用对应补丁并完成检查后，再次确认自动更新关闭。不得为了本次更新长期打开周期自动更新；任一份失败时按上述事务恢复，只有确认成功恢复后才说“全部保持原样”。

关闭和复核自动更新由平台脚本完成，不依赖 Computer Use。

共同基线用受管 `cn.mrs` 规则提供器同时驱动 DNS 与路由：`nameserver-policy` 的 `rule-set:<受管名称>` 把国内域名交给大陆加密 DNS，`RULE-SET,<受管名称>,DIRECT` 让连接直连。档位 3 另外保留 `geosite:cn` 后备，并让普通国外域名使用通过原主代理组访问的受管 DoH、AI 域名使用通过 AI 分组访问的受管 DoH。DNS 静态安全判断不执行订阅提供的 `exclude-filter`；引用带非空过滤器或动态成员代理组的解析器改用受管 DoH。`direct-nameserver` 作为直连出站的同一套后备，不得为单个国内网站添加 DNS 例外。

订阅已有可选 AI 分组时，直接复用，只补全规则；不得修改它的成员或当前选择。没有 AI 分组时才创建独立的 `🤖 AI · ClaudeEasy`，加入订阅全部可用的真实节点和代理提供者，让主代理组与 AI 节点互不影响。订阅只有 AI 分组时允许普通与 AI 流量暂时共用它，不能因此跳过共同基线或档位 3 增强。找不到任何可用节点或代理提供者时不创建无意义的分组。不得创建第二个安全代理分组，也不得替用户选择节点。

规则列表最前面必须依次放置 `NETWORK,UDP,<AI 分组>`、`NETWORK,UDP,REJECT`。所有 UDP 都先由 AI 分组处理，不能回到本地直连；所选节点不支持 UDP 时继续命中拒绝兜底。AI 分组当前选择必须是代理节点，不能是 `DIRECT`；节点不支持 UDP 时如实报告 WebRTC 未通过或 UDP 不可用。

不要设计按应用隔离。用户会在同一个浏览器里同时访问国内网站和 AI 网站，而 WebRTC 的 STUN 连接不带原网页域名，Mihomo 无法判断它来自哪个标签页。TCP 与 DNS 可以按域名区分，WebRTC 防护必须覆盖全局 UDP。QUIC 也使用 UDP，因此会经过 AI 分组；国内网页的 TCP 和 DNS 仍然直连。明确告诉用户：这会影响游戏、语音和视频通话；家宽通常更适合 AI，最终节点仍由用户选择。

逐份报告结果。当前订阅只有自动刷新和运行检查都通过才能写成“已更新并自动生效”；失败并恢复时如实报告。其他订阅写成“选择该订阅时生效”。同时说明主代理组、AI 分组、是否新建了独立节点选择器和配置中的 TUN 状态。

## Patch 专用验收（Diagnostics 不固定执行）

macOS 运行 `ruby scripts/macos/verify_routes.rb`，可用 `--main-group`、`--ai-group`、`--observation-seconds` 调整；Windows 运行 `powershell.exe -NoProfile -File scripts/windows/verify_routes.ps1`，对应参数为 `-MainGroup`、`-AiGroup`、`-ObservationSeconds`。Windows `-ControllerUrl` 只允许本机回环 HTTP/HTTPS，密钥只经标准输入交给 `-SecretStdin`，非空 `-Secret` 必须拒绝，请求禁用代理和重定向，任何输出或日志都不能包含密钥。两端都从 Mihomo `/rules` 的最后一个 `MATCH` 读取当前实际主代理组，并从 `/proxies` 的当前内存状态识别 AI 分组，不能另用磁盘配置或固定名称猜测。两者启动的 curl 都绑定独立源端口，只接受源端口、TCP、目标域名和新连接 ID 同时匹配的 Mihomo 实时记录，不能拿浏览器或后台程序的并发流量代替。验收同时读取 `/proxies`、`/providers/proxies`、`chains` 和 `providerChains`，按本次连接的实际叶子类型判断；自定义名称的 `Direct`、`Dns`、`Reject`、`RejectDrop`、`Pass`、`PassRule`、`Compatible` 或 `Rematch` 也必须失败。访问 Google 时必须经过主代理组，或订阅明确提供的非 AI 专用组，不能经过 `DIRECT` 或 AI 分组；访问 OpenAI、Anthropic 或 Claude 时必须经过 AI 分组当前节点。`Selector`、`URLTest`、`Fallback`、`LoadBalance` 和 `Relay` 都按实际连接链验收；没有 `now` 的主代理组或 AI `LoadBalance` 都以观察到的叶子为准，不能拿请求前的 `now` 快照代替。JSON 成功码统一为 `routes_verified`，失败码统一为 `route_verification_failed`；每项检查只返回 `passed`、`failed` 或 `not_observed`。任何一项走错都要继续修复，不能只看 YAML 规则。

Claude 联网只由分流验证脚本完成。任何 Patch、Diagnostics、复测或安全更新都不得用 Computer Use、浏览器自动化或系统浏览器打开 `claude.ai`，也不得进入已登录账号、读取账号页面或发送测试消息。用户要求“完整流程”“确认 Claude 可用”或“不要停”都不扩大这项授权；浏览器只打开本地区域检测页和下列三项 DNS/WebRTC 页面。

再验证用户报告的国内站点；没有指定站点时使用常见国内域名。通过 Mihomo `/dns/query` 读取当前 A/CNAME，同时直接查询策略中的两套大陆 DoH，确认当前结果来自同类大陆 CDN，而不是代理节点所在地的解析结果。随后记录 HTTPS 的 DNS、TCP、TLS、首字节和总耗时，并从 `/connections` 确认连接链为 `DIRECT`。解析位置、实时时间和连接链缺一项都不能写成通过。

然后使用 Computer Use 自动打开以下页面并完成操作。它们会收到浏览器公网 IP；用户已经要求运行本 skill 时可视为同意执行这些指定测试：

1. `https://ipinfo.cv/webrtc-check`
2. `https://ip.net.coffee/dns/`，点击“深度测试”
3. `https://ip.net.coffee/webrtc/`

三项都没有红色提示，而且没有未代理公网 IP、私网地址或本地运营商 DNS，才能说验证通过。macOS 或 Windows 环境只要提供 Computer Use，就由代理连续完成，不让用户代点。当前环境没有 Computer Use 时，给出中文逐步操作，写成 `未验证：需要手动测试`，要求用户在任何红色结果出现时截图发回，并继续修复直到通过。

不要修改或添加个人化的 Apple、iCloud 或测速网站规则。
