# ClaudeEasy Windows 平台策略

> 读取路由：网络流程且当前设备是 Windows，或维护 Clash Verge Rev、PowerShell 文件事务与运行恢复时读取本文件。所有网络任务先读取 [policy-core.md](policy-core.md)；本文件不重复共同边界。

## Windows

Clash Verge Rev 有正常主窗口。当前会话有电脑操控时，由代理操作已经运行的 Clash Verge Rev；没有或首次调用失败时先使用本文件已有的安全脚本，再按主入口识别工作台并帮助启用电脑操控。只有确实没有自动入口时才给用户一个最短界面动作。电脑操控不能代替用户处理 UAC、管理员认证或系统安全授权窗口。

当前订阅更新按 `safe-update-and-recovery.md` 运行：执行 `.\scripts\install_windows.cmd -SafeUpdateChangedOnly -Json`，后台读取全部远程订阅正文并逐份与本地配置比对。全部相同时返回 `no_change`，不创建备份、不写文件、不触发刷新；有变化时只为变化订阅创建备份、完成 YAML/协议/Mihomo 检查并写入变化文件，再通过已运行的 Clash Verge Rev 重新加载和核对原 TUN、代理组选择与运行状态。只有确实有变化时才要求客户端正在运行。失败时按安全更新事务恢复，不能把 `partial` 当成成功。

Clash Verge Rev 刷新订阅时运行 `profiles/Script.js`，按已保存档位重新应用全局补丁。刷新后的验收逐份确认本轮更新凭据，核对受管全局脚本、严格 UTF-8、YAML、代理组、Mihomo、更新前 TUN 与代理选择，以及全部远程订阅的 `allow_auto_update: false`；随后通过已安装的重新激活快捷键加载当前订阅，等待运行配置重新生成并通过运行检查，不能只检查刷新前仍在内存中的旧配置。失败时按更新前备份恢复并重新加载原运行配置。验收成功仍只是中间状态，必须继续完成与 macOS 相同的当前档位 `required_followups`、客户端动作、百度、Google、ChatGPT 三页连通性、档位 3 分流、DNS、WebRTC、本地区域指纹测试和最终状态复核；浏览器页面由 Computer Use 在同一用户默认浏览器会话中并行启动，不因单页等待阻塞其他页面。界面与浏览器动作优先由电脑操控完成；当前能力缺失时先帮助启用，确实不能使用才请用户完成最短的必要动作。任一原代理组或节点选择无法确认保留时不得报告完成。

控制器返回的 JSON 只要同一对象含大小写冲突字段就拒绝；代理组、节点选择和显式 `-MainGroup`、`-AiGroup` 名称都按大小写精确匹配，不能把两个合法名称合并。

`profiles.yaml` 的远程订阅项目允许 `option` 出现在列表项首字段或后续字段；两种位置都必须记录唯一字段位置和原始形态。`selected` 块状列表允许列表标记与 `selected:` 字段同级缩进，必须原样保留选择记录，不能将列表项误读为订阅字段。重复 `option`、重复 `allow_auto_update` 或无法唯一归属的嵌套结构必须在候选写入前拒绝，不能追加第二份字段。

Clash Verge Rev 每次加载或刷新订阅都会运行 `profiles/Script.js`。三个档位都安装全局扩展脚本并把数字档位写进受管代码：档位 1、2 只应用共同国内域名直连基线，档位 3 再应用完整策略。TUN 和顶层 IPv6 使用 Clash Verge Rev 的应用配置，因此不会被脚本后的应用设置覆盖。

自动查找 AppHome 时若 Roaming 与 Local 两个受支持候选同时存在，安装、卸载、备份、安全更新和诊断都必须拒绝歧义，不能静默选择其一。

Windows 不安装永久监听、计划任务或后台服务。三个档位仍关闭 Clash Verge Rev 的订阅自动更新。显式安全更新使用 `-SafeUpdateChangedOnly`：只读取 `type: remote` 项目，保留订阅地址、更新时间、间隔和其他选项，逐份比较远端正文与本地配置，只为发生变化的目标创建备份并写入；写入后立即通过已运行客户端重新加载和验收。重复安装不能把已经写成 `false` 的状态误记为原值；无法唯一识别清单、锚点、别名、重复键、多文档或制表符缩进时拒绝。事务仍使用独占锁、原字节和文件身份核对、版本化备份及中断恢复记录；失败时保留现场或恢复到更新前字节。

三个档位的安装（含首次安装）、配置修改、备份恢复、卸载和中断事务恢复均允许在 Clash Verge Rev 运行时执行；客户端运行或在事务期间启动本身不是拒绝、延期或只读的理由。写入仍须取得 AppHome 独占锁、核对全部目标身份与原字节、备份并校验候选；出现文件占用、并发改动或校验失败时按事务规则停止对应写入。文件处理后，代理通过已经运行的客户端加载当前配置，核对当前档位要求的开关、运行配置和原代理组选择；写入成功不能当作已经生效，首次安装写入快捷键也不能当作客户端已注册该快捷键。

备份、事务记录和 Mihomo 候选配置的临时文件必须在创建第一刻就只允许当前用户、SYSTEM 和 Administrators 访问，再写入内容和原子发布，不能先继承目录 ACL 后补权限。Mihomo 候选在写入前启动调用方死亡清理监视，监视同时覆盖 staging 与正式候选。

事务记录和新建文件准备记录持久保存恢复权限；新事务使用 `live_client`，旧版记录及 `client_stopped` 记录按同样的文件校验恢复，不再要求客户端未运行。恢复时必须先独占锁定并核对全部恢复目标，再批量执行修改。提交条件必须只返回一个布尔值。删除事务的目标缺失时，只能在同目录以私有 ACL 创建临时文件，完整写入原字节并执行 `Flush(true)`；提交条件通过且再次确认最终路径仍缺失后，才用不可覆盖的原子移动发布。条件拒绝或恢复中断时不能在最终路径留下空文件或原文前缀，也不能消费恢复记录。目标已换成不同文件身份时，只有完整原字节可以直接确认且不得改写；空内容、原文前缀或其他内容一律保留目标与事务并停止。以后任一公开命令再次进入同一目录时继续恢复。兼容的 `safe_update_running_client` 记录仍按安全更新目标范围核对；目标越界或权限未知时保留记录并停止恢复。

安全更新验收失败且整批允许恢复时，订阅恢复与一次性的运行状态恢复记录必须属于同一个可恢复事务；原验收清单不能继续复用。候选加载与运行恢复都必须在发送快捷键前，从独占锁定的同一运行文件版本取得身份、修改时间和内容哈希，再与当前客户端的 PID、启动时间和会话一起原子消费本阶段发送资格。每个持久阶段最多发送一次全局快捷键；同一或更换后的客户端重试都不得再次发送，只用已保存指纹等待并验证第一次加载或客户端自身重新生成配置的结果。只有原 TUN 与代理选择重新加载并验证成功后才能删除运行恢复记录。安装和备份恢复必须在取得同一 AppHome 独占锁后检查验收清单或运行恢复记录，存在任一种记录时都不得修改受保护配置。冲突、坏备份或事务失败时保留原验收清单并保持整批零改动；进程中断后只续跑运行状态恢复，不得用已经恢复的旧订阅重新验收并报告本次更新成功。

通过已锁定原文件句柄写入替换字节和失败恢复原字节时，都必须先把文件截为零长度，再写入目标内容并同步。这样，中断状态只能是空文件或当前目标字节的前缀，事务恢复可以可靠识别并恢复；不得先覆盖较短内容再依赖事后截断，因为进程可能在截断前留下旧尾部。

批量事务包含原本不存在的写入目标时，必须先确认全部新路径仍不存在，再以原子发布的私有准备记录登记规范相对路径；在此之前不得创建任何最终目标。取得新文件句柄并发布包含文件身份的主事务记录后，先删除准备记录，再开始写入。若进程提前中断，下次公开操作在读取用途档位或其他内部状态前处理准备记录：只删除仍为零字节、非链接、无硬链接且身份在检查期间未变化的目标；缺失目标直接略过，非空内容或身份变化按外部修改拒绝。准备记录损坏时停止，不能猜测删除。

恢复计划必须包含无需写入的已恢复目标和仍缺失的新文件目标；既有目标持有文件句柄，缺失目标持有父目录句柄。恢复与事务记录删除全部完成前不得释放这些句柄。恢复提交条件拒绝或抛错时，必须在句柄仍锁定期间把写入目标恢复到本轮开始字节、取消删除标记并删除本轮重建文件；事务记录保持原字节供下次重试。

Windows 全局脚本也必须做二次转换一致性检查；结果不一致时返回原配置。

组合 `Script.js` 时，只把代码状态中的独立行注释当作补丁边界；普通字符串、模板字符串的文本部分和块注释中的相同文字不是边界，模板表达式仍按代码检查，嵌套花括号不得逃过校验。已有脚本只允许一个同步 `function main` 声明；当前解析能力不能可靠重命名正文引用，因此唯一入口声明之外任何裸 `main` 引用都必须拒绝，包括 `main.version`、`const handler = main`、对象简写、再次作词法声明或裸赋值。使用补丁保留标识符、异步 `main`，或会在重命名后误调用补丁入口的递归 `main` 时，安装器也必须拒绝并保持整批文件不变。`eval`、`Function`、函数的 `.constructor` 和值恰为 `constructor` 的单、双引号字符串会脱离可验证边界，也必须在写入前拒绝。组合器先运行私有 setup，捕获受管引擎、真实全局，以及 `Object`、`Reflect`、`Array`、`Boolean`、`Error`、`Function`、`JSON`、`RegExp`、`String` 和相关原型的完整描述符。改名后的旧脚本直接放在专用原脚本边界内，仍位于 Clash 自己的真实 `try`/Script 顶层，不增加函数或回调层；它的顶层 `var`、函数、`globalThis`、`this` 与开头 `"use strict"` 字符串必须保持客户端直接加载时的行为。旧顶层结束后，finalizer 先恢复并核对内置对象，再把执行器可见的全局 `main` 定义为不可配置的受管访问器；旧顶层对 `globalThis.main` 的改写因此会被最终入口取代。受管入口调用改名后的旧 `main` 时使用 Script 的调用方式，并在 `finally` 中恢复、核对内置对象；旧函数正常返回后才运行 ClaudeEasy 变换，抛错时也必须先完成恢复。受管函数始终留在私有作用域，普通全局写入仍发生在真实执行环境。安全更新比较受管区块时忽略专用原脚本边界内的用户代码正文，但必须逐字核对边界外的引擎和组合结构，并要求整个受管区块外只有空白或注释；任何可执行前缀、后缀或额外 `main` 都拒绝验收。重装必须在组合检查通过后把区块外旧代码迁入专用原脚本边界并保留，卸载再从该边界恢复。

原脚本完整的字符串指令序言必须在受管可执行代码前重复，原文仍保留在专用边界内，使严格函数调用、未声明赋值和其他指令语义与客户端直接加载时一致。识别必须遵循 ECMAScript 的 BOM、空白、四种行终止符、注释、显式分号与 ASI；连续多个指令要逐个保留，字符串续接或前置模板之后的字符串不能提升成指令。单、双引号内的 U+2028/U+2029 按现代 JavaScript 字符串处理，入口行首也接受这两种行终止符。

首次安装把 `config.yaml` 与 `verge.yaml` 的原始字节和安装后哈希写进本地状态文件；用途档位状态 v2 同时保存受管 `Script.js` 区块哈希。安装状态、用途档位状态、自动更新所有权状态和安全更新清单都必须是非链接普通文件，使用严格 UTF-8、唯一字段和精确版本/类型结构；每个流程只读取一次，同一份字节同时用于解析、决策、冲突检查和删除。内部状态不得作为普通单文件备份恢复。v1 用途档位状态没有脚本所有权证据：若当前包无法确认受管区块，卸载必须零改动；用户按原档位重装后，安装器把当前受管区块与 v2 所有权状态放在同一事务，再允许安全卸载。卸载先生成 `Script.js`、订阅自动更新与应用设置的全部候选，再检查全部写入和删除目标；任一冲突时整批零改动。删除文件时必须在持有阻止同文件读取、写入、改名和替换的句柄期间核对字节并删除；失败恢复也不得覆盖恢复期间出现的新内容。卸载时只有当前哈希仍与安装程序最后写入的版本一致才恢复；检测到安装后新改动时保留当前文件和全部状态，不能覆盖。Windows 的订阅增强只在各订阅随后加载或刷新时发生，安装完成不能说所有订阅已经处理。
