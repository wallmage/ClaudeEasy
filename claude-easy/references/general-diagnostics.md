# ClaudeEasy 通用电脑诊断策略

> 读取路由：内部路由为 `general_computer` 时读取本文件，再读当前平台的 `general-macos.md` 或 `general-windows.md`。本文件是通用判断、证据选择、自动修复、复测、内部状态和经验沉淀的唯一权威来源。不读取哪些网络文件，以 `SKILL.md` 通用流程为准。

## 工作目标与完成状态

解决用户描述的原始电脑问题。不预设故障类别，不运行固定检查清单，不启动全量采集或永久监测。

分析或复核只做到原因、证据、反证和未知项清楚，不修改。修复必须针对已经确认的对象，做完最小改动、原场景复测和必要回归。

内部状态只能是下列之一，只供代理判断，不展示给用户，也不写入机器合同：

- `resolved`：原场景已恢复，且本次改动涉及的必要回归正常。
- `mitigated`：原场景明显改善，但仍有已知限制。
- `observing`：证据不足，已建立有范围、有停止条件的观察窗口。
- `blocked`：遇到真实阻塞，已提出用户现在必须做的一个动作。
- `unresolved`：在当前证据、权限或安全边界内无法确认或无法安全修复。

只有原场景通过且必要回归正常才能使用 `resolved`。指标恢复但原场景仍失败，不算解决。

## 原始问题与原场景

从用户原话和当前电脑确定：用户想恢复的行为、实际异常、发生时间、影响范围和成功表现。界面、系统状态或日志能直接读到的信息自行读取，不反问用户。

用户说“电脑很卡”时，原始问题是当时的具体操作没有按预期完成，不是“CPU 是否过高”。任何指标只有能解释这个行为时才有价值。

症状可以安全复现时，先用用户实际应用、实际动作和实际界面观察一次。Computer Use 当前会话实际可用且能操作目标窗口时，由代理操作并回读可见结果；结构化接口更可靠时直接用接口。Clash 客户端不是这里的普通应用，取证见 `SKILL.md` 共同安全边界。不能为了复现而提交支付、发送消息、重复登录、覆盖文件或增加账号风险。

历史问题已经消失时，先读对应时间窗的原始记录。当前健康状态不能代替历史现场。

## 候选解释

只保留能同时解释已知症状、时间、影响范围和健康对照的解释。常见、听起来合理或技术上可能存在，都不足以进入当前判断。

每个仍成立的候选必须同时具备：

- 已有支持证据；
- 当前反证或尚未解释的现象；
- 一项能明显改变判断的下一步验证；
- 该验证不同结果分别会导致什么行动。

不要强行凑固定数量。直接证据已经定位时可以只有一个；证据不足时也不能扩成无边界的可能性列表。

## 下一项检查的选择合同

每次只选一项检查，或一组不可分割的同源读取。调用前必须能说明它区分什么，以及不同结果如何改变下一步。无论得到什么结果都不会改变下一步时，直接跳过。

选择顺序：

1. 能否区分当前仍成立的解释；
2. 能否决定下一步行动；
3. 能否覆盖更多已知现象；
4. 所需时间、权限、隐私范围和副作用是否最低；
5. 是否需要用户介入。

不得因为工具容易调用、数据容易取得或结果显得专业而采集。不得扫描与当前问题无直接关系的文件或字段。

如何在当前平台取得该项证据，只问平台文件。本文件不规定命令清单。

## 判断更新与诊断重置

每得到一项证据，立即确认、降低、排除或撤回对应解释，再重新选择下一步。已被反证的故事不得继续指导操作。

连续两项检查都没有缩小范围时，回到原始问题做诊断重置：列出现有事实、已排除内容和唯一关键缺口。没有新的区分性证据前，不进行第三次试改。

## 证据满足条件与停止检查

直接记录已经指出故障来源和机制时，停止继续检查。没有直接记录时，至少需要彼此独立、能解释原场景的证据，并主动查看关键反例。

目标是取得足以选择安全修复的证据，不是描述电脑的全部状态。足以选择安全修复后立即停止采集。

## 自动修复、恢复与复测

修复必须针对已经确认的问题：

- 一次只改变一个原因相关的对象；
- 修改前记录必要原状态和恢复方法；
- 低风险、可恢复且属于用户请求的修复自动执行；
- 可能丢失未保存工作、删除数据、退出应用、注销、重启、重装、降级或改变安全与隐私边界时，先说明具体风险并取得授权；Clash 客户端及其内核、辅助进程的启停、重装、系统 Repair，以及为修复它们而发起的重启或注销，只按 `SKILL.md` 共同安全边界处理，不得用本条授权；
- 修复失败或出现副作用时立即恢复，不叠加新的试改。

用同一应用、账号、目标和动作复测原始问题，并检查本次修改可能影响的健康行为。如何在当前平台执行修复、保存原状态和恢复，只问平台文件。

转入网络流程只按 `SKILL.md` 内部路由的转入条件。本流程不得自行修改网络配置。

## Computer Use 与其他工具

第一阶段不开发全量状态采集器。按当前判断选用现有能力：

- Computer Use 只用于观察和操作用户实际使用的正常应用窗口；当前会话没有可调用、能操作目标窗口的工具时，不能假装已经观察或操作界面，仍可通过系统接口推进的部分必须继续。
- shell 和系统接口只回答一个明确问题。
- 日志只读相关时间窗、进程、应用和字段。
- 文件搜索只覆盖与当前问题有直接关系的位置。
- 网络查询只在本机证据已经把问题指向具体产品、系统版本或外部服务时使用，并优先官方或第一方资料。

只有真实案例证明原生工具无法稳定取得某项必要证据，或同一安全操作在两端反复出现实现差异时，才新增一个小型专用脚本。脚本必须回答一个明确问题，输出结构化结果，并在 macOS 与 Windows 分别定义等价能力或如实声明平台差异。未出现这种失败前，不新增通用采集器、后台监测或辅助脚本。

## 间歇性问题与观察窗口

现有历史已足够判断时，不另建观察窗口。只有现有历史不足时，才建立有范围、有开始时间、有停止条件和清理方法的观察窗口。不永久运行，不在后台持续采集。

## 经验沉淀与产品改进

可复用经验只保存：能识别适用范围的现场特征、最快产生决定性信息的验证、已确认的原因和修复、恢复方法、原场景与副作用复测结果、已知反例。

一次相关性、一次自然恢复或没有复测的修改不得固化。新经验先作为案例证据；只有能重复识别并稳定改善结果时，才写入产品策略。产品不会自动修改自身，也不上传用户日志或建立后台遥测。

## 用户沟通与真实阻塞

用户沟通、连续执行和真实阻塞以 `SKILL.md` 为准，本文件不重写、不另开一份更短的阻塞清单。

本流程额外遵守：

- 不询问用户属于哪类故障，也不要求用户选择检查方向。
- 能从本机读取或操作的事情由代理完成，不把取证或判断交给用户。
- 模糊描述默认留在本流程，不改问成网络配置问题。
