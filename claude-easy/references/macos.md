# ClaudeEasy macOS 平台策略

> 读取路由：当前设备是 macOS，或维护 ClashX Meta、macOS 文件事务与运行恢复时读取本文件。所有任务先读取 [policy-core.md](policy-core.md)；本文件不重复共同边界。

## macOS

当前订阅更新按 `safe-update-and-recovery.md` 运行 `bash scripts/install_macos.sh --safe-update`；下载使用 `curl --config -`，不得设置 User-Agent。

备份恢复必须先读取有效的已保存用途档位，再按该档位校验；档位缺失或损坏时零写入。

安全更新的文件回滚要分别记录未恢复项与已经恢复后又被外部刷新项。前者返回 `rollback_failed`；后者保留新内容并返回 `safe_update_rollback_superseded`，不能说“全部保持原样”。若运行内核仍待恢复，运行恢复状态优先并继续保留事务，同时说明新内容已保留。

macOS 只允许单次显式运行。安装器在取得操作锁或创建状态目录前先预检全部必需脚本、Ruby 模块与策略文件，任一缺失统一返回 `6/incomplete_package`，不得留下 AppHome。不得安装永久监听、LaunchAgent、`RunAtLoad`、`WatchPaths`、计划任务或目录监听。用户明确选择新档位时，安装器在平台、客户端、Mihomo、状态路径和初始快照全部通过后，先原子保存新档位作为恢复意图，再修改自动更新或订阅。可捕获的失败必须恢复旧档位；进程被强制结束时保留新选择，下一次 Patch 或安全更新按新档位完成缺失步骤，不得按旧档位重建订阅。

普通 Patch 与安全更新的最终 Ruby 子流程执行期间，Shell 必须暂存 TERM、HUP 与 INT。没有信号且子流程失败时恢复旧档位和自动更新；子流程确认成功时先提交保存档位与自动更新所有权，再以 `partial/operation_committed_interrupted` 处理等待信号。前台进程组信号同时终止子流程、无法确认提交状态时返回 `partial/operation_interrupted_recovery_intent`，保留新档位、自动更新关闭状态和所有权供下次继续。不能在可能已经提交配置后恢复旧档位。

Shell 在最终子流程前创建固定长度、权限为 0600 的 pending 提交收据；Ruby 完成文件与运行配置事务后、输出任何文本或 JSON 前，把同一文件原位改成 committed 并同步。stdout 断开或结果文件写满时，外层核对 committed 收据并返回 `partial/operation_committed_result_failed`。事务已经成功但收据写入、同步或读回失败时，Ruby 必须用不依赖再次输出的内部退出状态通知 Shell，外层同样返回 `partial/operation_committed_result_failed`。收据损坏、不可读或子进程异常终止而无法确认提交状态时返回 `partial/operation_result_unknown_recovery_intent`。以上情况都保留新档位、自动更新关闭状态和所有权；只有收据仍为有效 pending 且子进程普通失败时才恢复旧状态。收据路径必须位于当前备份目录，文件身份、权限、唯一链接、nonce 和 pending 字节不符时拒绝使用。卸载器不得使用外层进程继承的内部退出收据路径；只有操作锁子进程通过持锁验证后，才能启用父进程本轮签发的路径。

只处理 ClashX Meta 当前存储位置。使用本地存储时只看本地目录；使用 iCloud 时只选包含当前订阅的当前容器。读不到存储模式，或多个 iCloud 容器无法通过当前订阅唯一判断时停止，不猜。旧容器、历史目录和备份即使仍存在也不得处理。

订阅使用 YAML 1.2 核心类型读取，`yes`、`on`、`0123`、`1:20` 和日期保持文本。多文档 YAML 与循环别名按无效内容跳过；超过系统 Ruby 安全递归深度的文件只跳过该文件，不能终止整批。写入前先在临时文件中生成并重新解析候选，并强制使用满足最低版本的 Mihomo 检查。读取、校验和写入之间若订阅被刷新，重新读取并重试，连续变化时跳过。文件锁必须在固定时间内取得；首次建立状态目录时逐级创建私有目录并同步新目录及其父目录，中途失败后的重试必须先重新同步已出现的目录，完成前不得写恢复状态、偏好或配置。普通安装和安全更新在第一次整批写入前保存持久事务记录，记录逻辑路径、真实路径、原文件身份、原字节和完整候选；即将加载活动配置时还必须用 v4 记录更新前的活动真实路径、TUN 与 Selector 选择。订阅配置的逻辑路径本身不能是符号链接；发布事务前，逻辑路径与真实路径还必须同时位于同一个规范配置根目录。事务记录原子发布后必须同步父目录，且在这一步成功前不得写配置；事务完成时先用同目录完整临时文件原子替换成 v3 已提交标记并同步父目录，再删除记录和再次同步，删除未持久化时下次只清理标记、不得恢复已经提交的配置；标记替换后的首次父目录同步失败必须报告提交状态未知，并让外层保留当前档位和恢复意图。报告成功或清理记录前必须再次核对整批目标仍是本轮文件身份和完整候选。配置通过已锁定的原文件句柄先截零、再写入并同步，因此客户端同时原子替换目标时，新 inode 始终留在目标路径，本次操作检测到身份变化后停止。v2/v4 恢复只自动把同一原 inode 上的完整候选恢复成原字节；完整原字节只确认，空文件和任一原字节或候选前缀都保留目标与事务并返回待恢复。不同 inode 一律保留，不能在无法确认来源的状态上继续。每次写入都使用独占创建生成一个带日期时间的版本化备份，两个进程不能互相覆盖；备份完整写入并设好私有权限后同步备份目录，成功后才允许后续修改。`--dry-run` 与 `--no-reload` 只允许普通 Patch 使用；任何独立操作与这些修饰符组合，或一次指定多个独立操作，都在取得操作锁和写入前拒绝。

候选 YAML 重新读取后，必须再次执行完整转换。二次转换仍报告变化，或二次结果与第一次候选不同，说明补丁不具备幂等性；此时保留原文件并写成“已跳过：二次转换不一致”。

每份订阅即使转换结果无需修改，也必须把锁内原字节交给 Mihomo 校验；全部文件通过后才进入运行验收。

当前订阅写入前记录当前所有可选代理组的选择。候选可能新增选择器，加载前只保留旧运行状态与候选磁盘共有的选择器；加载后立即通过本地控制器恢复这些选择，再验收候选新增的 AI 分组。写入后只允许通过 Mihomo 本地控制器执行 `PUT /configs?force=true`，并要求 HTTP 204。加载前失败只恢复文件，不能再发一次 `PUT`；加载请求已经发出但结果失败或不明确时才按完整运行回退处理。刷新成功并恢复 TUN 与 Selector 后保留 Fake-IP 映射，只执行 `POST /cache/dns/flush`；请求失败视为刷新失败。Mihomo 会在配置重载时继承旧 Fake-IP 映射，不能再主动清空，否则应用或 AdGuard 仍缓存的旧假地址会失去域名对应关系。

普通 Patch、备份恢复和未完成事务恢复必须在每次控制器加载前、加载后以及运行检查结束时重新读取 ClashX Meta 的当前订阅，并在自动发现目录时同时重新读取本地/iCloud 存储位置。任一读取、唯一活动路径或开始时的存储位置不一致时，绝不加载旧订阅，也不把旧订阅的健康结果当成成功。首次加载前发现变化时按已核对的身份恢复本次文件批次；候选已经加载、运行检查或回退阶段才发现变化时，恢复能确认的文件但不再加载旧路径，保留事务供下次在稳定状态下恢复。显式 `--profile-dir` 绑定调用方给出的规范目录，不套用本地/iCloud 存储判断，但仍核对当前订阅。

当前订阅或存储偏好必须能与读取失败区分；缺少 `selectConfigName` 可以表示默认 `config.yaml`，但偏好导出、解析或字段类型失败不能按空值继续。当前目录必须恰好匹配一个活动配置；零匹配或多匹配都停止，未完成的事务保持不变。

普通 Patch 的持久事务可能在当前订阅已加载候选、事务记录尚未删除时被强制中断。下一次 Patch 必须先恢复原文件，再按 v4 中更新前的 TUN 与 Selector 重新加载当前原订阅；代理组选择只核对原订阅仍存在的选择器，候选临时新增的选择器不能阻止恢复。恢复只要求 DNS 缓存操作、原 TUN、原选择和实际联网恢复；旧配置本来无法通过的单项境外 DNS 查询不能阻止恢复。恢复完成后才能删除事务记录并开始新一轮校验；恢复失败时保留事务记录并停止。本次自动刷新失败、文件已恢复但原运行配置未恢复时，也必须保留同一事务供下次 Patch 重试。恢复入口使用 `--no-reload` 时不得删除事务或处理新候选，等待以后允许刷新时完成运行恢复。

备份恢复与普通 Patch 共用上述事务完成条件。开始备份校验前若存在未完成的配置事务，先恢复文件和当前运行配置；运行恢复失败时不删除事务，也不读取或写入备份。实际替换备份前另建持久事务；当前文件已与备份相同时，也用相同原字节和候选字节建立运行恢复记录。操作锁持续覆盖当前订阅的重新加载和运行检查；文件替换后被强制结束时，下次公开操作恢复替换前字节，运行回退失败时继续保留事务。

DNS 缓存清理后确认 TUN 保持加载前状态（档位 2、3 必须启用）、原有代理组选择已经恢复、国内 DNS 查询成功、实际境外 HTTPS 可连接。真实 HTTPS 同时证明境外解析、路由、TCP 和 TLS 可用，不能再用独立的固定境外 `/dns/query` 结果重复拦截。冷加载后的运行状态最多等待两秒，等待期间不得重复清缓存。档位 3 在提交事务前还要同时读取 `/proxies` 和 `/providers/proxies`，沿 AI 分组当前选择逐层检查所有同名候选；`Selector`、`URLTest`、`Fallback` 必须落到代理节点，`LoadBalance` 的全部当前成员都必须是安全代理路径，任何 `Direct`、`Dns`、`Reject`、`Pass`、`Compatible`、`Rematch`、`Relay`、未知组态类型、缺失目标或循环选择都失败。活动文件无需修改时也必须执行这项只读检查；备份恢复按保存档位验收，档位 3 必须包含当前策略的全部 AI 规则并位于宽泛规则之前，缺少任一规则或对应分组时失败。对用户报告的国内站点，还要比较 Mihomo 与两套大陆 DoH 的 A/CNAME、记录 HTTPS 分阶段耗时，并确认实时连接为 `DIRECT`；解析仍随代理节点位置落到境外 CDN 时继续修复。任何一步失败都先核对事务记录、文件身份和当前字节：仍安全拥有时恢复写入前原字节，并在候选已被内核采用时再次加载原配置；外部变化或提交状态未知时保留现场和事务记录。不得调用 AppleScript，不得切换 TUN、订阅、代理组或节点，更不得退出、停止或重启客户端。

活动文件无需修改时，三个档位仍要完成各自的控制器、TUN、代理选择、DNS 和连通性验收，档位 3 再检查 AI 路径；磁盘中的全部选择器都必须在运行状态中存在。这条验收不得重新加载配置或清理缓存。验收后还要重新核对整批文件身份和完整字节，任一文件变化就按最新稳定内容重试，无法确认时不能报告成功。
