# ClaudeEasy macOS 平台策略

> 读取路由：网络流程且当前设备是 macOS，或维护 ClashX Meta、macOS 文件事务与运行恢复时读取本文件。所有网络任务先读取 [policy-core.md](policy-core.md)；本文件不重复共同边界。

## macOS

ClashX Meta 是菜单栏应用。原生开关协调命令优先；没有主窗口不等于当前工具不能操作菜单栏。网络流程仅在客户端已运行、工具实际支持菜单栏或屏幕操作且能可靠定位其图标与菜单时允许 Computer Use 接替；只支持普通窗口附加的工具不能据此虚构菜单能力。不得为附加而启动客户端。

档位客户端开关运行 `ruby scripts/macos/patch_profiles.rb --reconcile-client-switches --usage-profile N --json`。命令先从偏好、本地控制器和 `scutil --proxy` 同时读取用户意图、TUN 实际状态、Mihomo 端口和系统代理归属；只有意图与实际状态一致且需要改变时，才向同一 PID 最多发送一次 ClashX Meta 内置的 `clashtun` 或 `clashtog` Apple Event，随后重新读取状态并检查实际连接。它不使用 `osascript`、System Events、`open` 或 LaunchServices，也不运行应用包主程序。档位 1 只协调 Clash 系统代理且不改 TUN；档位 2、3 先开启并验收 TUN，再关闭 Clash 系统代理并复验连接。第三方 PAC、自动发现或其他代理存在时不得自动开启 Clash 系统代理；第三方代理存在且 Clash 意图仍为开启时也不得盲目切换。

`client_switch_manual_required` 保留兼容代码，表示原生入口未完成，不能解释为要求用户点击。先依据 JSON `warnings` 中的原因码读取客户端身份、偏好、控制器与系统代理，确认前次事件是否已经生效；状态不明或事件可能仍在执行时不叠加点击、不重复发送事件。确认同一客户端稳定运行、实际状态与界面勾选一致且未达档位要求后，由 Computer Use 打开已定位菜单，只改变所需开关：档位 1 开启 Clash 系统代理；档位 2、3 先开启并验证 TUN，再关闭并验证 Clash 系统代理。已经符合的开关不点。

每次点击后重新读取菜单、偏好、控制器与 `scutil --proxy`，确认实际状态及原订阅、代理组、节点未变，并复验连接；再运行原生协调命令确认完成。不能仅凭点击成功或菜单勾选通过。第三方代理冲突保持原设置，继续只读取证和其他可执行项；能力缺失或无法消除的冲突按主入口真实阻塞处理，不要求用户代点。

当前订阅更新按 `safe-update-and-recovery.md` 运行 `bash scripts/install_macos.sh --safe-update --json`；更新前不运行测试，只先备份。下载使用 Foundation 原生网络请求，请求身份从当前运行的 ClashX Meta 应用信息动态生成，并发送 `Accept-Language: zh-CN,zh;q=0.9`；不得使用 curl 或固定 User-Agent。下载结果不是直接覆盖：必须按已保存用途档位解析并应用现行 Patch，完成 YAML 重读、二次转换一致性检查和 Mihomo 校验后才整批写入；任一原代理组或节点选择无法恢复时拒绝更新。更新目标中的当前订阅由已运行客户端的原生事件加载，本地控制器只用于观察和验收；加载后保留更新前 TUN、代理组选择和运行状态，失败时按本文件事务规则恢复。成功后再次确认订阅自动更新关闭；该回执仍是中间状态，必须继续按已保存档位完成客户端动作、全部验收和最终状态复核。

备份恢复必须先读取有效的已保存用途档位，再按该档位校验；档位缺失或损坏时零写入。

安全更新的文件回滚要分别记录未恢复项与已经恢复后又被外部刷新项。前者返回 `rollback_failed`；后者保留外部改动并返回 `safe_update_rollback_superseded`，不能说“全部保持原样”。若运行内核仍待恢复，运行恢复状态优先并继续保留事务，同时说明文件已恢复原内容，或在外部替换时保留了外部改动；不得说本轮候选已保留。

macOS 只允许单次显式运行。安装器在取得操作锁或创建状态目录前先预检全部必需脚本、Ruby 模块与策略文件，任一缺失统一返回 `6/incomplete_package`，不得留下 AppHome。不得安装永久监听、LaunchAgent、`RunAtLoad`、`WatchPaths`、计划任务或目录监听。用户明确选择新档位时，安装器在平台、客户端、Mihomo、状态路径和初始快照全部通过后，先原子保存新档位作为恢复意图，再修改自动更新或订阅。可捕获的失败必须恢复旧档位；进程被强制结束时保留新选择，下一次 Patch 或安全更新按新档位完成缺失步骤，不得按旧档位重建订阅。

普通 Patch 与安全更新的最终 Ruby 子流程执行期间，Shell 必须暂存 TERM、HUP 与 INT。没有信号且子流程失败时恢复旧档位和自动更新；子流程确认成功时先提交保存档位与自动更新所有权，再以 `partial/operation_committed_interrupted` 处理等待信号。前台进程组信号同时终止子流程、无法确认提交状态时返回 `partial/operation_interrupted_recovery_intent`，保留新档位、自动更新关闭状态和所有权供下次继续。不能在可能已经提交配置后恢复旧档位。

Shell 在最终子流程前创建固定长度、权限为 0600 的 pending 提交收据；Ruby 完成文件与运行配置事务后、输出任何文本或 JSON 前，把同一文件原位改成 committed 并同步。stdout 断开或结果文件写满时，外层核对 committed 收据并返回 `partial/operation_committed_result_failed`。事务已经成功但收据写入、同步或读回失败时，Ruby 必须用不依赖再次输出的内部退出状态通知 Shell，外层同样返回 `partial/operation_committed_result_failed`。收据损坏、不可读或子进程异常终止而无法确认提交状态时返回 `partial/operation_result_unknown_recovery_intent`。以上情况都保留新档位、自动更新关闭状态和所有权；只有收据仍为有效 pending 且子进程普通失败时才恢复旧状态。收据路径必须位于当前备份目录，文件身份、权限、唯一链接、nonce 和 pending 字节不符时拒绝使用。安装器和卸载器用内部退出收据区分子流程已输出的失败与取得操作锁失败，避免重复输出或丢失恢复结果。两者不得使用外层进程继承的内部退出收据路径；只有操作锁子进程通过持锁验证后，才能启用父进程本轮签发的路径。

只处理 ClashX Meta 当前存储位置。本地配置位于 `~/.config/clash.meta`；iCloud 位置从当前应用 `Info.plist` 的容器声明和当前订阅匹配，不用 Application Support 搜索结果代替配置定位。使用本地存储时只处理本地目录；使用 iCloud 时只选包含当前订阅的当前容器。只有 `kUserEnableiCloud` 确实缺失时才只读比较当前订阅：它只在本地目录唯一出现就自动按本地处理，不询问用户；本地与 iCloud 或多个 iCloud 容器同时匹配时停止对应写入。偏好导出、解析、字段类型或字段值异常时也停止对应写入。旧容器、历史目录和备份即使仍存在也不得处理。

订阅使用 YAML 1.2 核心类型读取，`yes`、`on`、`0123`、`1:20` 和日期保持文本。多文档 YAML 与循环别名按无效内容跳过；超过系统 Ruby 安全递归深度的文件只跳过该文件，不能终止整批。写入前先在临时文件中生成并重新解析候选，并强制使用满足最低版本的 Mihomo 检查。读取、校验和写入之间若订阅被刷新，重新读取并重试，连续变化时跳过。文件锁必须在固定时间内取得；首次建立状态目录时逐级创建私有目录并同步新目录及其父目录，中途失败后的重试必须先重新同步已出现的目录，完成前不得写恢复状态、偏好或配置。普通安装和安全更新在第一次整批写入前保存持久事务记录，记录逻辑路径、真实路径、原文件身份、原字节和完整候选；即将加载活动配置时还必须记录更新前的活动真实路径、TUN 与 Selector 选择。安全更新使用 v5 事务继续记录 ClashX Meta 进程身份，以及候选加载和恢复加载是否已经发出；旧 v4 事务首次恢复时原地升级。订阅配置的逻辑路径本身不能是符号链接；发布事务前，逻辑路径与真实路径还必须同时位于同一个规范配置根目录。事务记录原子发布后必须同步父目录，且在这一步成功前不得写配置；事务完成时先用同目录完整临时文件原子替换成 v3 已提交标记并同步父目录，再删除记录和再次同步，删除未持久化时下次只清理标记、不得恢复已经提交的配置；标记替换后的首次父目录同步失败必须报告提交状态未知，并让外层保留当前档位和恢复意图。报告成功或清理记录前必须再次核对整批目标仍是本轮文件身份和完整候选。配置通过已锁定的原文件句柄先截零、再写入并同步，因此客户端同时原子替换目标时，新 inode 始终留在目标路径，本次操作检测到身份变化后停止。v2/v4/v5 恢复只自动把同一原 inode 上的完整候选恢复成原字节；完整原字节只确认，空文件和任一原字节或候选前缀都保留目标与事务并返回待恢复。不同 inode 一律保留，不能在无法确认来源的状态上继续。每次写入都使用独占创建生成一个带日期时间的版本化备份，两个进程不能互相覆盖；备份完整写入并设好私有权限后同步备份目录，成功后才允许后续修改。`--dry-run` 与 `--no-reload` 只允许普通 Patch 使用；任何独立操作与这些修饰符组合，或一次指定多个独立操作，都在取得操作锁和写入前拒绝。

候选 YAML 重新读取后，必须再次执行完整转换。二次转换仍报告变化，或二次结果与第一次候选不同，说明补丁不具备幂等性；此时保留原文件，机器结果标记二次转换不一致。

每份订阅即使转换结果无需修改，也必须把锁内原字节交给 Mihomo 校验；全部文件通过后才进入运行验收。

当前订阅写入前记录当前所有可选代理组的选择。候选可能新增选择器，加载前只保留旧运行状态与候选磁盘共有的选择器；混合内联节点与 provider 的组只有在旧选择原本来自 provider 时才允许保留同名选择，已删除的内联节点不能作为 provider 回退。普通 Patch 的文件更新与备份恢复继续使用 Mihomo 本地控制器加载，并在成功后只调用 `POST /cache/dns/flush`；所有控制器运行流程只核对 TUN，不得通过 `PATCH /configs` 修改 TUN。安全更新不得直接调用 `/configs?force=true`，只能向写入前已经确认运行的同一 ClashX Meta PID 发送一次官方 `clash://update-config` 事件。事件必须直接定向到 PID，禁止用 `open`、LaunchServices 或应用包主程序启动客户端。客户端确认接收事件后，原 TUN、Selector、DNS 与实际连接全部通过才算成功；失败时恢复原文件，再发送至多一次客户端原生恢复事件。同一客户端进程的同一阶段已写入事务后不得重试。整个过程保留 Fake-IP 映射，不能主动清空。

普通 Patch、备份恢复和未完成事务恢复必须在每次控制器加载前、加载后以及运行检查结束时重新读取 ClashX Meta 的当前订阅，并在自动发现目录时重新确认已选存储位置；偏好缺失时每次都重新执行唯一的本地当前订阅判断。任一读取、唯一活动路径或开始时的存储位置不一致时，绝不加载旧订阅，也不把旧订阅的健康结果当成成功。首次加载前发现变化时按已核对的身份恢复本次文件批次；候选已经加载、运行检查或回退阶段才发现变化时，恢复能确认的文件但不再加载旧路径，按下述条件核验后结束旧事务；未通过则保留事务。显式 `--profile-dir` 绑定调用方给出的规范目录，不套用本地/iCloud 存储判断，但仍核对当前订阅。

未完成事务的运行检查点指向旧订阅、当前活动订阅已改变时，先安全恢复全部原文件。当前订阅也被该事务改写过时，不能仅凭代理名称和磁盘内容认定运行状态已恢复；无法区分原内容与候选时，按事务类型通过控制器或客户端原生事件重新加载当前已恢复订阅。保留加载前 TUN 和全部 Selector 选择，全过程复核原文件、当前文件、订阅与存储位置；严格实时代理、分组和订阅源身份、TUN、全部选择与实际连通通过后才结束旧事务。当前订阅未被事务改写，或本轮控制器已成功加载恢复文件时，启动缓存不匹配不阻止结束旧事务。当前订阅被改写且本轮未通过控制器加载时，仍要求缓存指纹匹配；后续 Patch 完成缓存刷新与完整配置验收。不得加载旧订阅或切换选择；缺项保留 pending，失败阶段记为 `recovery_active_profile_verification`，按共同异常处理继续诊断。结束旧事务不代表新更新或当前档位完整验收已经完成。

当前订阅读取必须能与失败区分；缺少 `selectConfigName` 可以表示默认 `config.yaml`，但偏好导出、解析或字段类型失败不能按空值继续。存储偏好缺失只允许使用上一段的唯一现行本地订阅判断。当前目录必须恰好匹配一个活动配置；零匹配或多匹配都停止，未完成的事务保持不变。

普通 Patch 的持久事务可能在当前订阅已加载候选、事务记录尚未删除时被强制中断。下一次 Patch 必须先恢复原文件；当前订阅未变时，再按 v4 中更新前的 TUN 与 Selector 重新加载当前原订阅；代理组选择只核对原订阅仍存在的选择器，候选临时新增的选择器不能阻止恢复。恢复只要求 DNS 缓存操作、原 TUN、原选择和实际联网恢复；旧配置本来无法通过的单项境外 DNS 查询不能阻止恢复。旧事务原配置与候选的代理身份相同、无法区分实时加载版本时，只在实时代理、分组和订阅源身份精确匹配（允许内核 GLOBAL、default 与分组派生的 Compatible 提供者，以及已声明订阅源的动态节点）且恢复文件身份、字节及当前订阅均稳定的条件下重新加载原文件；控制器与原生恢复的所有身份分支均核验持久记录中的原 TUN 与选择，不能用当前异常状态代替恢复目标。恢复完成后才能删除事务记录并开始新一轮校验；恢复失败时保留事务记录并停止。本次自动刷新失败、文件已恢复但原运行配置未恢复时，也必须保留同一事务供下次 Patch 重试。恢复入口使用 `--no-reload` 时不得删除事务或处理新候选，等待以后允许刷新时完成运行恢复。

备份恢复与普通 Patch 共用上述事务完成条件。开始备份校验前若存在未完成的配置事务，先恢复文件和当前运行配置；运行恢复失败时不删除事务，也不读取或写入备份。实际替换备份前另建持久事务；当前文件已与备份相同时，也用相同原字节和候选字节建立运行恢复记录。操作锁持续覆盖当前订阅的重新加载和运行检查；文件替换后被强制结束时，下次公开操作恢复替换前字节，运行回退失败时继续保留事务。

DNS 缓存清理后确认 TUN 保持加载前状态、原有代理组选择已经恢复、国内 DNS 查询成功、实际境外 HTTPS 可连接。普通 Patch、备份恢复和安全更新的内部运行检查都只保留加载前 TUN 状态；档位所需的客户端开关协调顺序以 [profiles-and-patch.md](profiles-and-patch.md) 为准。真实 HTTPS 同时证明境外解析、路由、TCP 和 TLS 可用，不能再用独立的固定境外 `/dns/query` 结果重复拦截。普通控制器冷加载最多等待两秒；安全更新按条件等待客户端原生加载，最长三十秒，等待期间不得重复发加载事件或清缓存。档位 3 在提交事务前还要同时读取 `/proxies` 和 `/providers/proxies`，沿 AI 分组当前选择逐层检查所有同名候选；`Selector`、`URLTest`、`Fallback` 必须落到代理节点，`LoadBalance` 的全部当前成员都必须是安全代理路径，任何 `Direct`、`Dns`、`Reject`、`Pass`、`Compatible`、`Rematch`、`Relay`、未知组态类型、缺失目标或循环选择都失败。活动文件无需修改时也必须执行这项只读检查；备份恢复按保存档位验收，档位 3 必须包含当前策略的全部 AI 规则并位于宽泛规则之前，缺少任一规则或对应分组时失败。对用户报告的国内站点，还要比较 Mihomo 与两套大陆 DoH 的 A/CNAME、记录 HTTPS 分阶段耗时，并确认实时连接为 `DIRECT`；解析仍随代理节点位置落到境外 CDN 时继续修复。任何一步失败都先核对事务记录、文件身份和当前字节：仍安全拥有时恢复写入前原字节，并在候选已被内核采用时再次加载原配置；外部变化或提交状态未知时保留现场和事务记录。不得用 AppleScript 或 System Events 操作界面；安全更新只允许通过 macOS Apple Event 接口向已确认运行的 PID 发送上述官方加载事件。安全更新事务内部不得切换 TUN、订阅、代理组或节点；平台命令成功后，`macos_client_switch_reconciliation` 运行独立原生开关协调命令。任何阶段都不得切换订阅、代理组或节点。

活动文件无需修改时，三个档位仍要完成各自的控制器、TUN、代理选择、DNS 和连通性验收，档位 3 再检查 AI 路径；磁盘中的全部选择器都必须在运行状态中存在。已加载配置必须与订阅拥有的完整配置一致，只忽略控制器地址和密钥等明确由运行时注入的字段。仅启动缓存不匹配、实时代理身份严格匹配且允许自动加载时，验收前建立原字节与候选字节相同的 v5 事务，通过上述原生恢复事件刷新当前订阅；保留当前 TUN 与选择，失败保留事务。随后重新执行包含缓存指纹的完整验收；缓存匹配时不得重新加载配置或清理缓存。验收后还要重新核对整批文件身份和完整字节，任一文件变化就按最新稳定内容重试，无法确认时不能报告成功。
