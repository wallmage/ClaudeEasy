# ClaudeEasy 用途档位与 Patch 策略

> 读取路由：首次安装、改变用途档位、执行 Patch，或维护档位与 Patch 验收时读取本文件。所有网络任务先读取 [policy-core.md](policy-core.md)；本文件不重复共同边界。

## 用途档位

### 选择与保存

首次在一台电脑上进入 Patch 时，先读取本机档位。macOS 固定保存于 `~/Library/Application Support/ClaudeEasy/usage-profile.plist`，安装和卸载不得接受环境变量把这个内部状态文件改到其他位置；Windows 保存于 Clash Verge Rev 应用目录中的 `claude-easy-usage-profile.json`。macOS 文件只记录版本和数字档位；Windows 文件还记录安装时受管脚本区块的哈希，用于确认卸载没有删除后续改动。没有已保存档位时，必须先问“你使用网络代理主要用于哪些用途？”，展示以下三项及改动差异，得到选择后才保存和修改。

用户明确说要配置 Claude 或 Claude Code 时，该表达本身就是档位 3 的选择；明确说要配置 ChatGPT、Codex、Gemini、Perplexity 等其他海外 AI，且排除 Claude 时，就是档位 2。

用户可以随时改档。升档只增加新档位所需能力。从档位 3 降到档位 1 或 2 时，先读取并记录旧档位，再运行对应平台的安全卸载程序，最后保存和执行新档位。安全卸载成功后清除旧用途档位；卸载失败或返回 `partial` 时必须保留，不能绕过未完成的恢复。只撤销能确认由本工具写入、且之后没有被用户或客户端继续修改的部分；不能为了降档覆盖后来产生的用户改动。macOS 只有从已开启改为关闭时才写订阅自动更新所有权状态；卸载时当前值仍关闭才恢复为开启，用户已经恢复、原本已关闭或没有状态时不写。所有权使用仅追加事件记录：`prepared`、`installed` 表示仍有恢复责任，`released` 表示已经没有所有权；状态文件保留时也必须按最后一条完整事件判断，不能按文件是否存在判断。中断的最后一条事件可在下次追加前截掉；追加失败只能留下可忽略的残段，不得重写已经同步的有效前缀。追加前后必须核对同一文件身份，不能覆盖并发替换。首条所有权记录先在同目录私有临时文件中完整同步并设好权限，再以不可覆盖的原子改名发布并同步父目录；目录同步失败就停止，成功前不得写 ClashX Meta 的 `defaults`。安装文件删除、自动更新恢复和所有权语义释放必须属于同一个可恢复事务；任一步失败或进程中断时，同时恢复用途档位、自动更新关闭状态和所有权。Windows 按远程 uid 保存原来为开启或缺少字段的项目，原本关闭的项目不纳入所有权；卸载只恢复仍为 `false` 的自有字段，保留用户已恢复的值、本地项目与无关元数据。macOS 已写入当前订阅的内容不能凭猜测还原；Windows 客户端运行时也不会改写应用设置。因此旧订阅增强仍可能保留，必须明确告诉用户“新档位已保存，但这部分旧增强仍保留”，不能伪装成已经恢复。

macOS 三个档位的关闭操作遇到已有 `prepared`/`installed` 所有权时都必须原位完成或续写，不得先写 `released` 再建立新所有权。首次安装时，Shell 在启动关闭子进程前登记回退责任并暂存 TERM、HUP、INT；普通失败先恢复自动更新，确认成功后才恢复旧档位。已有保存档位时保留关闭状态；回读或恢复失败时返回 `partial`，使下次按同一档位继续。

Windows 安装、备份恢复与卸载在客户端运行时的写入边界见 [windows.md](windows.md)。

Windows 安全卸载在读取安装、自动更新和用途档位状态之前，先检查安全更新清单。存在尚未验收的清单时返回 `safe_update_pending`，不得改动或删除全局脚本、用途档位、自动更新与安装状态、订阅、备份或清单；完成客户端刷新后先运行 `-VerifySafeUpdate -RefreshConfirmed` 完成整批验收或恢复，再重试卸载。

macOS 卸载暂存目录分为未就绪、就绪和已提交三种状态。未写出 `READY` 时不得删除任何目标，后续运行直接丢弃不完整暂存；写出 `READY` 后，删除前必须用不可覆盖的原子改名隔离目标，并核对隔离文件仍是最终检查时的身份与字节。并发发布到原路径的新文件必须保留。恢复只能把完整暂存文件原子发布到仍为空缺的目标，不能覆盖并发创建的文件。恢复发布本身被强制结束时，目标必须保持“完全不存在”或“完整原文件”两种状态，下一次运行可继续处理其余目标。异常退出按阶段返回单一机器或中文结果，并保留实际退出码。

用途档位文件、卸载暂存文件与元数据必须先同步文件内容，再同步父目录。安全卸载只有在全部暂存项和 `READY` 都完成同步后才能删除安装文件；删除后必须同步安装目录，失败时恢复全部暂存项并再次同步。首条自动更新所有权记录先在同目录私有临时文件中完整同步，再用不可覆盖的原子改名发布并同步父目录，不能在正式路径留下空文件或半条记录。

macOS 普通安装、订阅更新前备份、安全卸载和变更型 Ruby 入口共用备份目录中的私有跨进程操作锁。订阅更新前备份只使用这把锁保护备份一致性，不读取用途档位，也不处理旧的卸载或配置事务。其余变更流程的锁覆盖用途档位读取与匹配、初始快照、自动更新所有权、订阅事务、卸载暂存、最终核对、删除和提交；Ruby 直接变更入口必须先取得同一把锁，Shell 与 Ruby 子流程必须验证继承的描述符、固定锁文件身份及锁仍被实际持有，不能只信任环境标志。普通 Patch 的显式档位必须在锁内、任何写入前与固定 `usage-profile.plist` 一致；不一致或无有效档位时零配置写入。自动更新修改子命令只允许已验证外层锁的安装、卸载和恢复流程调用，卸载中断恢复还必须验证 `READY`、所有权标记和暂存的用途档位文件。另一个写流程占用时最多等待 5 秒，随后不修改任何状态并返回 `operation_in_progress`。内部 Ruby 配置锁仍保护单次文件事务，不能代替公开流程锁。这样卸载核对旧文件后，安装器不能在删除前发布新的用途档位或所有权状态。卸载在 `READY` 后被强制结束时，下一次普通安装必须先在同一把锁内调用公开卸载流程完成恢复和卸载；自动更新已处于本工具拥有的关闭状态时，恢复返回 `already_disabled_owned` 也必须作为幂等成功继续。只有结构正确的成功收据且暂存目录已经清除，才能继续选择和写入新档位，否则保留恢复状态并返回 `uninstall_recovery_failed`。

macOS 安全卸载发现未完成的配置事务时，必须先恢复原文件并重新加载当前原订阅，依次完成缓存、TUN、代理组、DNS 和连接检查。恢复失败时，在删除安装文件、清除用途档位或恢复订阅自动更新之前返回 `profile_transaction_recovery_failed`，并保留配置事务、用途档位和自动更新所有权；不得把文件恢复冒充运行状态恢复。

Shell 在创建操作锁文件前先区分用途档位文件不存在、有效和损坏；Shell 与 Ruby 共用严格读取入口，状态必须是单链接、无组或其他用户权限的非链接普通文件，并从同一份已验证字节读取唯一的整数 Version 与 Profile。XML 只允许 `plist version="1.0"` 下一个无属性 `dict` 和这两组纯文本键值，重复字段、额外节点、嵌套节点或错误类型都无效。已有但无法严格读取的状态必须返回 `usage_profile_invalid`，不能当成首次安装或覆盖。取得操作锁后再次读取，防止预检与提交之间的变化。

### 三档行为

| 档位 | 用途 | 必须做 | 明确不做 | 验收 |
| --- | --- | --- | --- | --- |
| **档位 1｜普通浏览** | 国内网站、海外普通网站 | 给当前存储位置中的全部订阅安装共同国内域名直连基线，关闭订阅自动更新；macOS 原生开关协调命令确认 Clash 系统代理开启，Windows 按平台界面规则确认 | 档位 1 不修改 TUN、IPv6、WebRTC、AI 分组或节点 | 百度、Google、ChatGPT 能稳定打开，速度无明显异常 |
| **档位 2｜海外 AI** | ChatGPT、Codex、Gemini、Perplexity 等，不含 Claude | 继承共同国内域名直连基线，保持订阅自动更新关闭；不执行档位 1 的系统代理开启动作，macOS 原生开关协调命令或 Windows 平台界面先开启 TUN，再关闭 Clash 自己的系统代理 | 档位 2 不增加 WebRTC 或 AI 分组补丁，不修改节点 | 百度、Google、ChatGPT 能稳定打开，速度无明显异常 |
| **档位 3｜Claude/Claude Code** | Claude 网页、Claude Code，或需要更强的泄漏防护 | 先完成档位 2，再运行完整补丁 | 不自动选择订阅、代理组或节点 | 完成普通站、其他 AI、分流、DNS 深度测试、WebRTC 测试和本地区域指纹测试 |

档位 2、3 关闭系统代理的目的，是避免 Clash 同时用系统代理和 TUN 重复接管同一流量，不是为了隐藏代理。只关闭 Clash 客户端自己的系统代理开关；不得清除或覆盖 AdGuard、其他 PAC、企业代理或安全软件的设置。AdGuard for Mac 的可选配置只在用户明确要求配置、恢复或导入时读取 [adguard.md](adguard.md)，不属于普通 Patch。不能用 `networksetup`、注册表或系统代理命令把其他产品的配置抹掉。

三个档位都包含共同国内域名直连基线。档位 3 的其余完整补丁包括：TUN、DNS 劫持、自动与严格路由、IPv6 关闭、普通国外与 AI DNS 分流、AI 分组与规则、局域网与国内 UDP 分流、其余 UDP/WebRTC 防护和完整验证。不得自动切换节点；节点建议见 [routing-and-security.md](routing-and-security.md)。无法确认目的地的 UDP 会经过 AI 分组，可能影响游戏、语音和视频，必须在选择界面说明。

macOS 与 Windows 的三个档位都把 `profile.store-selected` 设为 `true`，并保留 `profile` 下的其他设置，使 Mihomo 重新加载订阅后继续使用原代理组选择。

macOS 用 `bash scripts/install_macos.sh --profile N` 保存档位，随后运行 `ruby scripts/macos/patch_profiles.rb --reconcile-client-switches --usage-profile N --json`；Windows 用 `.\scripts\install_windows.cmd -UsageProfile N`。三个档位都先检查 Mihomo，关闭订阅自动更新，并安装共同国内域名直连基线；档位 1、2 不增加 TUN、IPv6、WebRTC 或 AI 分组补丁。Windows 三档都安装全局脚本，脚本内写入数字档位；档位 1、2 只执行共同基线，只有档位 3 继续执行其余完整补丁。自动更新设置由安装程序直接修改，不依赖 Computer Use：macOS 把 ClashX Meta 偏好项 `kAutoUpdateEnable` 写为布尔假值并立即回读；Windows 把 `profiles.yaml` 中每个 `type: remote` 项目的 `option.allow_auto_update` 写为 `false` 并逐项回读。任一平台无法安全识别、备份、写入或确认时，当前写入流程停止并保持原状态；代理立即转入诊断，修复后重新执行，不把脚本停止当作任务结束。

## Patch 检查顺序

以下步骤 1–8 用于三个档位的共同国内域名直连基线；档位 3 继续执行完整增强与专项验收。档位 1、2 不执行 TUN、IPv6、WebRTC、AI 分组或第三档验证。

1. 识别操作系统和客户端。
2. 找到客户端配置目录。
3. 先读取客户端当前使用本地存储还是 iCloud。macOS 偏好项缺失时，只做只读定位：当前订阅只在本地目录唯一出现就自动按本地处理；多个位置同时匹配才算安全歧义。确定后只处理该位置。
4. macOS 只枚举当前存储位置中客户端实际使用的顶层 `.yaml`、`.yml`；排除旧 iCloud 容器、缓存、备份、日志和临时文件。`config.yaml` 是 ClashX Meta 的默认基础配置，不得删除；当前订阅不是 `config` 时安静跳过，只有它本身被选中时才处理。
5. 找到当前订阅和主代理组。
6. 执行带已保存数字档位的平台安装程序；当前存储位置中的全部订阅必须使用同一共同基线。
7. 当前订阅修改后，通过 Mihomo 本地控制器自动刷新并完成运行检查；失败时恢复原文件和原运行配置。
8. 验证国内目标实时命中受管规则并直连；档位 3 再完成其余分流与浏览器测试。

## Patch 验证标准

档位 1 只验收系统代理、百度、Google、ChatGPT 和速度；档位 2 验收 TUN、Clash 自己的系统代理开关、百度、Google、ChatGPT 和速度。三页连通性由 Computer Use 在同一用户默认浏览器会话中并行打开，全部正常打开才算通过。不能因为未运行泄漏测试而把档位 1、2 判为失败。以下完整验收只属于档位 3。

只生成 ChatGPT、Gemini 和 Grok 的真实连接，同时读取 Mihomo `/connections`、`/rules`、`/proxies` 与 `/providers/proxies`。macOS 运行 `ruby scripts/macos/verify_routes.rb`，Windows 运行 `powershell.exe -NoProfile -File scripts/windows/verify_routes.ps1`；Windows 控制器只允许本机回环地址，密钥只经标准输入交给 `-SecretStdin`，非空 `-Secret` 必须拒绝。每个测试请求都通过当前 Mihomo 回环代理发出，并确认实际连接链包含当前 AI 分组；检测期间代理组或节点选择发生变化即失败。三项全部通过即为分流验证通过。Claude/Anthropic 禁测见 [policy-core.md](policy-core.md)。

档位 3 的浏览器验收只运行下列项目，并由 Computer Use 在同一用户默认浏览器会话中并行启动，不等待单页完成后再打开下一页：

然后必须测试：

1. `https://ip.net.coffee/dns/` 的“深度测试”
2. `https://ip.net.coffee/webrtc/`
3. 本地 `assets/claude-region-check.html`，点击“开始检测并运行 WebRTC 测试”

DNS 和 WebRTC 页面没有红色提示，且不显示用户未代理的公网 IP、私网地址或本地运营商 DNS，才算通过。本地区域指纹测试必须给出明确风险等级：绿色低风险才算通过；中等风险或高风险都算失败。不得用“不够单一”“不能完全通过”或其他含糊结论代替成功或失败。

两个远程页面会接收浏览器的公网 IP，并发起 WebRTC 或 DNS 测试请求。本地页面会连接页面已披露的 Cloudflare 出口查询和 Google、Cloudflare STUN 服务，但不连接 Claude/Anthropic 域名；这些检测都不上传订阅、节点密码或配置文件。

代理只记录每项通过、失败或未验证及失败类别，不把页面显示的公网 IP、私网地址、DNS 地址或运营商名称复制到聊天、JSON 或诊断记录。

macOS 和 Windows 只要当前会话提供电脑操控，就由代理使用 Computer Use 在用户默认浏览器中打开两个远程页面和本地页面，执行检测并读取结果，不限制浏览器品牌，也不把刷新或测试停给用户。没有电脑操控时先按主入口识别工作台并提供官方启用方法；确实无法启用且这些测试属于当前档位必做项时，才给用户最短操作并等待结果。任一远程页面出现红色结果，或本地页面不是低风险，都判定验收失败并继续处理，不得说已经验证。

### 档位 3 本地区域指纹闭环

已保存档位为 3 时，任何 Patch、更新、恢复、Diagnostics 修复或其他配置任务，都在全部配置动作结束后运行本地页面。初始配置收尾只运行一次；不得连续刷新、重复点击或用多次结果挑选较低分。绿色低风险直接通过。中等风险或高风险时，按页面本轮显示的可操作加分项从高到低自动处理；每轮调整完成后只重新测试一次，仍为中等风险或高风险就根据新结果继续调整，直到得到绿色低风险。只有下面明确保留给用户的选择，或电脑操控确实不可用时，才请用户做一个动作。

中等风险或高风险时按以下顺序处理：

1. **时区：** 中国大陆时区加 24 分，香港或澳门时区加 14 分。命中时首选台北，次选东京；台湾与中国大陆同为东八区，改成台北不会改变电脑显示的实际时间。
2. **系统地区与浏览器语言：** 浏览器语言为中国大陆简体中文时加 18 分；Intl 区域设置显示中国大陆或简体中文时也会加分。命中时把系统地区设为台湾，浏览器首选语言设为“繁體中文（台灣）”。解释目标是让代理出口、系统时区、系统地区和浏览器语言尽量统一。
3. **代理服务器：** 首选台湾家宽；没有家宽时选择台湾普通节点；没有合适的台湾节点时次选日本，家宽优先。只在聊天中建议，节点和代理组继续由用户自己选择。
4. **当前与默认浏览器：** 当前页面使用国产浏览器或应用内置网页加 8 分。命中时由 Computer Use 改用用户默认浏览器访问 AI 服务和运行本地测试，不限制浏览器品牌。国产浏览器可以正常使用，但不要设为默认浏览器。AI 工具登录或授权时会调用默认浏览器并打开服务网站；服务网站可能读取国产浏览器指纹，增加不必要的风险。

当前会话提供电脑操控时，先完成全部只读准备，再一次说明本轮将修改的时区、系统地区、默认浏览器或浏览器语言，并请求即时授权。用户同意后由代理连续完成本轮结果支持的全部设置，逐项回读，再运行下一轮单次测试；相同设置不重复询问。电脑操控不授权切换 Clash 订阅、代理组或节点，这一项仍给出一个明确建议并等待用户选择。没有电脑操控时先按主入口处理启用；确实无法启用后才给当前平台的最短界面步骤。

## 强制完成闸门

Patch、订阅更新、备份恢复和任何实际修改网络配置的 Diagnostics 在准备收尾前，必须在内部建立当前档位清单。每项只能标记为“通过”“不适用”或“待处理”；“失败”“未验证”“partial”、警告或工具报错都属于“待处理”。存在“待处理”时继续诊断、修复和复测，不能输出完成说明。

共同清单：用途档位已保存且与本轮一致；当前存储位置中的目标订阅已处理；订阅自动更新已关闭；客户端开关符合档位；当前运行配置已经验收；原订阅、代理组、节点和允许保留的 TUN 状态没有被意外改变；没有未完成事务或恢复记录；本轮电脑操控修改均已回读；用户原始要求逐项完成。

- **档位 1：** 共同国内直连补丁、Clash 系统代理、百度、Google、ChatGPT 和速度全部通过。
- **档位 2：** 共同清单和档位 1 的适用站点通过；TUN 开启、Clash 系统代理关闭；百度、Google、ChatGPT 通过；没有误加档位 3 增强。
- **档位 3：** 档位 2 的适用项、完整补丁、ChatGPT/Gemini/Grok 实时分流、DNS 深度测试、WebRTC、本地区域指纹低风险全部通过。中高风险时完成可自动修改的系统和浏览器设置并逐轮复测；节点选择仍需用户决定时只请求这一项。

只有清单全部为“通过”或“不适用”才允许按 [policy-core.md](policy-core.md) 输出简短完成结果。真实阻塞不伪装成完成；只向用户提出当前唯一需要的动作，收到回复后继续同一清单。
