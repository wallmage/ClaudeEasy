# ClaudeEasy 订阅更新与恢复策略

> 读取路由：用户询问订阅是否有更新、明确要求更新订阅、列出或比较备份、恢复配置，或维护备份恢复行为时读取本文件。所有网络任务先读取 [policy-core.md](policy-core.md)；本文件不重复共同边界。

## 检查与更新订阅

### 只检查订阅

用户只问“有没有更新”：从本次已读取的已安装 `SKILL.md` 路径确定 Skill 根目录；以下命令以该目录为工作目录，或把脚本换成绝对路径，不从仓库根目录执行相对路径。直接调用公开入口，不搜索仓库或测试。可读取当前存储的订阅索引，将简称对应到唯一完整显示名；不唯一时只问目标名称。

```bash
# macOS
ruby scripts/macos/patch_profiles.rb --check-subscription-updates --subscription-name "Yue.to Infinite" --json
```

```powershell
# Windows
.\scripts\install_windows.cmd -CheckSubscriptionUpdates -SubscriptionName "Yue.to Infinite" -Json
```

省略名称检查当前存储全部远程订阅；指定名称只读该订阅正文。每项一次下载，30 秒请求超时，正文仅在内存比较；不创建备份、状态或缓存，不刷新、不改档、不做后续网络验收。

macOS 从当前存储读取索引、本地正文和已保存档位；Foundation 按运行中客户端身份下载，将远端按保存档位在内存转换后与本地比较。Windows 读取当前 AppHome 的索引和正文，用现有 .NET 请求及正文比较，不运行全局补丁。比较基准均为本地，不声称还原服务商历史。

依据 `items[].update_available`：true 有变化、false 无变化、null 未确认；pending 只是发现变化，不是已应用。有变化时根据同次返回的 `items[].details` 主动说明具体节点、代理组成员、规则与配置字段变化，按下文“结果说明”简述，明细按需展开。说明检查对象和未修改配置；无变化只报结论，部分失败不能说全部无更新。不为补明细再次下载。

macOS 返回 `client_process_not_visible` 时，立即用 `/bin/ps -ax -o comm=` 做一次只读权限核对，不先搜索源码，也不直接让用户启动客户端。出现实际权限拒绝/XPC 证据，或本会话已确认同一调用受限时，通过宿主审批重试同一完整检查入口一次；不得绕过审批，不申请任意 Ruby 代码的长期权限。进程查询成功且确无客户端时才说明未运行；查询可见但入口仍失败时再追踪相关实现。`client_process_not_unique` 表示多个可见客户端。零可见本身不是沙盒证据。不为检查启动客户端，不先下载验证权限再下载报告。

### 更新入口与意图

用户说“更新订阅”“更新节点”：直接进入更新入口；不得先执行只检查命令，再以“检查了但没有更新”结束。读取已保存档位与当前存储，连续完成备份、更新、补丁、验收、最终复核。已授权流程不再询问是否继续，不临时修改源码或绕过包装器执行。

- macOS 普通更新：`bash scripts/install_macos.sh --safe-update --json`。同次下载在内存比对，只写变化目标；全部相同可报告无需更新。
- macOS 明确要求“重新刷新”“全部重写”“即使相同也写入”：`bash scripts/install_macos.sh --safe-update --force-rewrite --json`。每份远程订阅重新下载、备份、校验、重写并补丁；不以内容相同跳过，不先做远端比较。
- Windows 更新和重新刷新均通过已运行 Clash Verge Rev 的“更新所有订阅”。按下节执行；不使用后台下载写入入口替代客户端刷新。

macOS 下载使用 Foundation，身份动态取自运行中 ClashX Meta；不得用 curl 或固定 User-Agent。严格 UTF-8、YAML、协议、补丁二次一致性与 Mihomo 校验保持有效。当前配置有 AnyTLS 而候选全部失去 AnyTLS、改用 Shadowsocks 时拒绝更新。当前订阅用同一客户端进程的官方更新事件加载；不直接重载内核。原选择不能保留时返回具体失败，不主动写回节点选择。

### Windows 客户端刷新

1. `scripts\install_windows.cmd -SnapshotProfiles -Json`：保存全部远程订阅与运行状态。已有待验收记录先继续本轮，不覆盖备份或重新下载。
2. 确认已运行窗口中的“更新所有订阅”控件，执行 `scripts\install_windows.cmd -BeginSafeUpdateRefresh -Json`，随即由 Computer Use 点击一次；观察每份订阅本轮完成结果。内容相同也必须取得刷新凭据，不能以哈希相同推断已经刷新。
3. 确认本轮客户端刷新完成后执行 `scripts\install_windows.cmd -VerifySafeUpdate -RefreshConfirmed -Json`。只有实际观察到完成，才传 `-RefreshConfirmed`；不是另一次用户确认。
4. 脚本核验全局补丁、订阅正文、运行加载、TUN、原选择与自动更新关闭状态；随后完成当前档位全部验收。

当前会话确实无法操作客户端窗口时，先完成备份与准备，按主入口说明能力限制；用户准备操作时记录开始时间，只请其在已运行 Clash Verge Rev 点击“更新所有订阅”，全部完成后回复“全部订阅已更新”。收到确认继续第 3、4 步，不把点击交接当成任务结束。更新计时超过窗口时按下节恢复，不把迟到确认当成新一轮成功。

### 连续执行与验收

平台结果 `safe_update_completed`、`safe_update_verified`、`subscriptions_updated` 仅表示脚本阶段完成。`workflow_complete: false` 时，立即继续 `required_followups`，不发送最终回复、不再运行一次安装命令重打已经应用的补丁。

内部保留本轮记录：订阅写入结果、备份凭据、已保存档位、每项验收状态、时间、浏览器与证据。新消息和上下文压缩后接着未完成项执行；不反复翻完整日志。只有相关配置改变、浏览器改变、证据失效或用户明确要求重新测试，才重做对应项。

更新前只读取必要状态，不运行网络测试。更新后：

1. macOS 执行 `ruby scripts/macos/patch_profiles.rb --reconcile-client-switches --usage-profile N --json`；Windows 执行当前档位客户端动作。
2. 按 [profiles-and-patch.md](profiles-and-patch.md#patch-验证标准) 完成当前档位验收。开始浏览器验收时确定用户指定浏览器，否则用默认浏览器；独立页面并行推进，按完成状态等待，不连续读取未变化页面。区域指纹只用该节 here.now 入口。
3. 最终核对全部远程订阅、补丁、运行配置、原代理选择、客户端开关、订阅自动更新关闭、无未完成事务。缺项继续处理，全部通过才报告完成。

### 失败处理

失败先读正式入口的订阅名称、原因码与 HTTP 状态；结合事务和运行状态确认是否写入、是否恢复。HTTP 403 等下载失败只检查对应服务商已可访问的订阅状态；服务恢复或原因修复后重试正式入口。原因未变不反复刷新全部订阅，不通过底层入口、临时 monkey patch 或全局命令追踪取代受控流程；日志不得包含订阅 URL 或凭据。

工具不支持、页面故障、自动审批拒绝分别处理。自动审批或 URL 策略拒绝保留原文、目标和范围；不得换工具绕过，也不扩大为未经证实的全局限制。完成不受影响的项目；只有取得新证据、授权或受支持且更安全的方案才重试。同一阻碍不反复巡视窗口、重复要求用户操作；确实无法推进时按主入口简短说明真实限制。

每轮更新最多等待 180 秒：macOS 从安全更新命令开始，Windows 从 `-BeginSafeUpdateRefresh` 开始；包括本轮下载、写入、加载，不限制后续诊断时间。超时按已有事务恢复，恢复不计入窗口。下载、写入、收到加载事件均不是成功；回滚结果不能报告完成。原运行状态未恢复时保留恢复记录，继续安全诊断，不切换节点、不重启 Clash。

### 结果说明

先说完成结果与测试结论，再按订阅简述变化；无变化一行，失败给名称和日常语言原因。新增、删除、改名、连接参数变化按本轮证据说明；同一节点进入多个组只算一个节点。详细节点、组成员和规则明细在用户要求时展开，不默认输出长清单。用户明确不要比较时，直接报告重写、补丁和测试结果。

只用本轮候选、备份和实际状态；区分远端变化与工具补丁，不为补报告重新下载。不输出订阅 URL、服务器、端口或凭据，不把机器状态名和排查过程当解释。

Windows 完整配置流程第一次修改前，先运行 `-BackupSubscriptions -Json` 保存当前存储位置全部远程订阅正文；安装器随后保存全局脚本、索引、应用设置及既有档位和所有权状态；卸载删除内部状态前同样备份。不能凭当前文件缺失推断历史状态不存在。任一备份失败就不开始修改。恢复某个历史时点时必须核对这组正文与设置，而非只恢复全局脚本或卸载到首次安装前。保留最初恢复点，后续试验的备份不能取代它。缺失原订阅正文时明确记录无法完整还原；文件哈希一致和热加载成功不能代替原始症状、DNS 与 WebRTC 的当前档位复测。

配置历史用于诊断与回滚：macOS 下列备份参数都由 `ruby scripts/macos/patch_profiles.rb` 执行，不能传给 `install_macos.sh`。当用户说某次改动后变慢或断网，先用 `--list-backups` 列出备份，按 `created_at` 选择症状出现前最近的一份作为候选，再用 `--compare-backup ID` 把当前配置与候选做配置差异比较；两端公开的备份 ID 统一为不含真实文件名的 `ce-backup-v1-<64 位十六进制>`，旧原始编号只作为兼容输入，不能再次输出。JSON 列表在 `items` 返回含 `id` 与 RFC 3339 `created_at` 的对象；JSON 比较在 `items` 返回 ID、是否相同、备份 SHA-256 与恢复所需的当前 SHA-256，使列出、比较、恢复可以直接衔接。时间接近只能帮助选备份，不能仅凭时间接近就判定某项变化造成故障。不得自动删除历史备份。macOS 恢复使用 `--restore-backup ID --expected-current-sha256 SHA256`；Windows 使用 `-ListBackups`、`-CompareBackup ID`、`-RestoreBackup ID -ExpectedCurrentSha256 SHA256`。恢复前验证备份 YAML 与 Mihomo、核对目标文件和预期 SHA-256，并为当前版本再建备份；恢复后复测原始症状，恢复或运行检查失败时恢复回滚前版本。macOS 备份恢复、Patch 与订阅更新前备份共用操作锁，并在读取备份和写配置前先恢复未完成的批量事务；事务恢复改变当前字节时，本次请求按预期哈希冲突停止，必须重新比较。备份事务把提交后的真实路径和文件身份交给运行加载与失败回退；外部以相同字节替换目标也不得覆盖。macOS 恢复当前订阅后通过 Mihomo 本地控制器重新加载；保持恢复前的 TUN 开关与目标仍保留的代理组选择，并完成缓存、DNS 和连接检查，失败时恢复回滚前版本。文件恢复但运行内核未恢复时，只在内部记录并继续完成加载与验收；确实需要用户动作时按 `SKILL.md` 只说明一个步骤。恢复非当前订阅时不得切换当前订阅。
