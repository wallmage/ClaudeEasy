# ClaudeEasy 安全更新与恢复策略

> 读取路由：用户明确要求安全更新、列出或比较备份、恢复配置，或维护事务恢复行为时读取本文件。所有任务先读取 [policy-core.md](policy-core.md)；本文件不重复共同边界。

## 完整任务顺序与完成条件

平台命令返回 `safe_update_completed` 或 `safe_update_verified`，只表示全部订阅的更新事务、补丁和平台内部运行检查已经完成，不代表用户要求的安全更新任务已经完成。机器结果出现 `workflow_complete: false` 时，必须继续完成 `required_followups`；不得把中间回执当成最终说明。

安全更新必须按以下顺序连续执行，不需要用户逐项提醒：

1. 读取已保存档位。档位 3 在任何更新写入前，先用实际用于 Claude 的同一浏览器取得更新前区域指纹基线；档位 1、2 直接进入下一项。
2. 执行本文件规定的全部订阅更新事务，并重新应用已保存档位的补丁和内部运行检查。
3. 完成当前档位在 `profiles-and-patch.md` 规定的全部验收。档位 3 固定依次完成分流验证、DNS 深度测试、WebRTC 测试 1、WebRTC 测试 2；测试结果不完整、超时或波动时继续重试并按对应策略查明，不得提前结束。
4. 档位 3 在同一浏览器完成更新后区域指纹重扫，并与更新前基线比较；不得跨浏览器拼接结果。
5. 做最终状态复核：逐份订阅的本轮刷新与生效状态、已保存档位、补丁、代理组选择、客户端开关、订阅自动更新关闭状态和所有未完成事务都必须重新读取确认。

如果执行更新后才发现缺少更新前区域指纹基线，自动把当前状态作为新的更新前基线，并重新执行整套安全更新和全部后续检查；这不需要用户决定。任何已知但尚未执行的检查都必须立即继续，不得因为仍有工作未做而停止。只有剩余步骤确实需要用户选择、授权或现场操作，且没有安全替代路径时才可停下；停下前仍要完成所有互不依赖的步骤并明确唯一缺口。

只有全部远程订阅和当前档位要求的每一项都有本轮新证据，且最终状态复核通过，才可输出完成说明。失败、无法完成或仍需重试的项目必须明确报告实际状态，不能宣称完整完成。

## 订阅补丁与安全更新

项目不得安装永久监听、后台守护、LaunchAgent、`WatchPaths` 或计划任务来盯订阅变化。三个档位都会关闭订阅自动更新，因此平时没有订阅变化，也不需要轮询。

用户说“更新节点”“更新订阅”或同义表达时，触发一次安全更新。这里的“节点”按用户意图理解为全部远程订阅，不是切换或只刷新当前节点：

用户已经说明服务商订阅开关已打开或倒计时仍有效时，立即执行安全更新。不得检查或操作服务商后台，不得用 Chrome、Browser 或 Computer Use 登录控制面板、检查开关或验证倒计时。先做一次正常更新，不得在更新前推测开关状态。有多份订阅时，必须尝试每份候选，并逐一报告哪些订阅下载与校验成功、哪些失败；整批原子事务中，只要一份失败，其余成功候选也不得写入，报告必须注明“下载与校验成功但未写入”。

只有更新确实失败且没有明确的本机故障时，才提示订阅开关这一可能性。固定提醒为：“服务商可能设置了订阅开关。请登录服务商网站，在控制面板找到订阅开关并打开；开关关闭时无法更新。打开后请立即重试安全更新。”不得声称已经检查服务商后台或确认开关关闭。

1. 读取已保存档位、当前存储位置和客户端记录的全部远程订阅；不输出地址。清单缺失、重复或无法一一对应配置文件时停止。
2. 每次写入前为全部当前配置创建带日期时间的私有备份。第一次运行另存初始快照；不得自动删除历史备份。
3. macOS 在内存中下载全部远程订阅，地址只经标准输入交给 `curl`，不得放进进程参数、日志或错误提示。每次请求都禁用用户 curl 配置并清除环境代理，显式使用控制器 `/configs` 报告的当前 Mihomo 回环监听；监听缺失、无效或不可用时停止，不能回退到环境代理或默认直连。每份响应最多 32 MiB，只接受 HTTPS 成功响应和有效 UTF-8 YAML。
4. 三个档位都对每份候选重新应用共同国内域名直连基线；档位 3 再应用完整补丁，档位 1、2 不得增加第三档字段。全部候选都要经过 YAML 重读、二次转换一致性检查和受支持 Mihomo 校验。
5. 只有全部候选合格且当前文件哈希仍与读取时一致，才在锁内统一替换。任何一份下载、转换、校验、并发检查或写入失败时都尝试恢复全部目标；恢复所有目标后才可写“全部保持原样”。恢复本身失败时继续处理其余目标，并逐份报告未恢复项。
6. 更新后只通过本地控制器刷新当前订阅，保留目标配置中仍存在的代理组选择，清理 Fake-IP 与 DNS 缓存并执行当前档位验收。旧自有分组被候选删除时不再要求它继续存在；候选仍保留的用户 Selector 丢失或改选仍必须失败。运行检查失败时整批回滚；回滚前也要备份当前版本，恢复目标必须匹配预期 SHA-256、真实路径和提交文件身份。运行回退已经恢复当前订阅文件时，整批回退必须把它视为已恢复，继续恢复其他订阅，并报告运行内核仍未恢复；不能再次回退同一文件并误报文件恢复失败。事务在写入前记录真实路径、原 inode、原字节和完整候选；macOS 订阅配置的逻辑路径本身不能是符号链接，发布前还必须同时确认逻辑路径与真实路径都在同一个规范配置根目录内。v2 事务中，目标已为完整原字节时只确认，只有同一原 inode 上的完整候选才自动恢复；空文件以及原字节或候选的任何截断前缀都无法判断来源，必须原样保留目标与事务并返回待恢复。不同 inode、重指后的符号链接目标都是客户端或外部流程发布的新文件，即使字节相同也必须保留；文件事务可以结束，只有运行内核仍需恢复时才保留记录和待恢复状态。没有文件身份的旧版事务只在目标已是原字节时结束，否则停止并保留，不能按候选摘要覆盖。若进程在当前订阅加载候选后被强制结束，下一次安全更新先按事务恢复原文件，再通过本地控制器重新加载恢复后的当前订阅、清缓存并验收；运行内核无法恢复时在下载前返回待恢复状态，不能让磁盘与运行内核继续分叉。
7. Windows 运行 `-SnapshotProfiles`，从 `profiles.yaml` 核对每个远程 uid 与本地文件一一对应。读取索引后持续持有索引及全部远程订阅的只读版本锁，先确认当前每份订阅都有非空代理组并通过 YAML、Mihomo，再从锁内同一版本建立脱敏清单和备份、记录客户端的 `updated` 时间戳，最后发布清单才释放锁；客户端写出的 `updated: null` 是合法的空时间戳。Clash Verge Rev 先写订阅文件、后保存索引的更新若已写出订阅但尚未保存索引，订阅必须先通过基线校验；索引写入在版本锁期间失败，只有清单发布后重试成功才能成为本轮时间戳凭据。中间文件不通过校验时不得创建更新前备份或清单。存在尚未验收的清单时必须先完成 `-VerifySafeUpdate`，不能覆盖。再通过 Clash Verge Rev 界面的“全部更新”触发，没有该入口时逐份处理清单中的每一份。之后运行 `-VerifySafeUpdate`，每份订阅必须以文件 SHA-256 变化或比快照更新的 `updated` 时间戳证明本轮已刷新；内容不变但时间戳更新可以通过，两者都不变时保留清单和订阅并返回 `safe_update_refresh_pending`。有刷新凭据后再确认已安装的受管 `Script.js` 与当前安装包及保存档位一致，逐份确认顶层 `proxy-groups` 是至少含一个条目的块状或行内列表，然后做 YAML 与 Mihomo 检查并确认当前档位仍关闭自动更新；缺少代理组或列表为空时不能判成功。通过 Mihomo 校验的非空代理组只会使用当前引擎支持的合法类型，而引擎必须为全部合法类型以及只有 AI 分组的配置选出代理组主目标，不能静默返回原配置。这里不重新实现 YAML 解析器，也不声称在 PowerShell 中执行了用户原脚本或全局脚本；合法性继续由 Mihomo 判断。`profiles.yaml` 映射未变但订阅文件缺失时，必须从清单绑定且哈希匹配的备份原子重建，并与清单删除一起提交；同一路径重新出现时视为并发变化，不得覆盖并保留清单。只有订阅内容缺失或检查失败，且索引与受管脚本仍与检查开始时一致，才允许在持续锁住这两个控制文件时整批恢复；索引、脚本或其他验收状态并发变化时必须返回 `safe_update_verification_retry_pending`，保留当前订阅和清单。订阅本身并发变化时也不得覆盖新内容。旧版 v1 清单可凭内容变化验收，且不再依赖不会用于自动恢复的旧备份；内容没变但当前订阅完整通过检查时，删除旧清单并返回 `safe_update_legacy_snapshot_required`，允许下一次建立 v2 快照。验收失败时不能自动恢复来源无法确认的旧备份，必须返回 `safe_update_legacy_recovery_pending` 并保留当前订阅和清单。只有 v2 一致快照的全部恢复成功后才作废清单。文件恢复不等于运行内核已经恢复，必须把运行状态写成“未验证”并重新读取实时配置与分流；不得把只更新当前一份、只完成界面点击或只恢复文件报告成完成。
8. 三个档位都会关闭订阅自动更新。网络正常时不主动建议频繁更新；连接异常、服务商通知订阅变化，或距离上次更新已数月时，引导用户说：“请帮我安全更新全部订阅”。本次只执行一次获取和更新，不长期重新开启周期自动更新；按已保存档位重新应用补丁并通过验收后，再次确认自动更新关闭。任何一份失败时必须按上述事务恢复，只有确认成功恢复后才说“全部保持原样”。

macOS 安全更新恢复未完成事务时，活动配置必须从当前存储目录的全部顶层配置识别，不能只搜索远程订阅目标；因此活动 `config.yaml` 也必须真正重新加载。旧事务和本次更新回滚都只有在原字节恢复、原配置重新加载、缓存清理和运行检查全部成功后才可删除；运行恢复失败时保留同一记录，下一次 Patch 或安全更新继续处理，且在完成前不得下载或写入新候选。

配置历史用于诊断与回滚：当用户说某次改动后变慢或断网，先列出备份，按 `created_at` 选择症状出现前最近的一份作为候选，再把当前配置与候选做配置差异比较；两端公开的备份 ID 统一为不含真实文件名的 `ce-backup-v1-<64 位十六进制>`，旧原始编号只作为兼容输入，不能再次输出。JSON 列表在 `items` 返回含 `id` 与 RFC 3339 `created_at` 的对象；JSON 比较在 `items` 返回 ID、是否相同、备份 SHA-256 与恢复所需的当前 SHA-256，使列出、比较、恢复可以直接衔接。只输出字段路径与哈希；不返回配置文件名，provider 等动态映射名用固定占位符表示，不输出配置值。时间接近只能帮助选备份，不能仅凭时间接近就判定某项变化造成故障。macOS 使用 `--list-backups`、`--compare-backup ID`、`--restore-backup ID --expected-current-sha256 SHA256`；Windows 使用 `-ListBackups`、`-CompareBackup ID`、`-RestoreBackup ID -ExpectedCurrentSha256 SHA256`。恢复前验证备份 YAML 与 Mihomo、核对目标文件和预期 SHA-256，并为当前版本再建备份；恢复后复测原始症状，恢复或运行检查失败时恢复回滚前版本。macOS 备份恢复与 Patch、安全更新共用操作锁，并在读取备份和写配置前先恢复未完成的批量事务；事务恢复改变当前字节时，本次请求按预期哈希冲突停止，必须重新比较。备份事务把提交后的真实路径和文件身份交给运行加载与失败回退；外部以相同字节替换目标也不得覆盖。macOS 恢复当前订阅后必须通过本地控制器重新加载，保持恢复前的 TUN 开关与目标仍保留的代理组选择，并完成缓存、DNS 和连接检查；失败时恢复回滚前版本。文件恢复但运行内核未恢复时必须单独报告；恢复非当前订阅时不得切换当前订阅。Windows 客户端运行时不得为了恢复而停止客户端，只能完成比较并报告当前无法安全自动恢复。
