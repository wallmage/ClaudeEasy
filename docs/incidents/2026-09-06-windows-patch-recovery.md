结论：补丁超时与恢复流程缺口叠加；操作代理还误触发了订阅更新。不能把这些失败归咎于朋友反复点错。

## 已确认代码问题与修复

1. **全局脚本超过执行上限。** 主组检测解析全部规则后才找 MATCH；普通规则反复逐字符解析、反复规范化；相同 DNS 目标反复检查整组节点。改为短路查找、普通规则直接拆分、复用预计算值，以及仅在单次 DNS 阶段缓存相同解析器的安全结果。保留双遍一致性检查与用户规则语义。
2. **控制器尚未就绪就失败。** 恢复选择与清理 DNS 缓存原在等待循环外；现纳入有界等待。运行文件被客户端短暂占用时只重试共享/锁冲突；打开失败时释放已取得的目录句柄。
3. **回滚只还原文件。** 现先确认文件恢复，再核对客户端身份，最多发送一次独立恢复加载；等待原运行配置、TUN、选择和缓存处理通过。有文件冲突则不加载；不能验证则保留未完成状态。
4. **客户端正常变化阻止升级和卸载。** 仅对已证明的 DNS 列表缩进、已保存档位 3 的系统代理关闭和控制器开启做反向哈希核验。其他变化仍拒绝；已接受的开关值保留到卸载基线。新生成的 DNS 列表使用客户端的同级缩进。
5. **同档位升级被误拒绝。** 原检查把“旧运行配置已有同档位规则”当作失败。现要求旧 v2 所有权哈希吻合后允许升级，仍检查重新生成和完整运行状态；首次安装保留防误判检查。

6. **内部状态未留历史备份，恢复时误删旧档位。** 主 session 第 112 行已读到档位 3，第 535 行卸载明确删除档位与自动更新所有权状态；最终却将它们视为当天新增。安装覆盖和卸载删除这些状态前现均备份，恢复不得猜测原状态不存在。

## 操作流程修复

- 重载入口必须按控件文字确认，区分“重新激活订阅”与“更新所有订阅”。绿色激活提示不能替代脚本控制台和运行检查。
- 出现超时先保护旧配置；未经相同 Boa 引擎、完整组合脚本和同规模输入验证，不继续要求用户激活候选。
- 完整配置第一次修改前备份所有远程订阅正文；后续备份不能替代最初恢复点。历史恢复同时核对订阅正文、索引、脚本、设置和原始症状。

这些 Windows 特有修复不改变 macOS 补丁行为；两端仍共享规则输出样本。

## 复现与验证边界

采用 172 个代理、31 个组、3476 条规则、250 项 DNS policy 的无真实账号模拟配置。原版完整组合脚本在 Boa 0.21.1 中约 5.19 秒，修复后约 0.30 秒；序列化输出逐字相同。新回归测试对旧版本实测报 `ETIMEDOUT`，修复版通过。此耗时是开发机测量，不能作为所有 Windows 机器的速度保证。

[Clash Verge Rev 2.5.2 脚本执行器](https://github.com/clash-verge-rev/clash-verge-rev/blob/v2.5.2/src-tauri/src/enhance/script.rs)使用 Boa 和 5 秒上限；[同版界面实现](https://github.com/clash-verge-rev/clash-verge-rev/blob/v2.5.2/src/pages/profiles.tsx)分别提供更新全部和重新激活入口。

403 属于订阅服务拒绝请求，本次没有证据证明是 ClaudeEasy 生成配置造成。脱敏包不足以确定 MESL 当前 DNS 红色的具体解析器、浏览器设置或出口；也不能从本机补回朋友缺失的历史订阅正文。仓库修复与朋友电脑已恢复是两件不同的事，不能混报。
