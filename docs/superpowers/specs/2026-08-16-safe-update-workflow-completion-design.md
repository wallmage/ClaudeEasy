# 安全更新完整流程设计

## 目标

用户要求更新全部订阅后，ClaudeEasy 自动完成当前用途档位规定的全部流程。订阅事务成功只是中间结果；没有完成修改前基线、档位验收和最终状态核对时，不得结束任务或宣称完整完成。

## 当前问题

macOS 安全更新命令在订阅下载、档位补丁、配置校验和内部运行检查成功后返回 `safe_update_completed`。这个名字没有说明浏览器与真实分流检查仍在命令范围之外。Skill 的更新完成条件和档位 3 验收分散在不同文件，机器结果也没有表示整套流程尚未完成，代理容易把命令成功误当成用户任务完成。

## 设计

保留 `safe_update_completed` 与 `safe_update_verified`，避免破坏已有调用方；给结果合同增加三个向后兼容的可选字段：

- `workflow_complete: boolean`：结果是否已经覆盖整个用户任务。
- `completed_scope: string`：本次命令实际完成的范围。
- `required_followups: string[]`：仍需完成的稳定机器标识。

macOS `--safe-update` 和 Windows `-VerifySafeUpdate` 成功时都返回 `workflow_complete: false`。它们只证明订阅事务、档位补丁和平台内部检查成功，不能证明浏览器与完整档位验收已经完成。

`safe-update-and-recovery.md` 统一规定安全更新的完整顺序。`SKILL.md` 只保留不可误解的入口规则：脚本成功是检查点，不是任务终点；缺项且无需用户决定时必须继续。档位的具体检查内容仍由 `profiles-and-patch.md` 负责，不在入口文件复制。

## 档位 3 顺序

1. 读取档位、存储位置和全部远程订阅。
2. 在任何更新前完成区域指纹基线。
3. 执行平台安全更新并确认全部订阅、补丁、内部检查和自动更新关闭。
4. 完成 Google、OpenAI、Anthropic、Claude 真实分流检查。
5. 完成 DNS 深度测试和两项 WebRTC 测试。
6. 完成同一浏览器的修改后区域指纹扫描。
7. 再次核对自动更新关闭、订阅与代理选择未变、没有遗留事务。
8. 全部结果完整后才报告任务完成。

如果修改前基线漏做，立即把当前状态作为新基线并重新执行一次完整安全更新；不要求用户决定。如果测试未完成、超时或结果波动，按对应策略自动重试或继续诊断，不以单次有利结果结束。

## 测试

- 结果合同测试覆盖三个可选字段的类型、脱敏和子结果合并。
- macOS wrapper 测试要求安全更新成功仍返回 `workflow_complete: false` 和完整后续清单。
- Windows 测试要求安全更新验收成功仍返回同样语义。
- Skill 合同测试锁定完整顺序、自动继续、遗漏基线后的自动重做和最终报告禁令。
- README 与测试范围只同步用户可见摘要和实际覆盖，不复制策略细节。
