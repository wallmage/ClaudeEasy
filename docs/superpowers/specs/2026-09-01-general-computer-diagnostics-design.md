# ClaudeEasy 通用电脑诊断设计

## 结论

ClaudeEasy 将从网络配置与诊断 Skill，逐步发展为面向 macOS 与 Windows 的通用电脑诊断和修复 Skill。

第一阶段保留两套互不干涉的流程：明显的网络问题继续使用现有网络流程；其他电脑问题使用新的通用判断流程。新流程成熟并经过实际效果验证前，不迁移、不改写现有网络能力。

## 产品目标

ClaudeEasy 必须让 Codex 相比未安装 Skill 时：

- 更高概率解决用户原始问题；
- 更少要求用户提供信息或手动操作；
- 更快定位真正原因，减少无关检查和试错；
- 自动完成安全的检查、修复、复测和失败恢复；
- 在证据不足时准确保留未知，不用猜测换取表面上的完成。

用户只需要描述问题。代理自行使用当前会话实际提供的 shell、Computer Use、日志、应用界面和官方资料完成后续工作。密码、验证码、MFA、实体操作、系统强制授权，以及可能丢失数据或无法安全恢复的动作，才允许打断用户。

## 非目标

第一阶段不做以下事情：

- 不把电脑问题拆成预设故障类别、支持清单或优先方向；
- 不建立启动即采集所有系统状态的“全面体检”；
- 不为尚未出现的需求创建通用采集框架或永久后台监控；
- 不因为新增通用流程而修改现有网络策略、脚本、档位或完成标准；
- 不在第一阶段让新流程处理生产环境中的网络问题；
- 不承诺所有问题都能自动修复，但所有电脑问题都必须能够进入同一通用流程并得到可靠推进。

## 第一阶段架构

### 一个入口，两套流程

`claude-easy/SKILL.md` 是唯一入口。代理先在内部完成一次分流，不向用户提问：

1. 用户明确描述连接、网站或网络服务无法访问、网络速度、DNS、代理、分流、泄漏、Clash、订阅、节点、TUN 或系统代理问题时，进入现有网络流程。
2. 其他所有电脑问题进入新的通用流程。
3. 无法从用户描述确定时，默认进入通用流程。
4. 通用流程取得证据后确认问题属于网络时，停止通用流程的写入，携带已经取得的事实转入现有网络流程；通用流程不得自行修改网络配置。

分流只服务于第一阶段的风险隔离。它不是长期的故障分类体系。

### 隔离边界

- 现有网络策略文件、脚本、机器合同和用途档位保持不变。
- 新通用流程使用独立的策略文件，不读取或套用网络用途档位、Patch、订阅、DNS、WebRTC 或 Mihomo 完成闸门。
- 两条流程可以共享用户沟通、连续执行、真实阻塞和保守写入原则，但每条具体规则只能有一个权威来源。
- `SKILL.md` 只保存分流、共同边界、网络紧急边界和策略读取路由；通用判断细节进入新的通用策略文件。

## 通用判断流程

通用流程固定判断方法，不固定检查对象和执行顺序。

### 1. 锁定原始问题

从用户原话和当前电脑中确定：用户想恢复的行为、实际异常、发生时间、影响范围和成功表现。能从界面、系统状态或日志取得的信息自行读取，不反问用户。

用户说“电脑很卡”时，原始问题不是“CPU 是否过高”，而是用户当时的具体操作没有按预期完成。任何指标只有能够解释这个行为时才有价值。

### 2. 优先观察原场景

症状可以安全复现时，优先使用用户实际应用、实际动作和实际界面观察一次。Computer Use 可用时由代理操作并回读可见结果；结构化接口更可靠时直接使用接口。不能为了复现提交支付、发送消息、重复登录、覆盖文件或增加账号风险。

历史问题已经消失时，先读取对应时间窗的原始记录；当前状态不能替代历史现场。

### 3. 形成有依据的候选解释

只保留能够同时解释已知症状、时间、影响范围和健康对照的解释。常见、听起来合理或技术上可能存在，都不足以进入当前判断。

每个候选解释必须同时具备：

- 已有支持证据；
- 当前反证或尚未解释的现象；
- 一项能够明显改变判断的下一步验证；
- 该验证不同结果分别会导致什么行动。

没有必要强行凑固定数量。直接证据已经定位问题时可以只有一个；证据不足时也不能扩张成无边界的可能性列表。

### 4. 选择最有区分力的下一步

每次只选择一项检查或一组不可分割的同源读取。选择标准依次为：

1. 能否区分当前仍成立的解释；
2. 能否决定下一步行动；
3. 能否覆盖更多已知现象；
4. 所需时间、权限、隐私范围和副作用是否最低；
5. 是否需要用户介入。

如果一项检查无论得到什么结果都不会改变下一步，就不执行。不得因为工具容易调用、数据容易取得或结果显得专业而采集。

### 5. 更新判断而不是累积检查

每得到一项证据，立即确认、降低、排除或撤回对应解释，再重新选择下一步。不能保留已经被反证的故事继续指导操作。

连续两项检查都没有缩小范围时，执行诊断重置：回到原始问题，列出现有事实、已排除内容和唯一关键缺口。没有新的区分性证据前，不进行第三次试改。

### 6. 到达足够证据后停止

直接记录已经指出故障来源和机制时，可以停止继续检查。没有直接记录时，至少需要彼此独立、能够解释原场景的证据，并主动检查关键反例。

诊断目标是取得足以选择安全修复的证据，不是追求完整描述电脑的全部状态。

### 7. 最小修复

修复必须针对已经确认的问题：

- 一次只改变一个原因相关的对象；
- 修改前保存必要原状态和恢复方法；
- 低风险、可恢复且属于用户请求的修复自动执行；
- 可能丢失未保存工作、删除数据、退出应用、注销、重启、重装、降级或改变安全与隐私边界时，才向用户说明具体风险并取得授权；
- 修复失败或出现副作用时立即恢复，不叠加新的试改。

### 8. 原场景复测

使用相同应用、账号、目标和动作验证原始问题，并检查本次修改可能影响的健康行为。指标恢复但原场景仍失败，不算解决。

最终内部状态只能是：`resolved`、`mitigated`、`observing`、`blocked` 或 `unresolved`。只有原场景通过且必要回归正常时才能使用 `resolved`。

## 工具与证据策略

第一阶段不开发全量状态采集器。代理按当前判断选择现有能力：

- Computer Use 用于观察和操作用户实际使用的正常应用窗口；
- shell 和系统接口用于回答一个明确问题；
- 日志只读取相关时间窗、进程、应用和字段；
- 文件搜索只覆盖与当前问题有直接关系的位置；
- 网络查询只在本机证据已经把问题指向具体产品、系统版本或外部服务时使用，并优先官方或第一方资料；
- 间歇性问题只有在现有历史不足时建立有范围、有停止条件的观察窗口，不永久运行。

只有真实案例证明原生工具无法稳定取得某项必要证据，或同一安全操作在两端反复出现实现差异时，才新增一个小型专用脚本。脚本必须回答一个明确问题，输出结构化结果，并在 macOS 与 Windows 分别定义等价能力或如实声明平台差异。

## 平台策略

macOS 与 Windows 使用相同的通用判断流程和完成标准，但各自拥有独立的平台策略文件。平台文件只规定当前系统如何可靠取得证据、如何执行安全操作，以及权限或工具缺失时如何继续；不得复制通用判断规则，也不得列出每次都要运行的命令清单。

Computer Use 是否可用以当前会话工具为准。没有实际可调用能力时不能假装已经观察或操作界面；仍可通过系统接口推进的部分必须继续完成。

## 持续优化

通用流程通过已经确认的真实案例缩短后续路径。每个可复用经验只保存：

- 能够识别适用范围的现场特征；
- 最快产生决定性信息的验证；
- 已确认的原因和修复；
- 恢复方法；
- 原场景与副作用复测结果；
- 已知反例。

一次相关性、一次自然恢复或没有复测的修改不得成为固定规则。新经验先作为案例证据；只有能够重复识别并稳定改善结果时，才进入产品策略。产品不会自动修改自身，也不上传用户日志或建立后台遥测。

## 效果评估

新流程与未安装 Skill 的 Codex 在相同模型、工具、权限、初始状态和用户描述下比较：

- 原始问题解决率；
- 原因判断正确率；
- 首次取得有效区分证据的时间；
- 总解决时间；
- 无关检查数量；
- 用户被询问或要求操作的次数；
- 无效修改、错误修改和恢复失败数量；
- 错误宣布“已解决”的次数。

单次案例只用于改进该案例，不足以证明总体优势。迁移网络流程必须依赖覆盖现有网络能力和失败边界的多次真实或可重复案例，不能只按运行时间决定。

## 演进阶段

### 初期：并行

- 网络问题使用现有网络流程。
- 其他问题使用通用流程。
- 通用流程可以用历史网络案例离线评估，但不接管生产网络任务。

### 中期：网络能力降级准备

当通用流程在网络案例中的成功率、安全性、用户介入和解决时间均不低于旧流程，并且现有网络配置、更新、恢复、泄漏防护和跨平台验收全部可以由通用流程表达时，网络从独立主流程转为待迁移领域能力。

迁移逐项进行；未通过对照验收的能力继续走旧流程。

### 后期：统一

所有电脑问题进入通用流程。网络只作为通用判断引擎按需调用的证据、策略和修复能力，不再拥有独立入口。旧网络流程只有在全部能力迁移并通过验收后才删除。

## 第一阶段文件边界

- `claude-easy/SKILL.md`：共同原则、顶层分流、两条流程的读取路由和不可突破边界。
- `claude-easy/references/general-diagnostics.md`：通用判断流程、证据选择、自动修复、复测、学习和内部状态的唯一权威来源。
- `claude-easy/references/general-macos.md`：macOS 取证、Computer Use、权限和安全操作边界。
- `claude-easy/references/general-windows.md`：Windows 取证、Computer Use、权限和安全操作边界。
- 现有七个网络策略文件、`policy.json`、`result-contract.json` 和全部网络脚本：保持原职责和现行行为。
- `README.md`：只解释用户可见的双入口行为和通用能力。
- `claude-easy/agents/openai.yaml`：把 Skill 的可发现范围扩展到全部电脑诊断与修复。
- `AGENTS.md`：记录新文件的规则归属和第一阶段隔离边界。

第一阶段不新增通用诊断脚本、机器结果合同、后台服务或故障类别文件。真实失败证明需要后，再按最小范围增加。

## 第一阶段完成标准

- 明显网络任务仍读取并执行原有网络流程，网络策略和脚本没有行为变化。
- 其他电脑问题进入通用流程，不读取或执行网络用途档位、Patch 或完成闸门。
- 分流不要求用户选择故障类型；模糊问题默认进入通用流程。
- 通用流程的每项检查都能说明它区分什么，以及结果如何改变下一步。
- 通用流程不会启动全量采集、永久监测或无关文件扫描。
- macOS 与 Windows 的自动化、权限、恢复和完成条件一致，平台实现差异分别说明。
- README、Skill、策略文件和安装副本描述同一现行行为。
- 现有自动化测试全部通过；没有为了锁定文案或文件布局而增加 prose test。
