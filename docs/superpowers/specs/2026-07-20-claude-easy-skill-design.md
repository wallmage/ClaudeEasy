# ClaudeEasy Skill Design

**首次确定：** 2026-07-20
**当前版本：** 2026-07-29

本文档固定记录产品需求和架构。详细配置规则保存在 `claude-easy/references/patch-policy.md`，开发流程保存在 `AGENTS.md`。

## 产品目标

ClaudeEasy 面向不懂网络配置的用户，包含两个模块：

- **Patch** 首次运行时询问并保存用户用途，只应用该用途需要的最少设置；完整 DNS、AI 分流和 UDP/WebRTC 防护只属于第三档。
- **Diagnostics** 接受用户模糊的网络故障描述，主动复现、取证、分析、解释、修复并复测，不要求用户先判断问题类型或指出日志位置。

用途档位同时约束 Patch 和 Diagnostics，是用户长期保存的网络需求，不是一次性安装参数。

失败时必须保留原配置并给出中文说明。真实案例只用于检验工作流，不作为固定问题、固定工具或固定答案写进产品。

产品不支持旧版 ClashX、旧版 Clash Verge 或 Linux，不包含 Apple、iCloud、Speedtest 等个人规则。

## 核心要求

- 不得运行 ClashX Meta 主程序做诊断、审查、测试、版本查询或只读探测；禁止直接执行应用包主程序、传入 `--version`、用 `open`/LaunchServices 打开应用，或通过 Computer Use 启动未运行的客户端。客户端版本读取 `Info.plist`，实时状态读取进程、日志、偏好或本地控制器，内核版本检查 Mihomo；客户端未运行时保持未运行。

- 绝不退出、停止或重启 Clash。
- 只有用户选择的档位明确要求时，才通过客户端界面切换 TUN 或 Clash 自己的系统代理；AdGuard for Mac 只允许按下述已知兼容路径在自己的界面中切换模式，不改写第三方 PAC，也不切换订阅、代理组或节点。
- 只处理客户端当前存储位置，不扫描旧容器、备份或废弃订阅。
- 保留 ClashX Meta 的默认 `config.yaml`；当前未选中它时安静跳过。
- 已有 AI 分组只补规则并保留原有成员；没有时创建包含全部真实节点和代理提供者的独立 AI 选择器。
- 主代理组支持 Mihomo 的 `select`、`url-test`、`fallback` 和 `load-balance`；显式成员与 `include-all` 系列来源按 Mihomo 过滤语义识别，危险组名通过受管选择器安全引用；优先与 AI 节点独立选择，让普通流量可走便宜节点、AI 流量可单独走家宽。订阅只有 AI 分组时允许共用，不能跳过补丁；不创建安全代理分组，也不自动替用户选择节点。
- 三个档位用同一受管 `cn.mrs` 规则提供器同时驱动 `nameserver-policy` 与 `RULE-SET,...,DIRECT`，覆盖当前存储位置中的全部订阅；档位 3 另让普通国外域名使用带原主代理组标签的 IP DoH、AI 域名使用带 AI 分组标签的 IP DoH。DNS 静态安全判断不执行订阅提供的 `exclude-filter`；引用带非空过滤器或动态成员代理组的解析器改用受管 DoH。保留节点启动解析。受管缓存路径按 Mihomo HomeDir 所在文件系统的大小写与 Unicode 等价规则避让用户路径别名。
- 所有 UDP 先经过 AI 分组，节点不支持时拒绝兜底。HTTP/3/QUIC 因此不会直连；国内网页的 TCP 和 DNS 仍按域名直连。这是共享浏览器中避免 WebRTC 直连所需的取舍，不能把浏览器白屏自动归因于 QUIC。
- 不做按应用隔离：浏览器同时承载国内和 AI 网站，STUN 连接也不携带原网页域名，Mihomo 无法判断它来自哪个标签页。TCP 和 DNS 按域名分流，WebRTC 防护覆盖全局 UDP。
- 修改前备份，候选必须可解析、可通过 Mihomo 校验且二次转换一致。
- 不输出订阅地址、认证信息、控制器密钥或完整节点地址。

## 三档 Patch 架构

第一次在一台电脑上进入 Patch 时，必须问“你使用网络代理主要用于哪些用途？”，解释三个档位后保存数字选择。macOS 的 `usage-profile.plist` 固定属于 ClaudeEasy 状态目录，公开安装和卸载不接受外部路径覆盖；Windows 使用 `claude-easy-usage-profile.json`。用户可以修改；升档补充能力。从第三档降到第一、二档时先运行安全卸载，再保存新档位；只撤销能证明由本工具拥有且未被继续修改的设置，不能覆盖后来的用户改动，无法可靠恢复的旧订阅增强必须明确报告。

安全卸载成功后清除旧用途档位，失败时保留；这样档位 3 才能按“先卸载、再保存新档位”完成降档，同时不能绕过未完成的恢复。

1. **档位 1｜普通浏览**：给当前存储位置中的全部订阅安装共同国内域名直连基线，关闭订阅自动更新，并确认 Clash 的“设置为系统代理”已开启；不修改 TUN、IPv6、WebRTC、AI 分组或节点。用国内站、Google、Twitter 和用户常用站点验收。
2. **档位 2｜海外 AI**：继承共同国内域名直连基线并保持订阅自动更新关闭；用于 ChatGPT、Codex、Gemini、Perplexity 等，不含 Claude。开启 TUN，关闭 Clash 自己的系统代理开关；按下述规则处理 AdGuard for Mac，不改写第三方 PAC，也不增加 WebRTC 或 AI 分组补丁。验收增加 ChatGPT、Gemini 和 Agent 联网。
3. **档位 3｜Claude/Claude Code**：先完成第二档，再运行现有完整补丁、Claude 区域指纹检测和完整验收。说明全局 UDP 对 QUIC、游戏、语音和视频的影响；只建议台湾家宽优先、其次日本家宽，不自动切换节点。

关闭 Clash 系统代理是为了避免与 TUN 重复接管，不是隐藏代理。明确的 Claude 或 Claude Code 网络配置需求可直接选择或升级第三档。三个档位都进入共同国内域名直连转换；第一、二档在完成共同基线后结束，客户端开关由 Computer Use 完成。只有第三档进入其余完整增强。

### 档位 3 的区域指纹检查

第三档在任何设置修改前，通过 Computer Use 优先识别用户实际打开 Claude 的浏览器，并在同一浏览器打开随 Skill 安装的 `assets/claude-region-check.html`；无法确认时才使用系统默认浏览器并明确记录限制。点击检测、等待结果并向下读取十项信号；单次最多等待 60 秒，超时只刷新重试一次，禁止无限等待、使用 Codex 内置浏览器或命令行请求替代。本地页是单文件页面，不上传完整检测结果；WebRTC 项通过 Google、Cloudflare 的三个 STUN 地址读取公网 IP，再把这些 IP 交给 IPWhois 查询国家代码。STUN 服务会看到连接源 IP，IPWhois 会收到待查询 IP 和查询请求的出口 IP；CSP 只允许 IPWhois 这一条 HTTPS 请求。页面正式支持 macOS 的 Safari、Chrome 和 Windows 的 Edge、Chrome；其他浏览器能运行就记录实际检测结果，不能运行时保持“未验证”并把兼容性限制纳入第一次授权。十项权重为系统时区 24、浏览器语言 18、浏览器可见中文字体 14、国产厂商字体 10、WebRTC IP 泄露 10、国产浏览器/WebView 8、国产品牌设备 6、Intl 区域设置 4、UTC+8 偏移 3、Emoji 平台推断 3；除浏览器语言和 WebRTC 外，项目、权重、分档、颜色和计分函数与 FuckClaude 当前源码一致：0–30 分为绿色“低风险”，31–60 分为橙色“中等风险”，61–100 分为红色“高风险”。WebRTC 只按 STUN 公网 IP 的国家代码计分：只有中国大陆 `CN` 贡献 `+10`，其他国家和地区以及没有发现公网 IP 均贡献 `+0`；不再比较 WebRTC 与网页出口是否相同，无法确认归属地时显示“无法读取”，也不能替代两项专用 WebRTC 验收。不同浏览器会暴露不同的语言、字体、设备和 User-Agent 信号，因此不得借用其他浏览器的值，不得合成一个现实中不存在的指纹。Safari 缺少 Chromium 设备提示、Windows 桌面浏览器没有提供设备型号时使用普通 User-Agent 完成检测，并把设备项标为“有限信息”。浏览器没有提供的值标为“无法读取”，贡献为“未知”；存在任何无法读取项时不显示可比较总分，只显示已知项合计和未知权重。任何非零贡献仍单独显示，但“命中”只按信号分达到上游 `0.25` 门槛统计。JavaScript 被禁用时显示明确提示并禁用检测按钮。本地文件缺失、不可读、JavaScript 被禁用或页面报错时记为“未验证：本地检测页不可用”。检测页提供区域指纹参考分，分数越高表示大陆关联信号越多，但不是 Claude 官方结论，也不能作为 Claude 是否可用的通过条件；它不覆盖 DNS 或 TUN。选择第三档已授权打开本地检测页、这一次国家代码查询和 STUN 探测，不增加单独确认。

浏览器语言项只读取 `navigator.language` 返回的当前浏览器界面语言；`zh-CN`、`zh-Hans` 或 `zh-Hans-CN` 这类中国大陆简体中文计 1，英文、繁体中文、新加坡中文和其他语言计 0，`navigator.languages` 中的后备语言不参与计算。四类可选调整是系统时区、浏览器语言、Intl 区域设置和当前用于 Claude 的国产浏览器/WebView。初检后先保存四项修改前快照，只汇总实际命中项、旧值→建议值和影响，一次请求用户授权，并明确说明“这些调整只降低参考分，不保证改变 Claude 判定；是否应用？”用户只回复“同意”而未指定语言时，默认采用 `Asia/Taipei`、`zh-TW` 和台湾区域设置；明确要求英文时采用 `Asia/Taipei`、`en-US` 和美国区域设置。浏览器语言把目标语言排在第一位。台北与北京、上海同为 UTC+8，不会改变当前时间；区域设置可能改变系统和其他应用的日期、数字格式。国产浏览器信号只描述当前用于 Claude 的浏览器，不把已安装但未使用的浏览器算作命中；可以建议改用 Safari、Chrome 或 Edge 打开 Claude，但不得仅为降低参考分修改系统默认浏览器。只有用户明确要求更改系统默认浏览器时才执行，不卸载原浏览器。本批设置任一步或最终验收失败时，只在当前值仍等于本轮写入值时按快照恢复；用户在期间继续修改过的值不得覆盖。

浏览器可见中文字体、国产厂商字体、设备品牌、UTC+8 时区偏移和 Emoji 平台推断不作为自动修改目标；不得删除字体、伪装设备或 User-Agent，也不得改变实际时钟追分。Emoji 项只按 User-Agent/平台信息推断，不声称真的检测了渲染。只读分类 `ANTHROPIC_BASE_URL` 时：未设置为默认端点；解析失败、非 HTTPS 或包含 userinfo 为端点配置异常；只有 hostname 规范化后精确等于 `api.anthropic.com`、使用默认 443 端口且不得包含 userinfo 时才是官方端点；其余合法 HTTPS 地址为自定义端点。只报告类别，不能输出完整 hostname 或自动更换端点。完成授权设置与网络补丁后，回到修改前实际用于 Claude 的同一浏览器重新扫描；只有两次扫描都完整，或无法读取项集合完全相同，才报告数值变化，覆盖范围不同时分别报告已知项合计和未知权重。任何非零项都照实报告，但参考分不参与网络验收的通过条件。没有 Computer Use 时只能让用户用系统浏览器手动完成两次检测，不能换用内置浏览器。

## Diagnostics 架构

Patch 和 Diagnostics 是两条独立工作流，但共享同一个用途档位。除 AI 服务状态前置检查外，每次诊断先读取档位，并把它转换为需要保持的能力、禁止检查或修改的内容、修复后的回归项目。用户报告故障不能自动升档；只有用户明确增加用途时才改档。单项 Clash 配置修复仍属于 Diagnostics，并复用 Patch 的安全事务；完整增强只用于档位 3。

### AI 服务状态前置检查

用户报告 OpenAI、Anthropic 或其他 AI 服务无法连接、反复重连、流式响应中断、超时、明显变慢或服务错误时，第一步先确定服务提供商并查询对应提供商的官方状态页和事件历史，再读取用途档位和检查本机配置、节点、DNS 或日志。检查记录查询时间、故障时间窗、事件状态、受影响组件与匹配程度。匹配事件是服务端异常的有力证据，但不自动解释每一次失败；查不到事件也不排除区域性、账号、模型或尚未公布的异常。随后仍进行当前档位允许且确有必要的本机核对，不能因为存在官方事件就顺手修改本机配置。

解决原始问题是 Diagnostics 的结束目标。只读检查是第一阶段，不是交付结果；诊断结论不是完成，解释、建议和状态说明不能代替行动。确认原因后，主代理在已有授权、用途档位和产品边界内连续完成修复、复测、继续迭代，直到原始症状与相关回归项通过，或出现工具强制确认、缺少敏感输入、越权、不可恢复风险等真实阻塞。

- **档位 1：** 维护全部订阅共同的国内域名直连基线，并保障普通境外网站与系统代理；不检查或修改 TUN，不运行 DNS 泄漏、WebRTC、AI 分组或 Claude 检查。
- **档位 2：** 继承共同国内域名直连基线，增加 TUN、普通海外 AI 与 Agent 联网；不运行 DNS 泄漏、WebRTC 或 AI 分组检查。
- **档位 3：** 同时维护普通浏览、海外 AI、Claude、DNS、WebRTC 和 AI 分流。共享网络路径发生修改时，复测本次改动可能影响的第三档能力；只改浏览器或单个应用时不机械运行无关测试。

诊断采用同一个闭环处理不同问题：

1. AI 服务连接问题先完成官方状态检查；其他问题从下一步开始。
2. 把用户描述转成可以复现或监测的现象。
3. 有 Computer Use 且故障能在界面看到时，先在用户实际应用中复现；保存修改前基线，并用异常目标加至少两个健康对照建立范围矩阵。
4. 同时保留多个解释，按区分能力选择浏览器、应用、DNS、Mihomo 连接、传输质量、系统计数和相关日志证据。
5. 用独立证据和反证更新判断；资料不足时建立有期限的观察窗口。
6. 执行最小、可恢复的修复。两次假设或修改无效后恢复全部试验并做诊断重置，没有新证据不进行第三次修改。本机无法处理时，基于已确认的问题类别查询当前官方方案。
7. 在同一应用、账号、目标和动作中连续复测原始症状，并用小白能懂的语言报告结论、证据、修复、结果和未知项。

### 因果判定门槛

把伴随事件、设置、进程、设备、节点或服务认定为反复故障的主要原因前，必须验证原始事件而非引用文本，确认时间方向，并在同一时间范围报告候选事件命中率、故障覆盖率、“有候选事件但没有故障”和“没有候选事件却发生故障”。多个日志若只是记录同一个下游现象，不能算两种独立证据。最后用单变量干预重复触发与恢复原始症状；无法安全干预时，必须有直接记录上游失败的独立证据替代。全部门槛通过时写“已确认的主要原因”；尚缺门槛时固定写“下一项验证”和“尚缺门槛”，不能把有力支持改称主因。机制解释只能说明为什么可能发生，不能补足实测证据，也不能据此写成主要原因。

预计超过 10 分钟且能拆出多路独立只读证据时，主代理可以安排多个 Sub Agent 并行调查；它先固定档位、范围和统一时间窗，并保证同时只有一个界面操作者、一个主动流量生成者。Sub Agent 不写配置、不更新订阅、不恢复备份，也不作最终判断；写入、更新、恢复和结论由主代理串行完成。

Skill 不维护一张每次全跑的诊断清单。具体工具同时由现场证据和保存档位决定；完整 DNS/WebRTC 与 AI 分流验收只属于档位 3。macOS 使用实时进程、连接和接口数据，不能虚构不存在的历史；Windows 可以读取系统保存的网络用量，但聚合总量不能冒充逐应用归属。

浏览器诊断必须把主文档网络耗时、关键资源、首次显示和加载结束分开。配置缺陷不能直接当成故障原因。怀疑扩展、过滤器或共同网络组件时，目标开关对照只回答该目标是否受影响；还要用至少两个健康对照判断范围。只有单站异常时修目标交互；跨目标出现同类故障时修共同组件本身，不按网站不断加例外。重叠接管与职责分层也受档位限制：第一档不盘点或切换 TUN；第二、三档只有证据指向共同路径时才检查。修复后验证原始症状和当前档位中可能受影响的能力；无改善或功能退化立即恢复，不能因为浏览器问题顺手应用更高档位的 Clash 配置。

AdGuard for Mac 是 Patch 和 Diagnostics 共享的已知兼容路径。档位 2、3 检测到它以 `Network Extension` 与 Clash TUN 同时透明接管时，通过 Computer Use 在 AdGuard 自己的界面切换为“自动代理”，让 Clash TUN 负责最终分流、DNS 和 UDP，AdGuard 负责遵守系统代理的过滤。Mihomo 使用 Fake-IP 时，AdGuard 可能继续缓存旧假地址；若日志中的目标域名和 Fake-IP 与 Mihomo 当前反向映射交叉证明该 **Fake-IP 被重新分配**给另一个域名，浏览器会收到错误证书或丢失关键脚本。此时只通过 AdGuard 界面启用 **AdGuard 出站代理**：HTTP、`127.0.0.1`、运行配置中已确认由当前 Mihomo 监听的 **Mihomo HTTP 代理端口**，让 AdGuard 按域名把请求交给 Mihomo。不得固定假设端口、覆盖已有的非 Clash 出站代理或关闭 HTTPS 过滤；修改前记录完整原状态，任何复测失败都恢复 AdGuard 原状态。修改后复测至少三个无关目标、Safari 和 Chrome 的广告过滤，以及当前档位可能受影响的能力。Clash TUN 存在时不得把 AdGuard 改为 `Network Extension`；禁止按应用调整 AdGuard 过滤范围，因为产品不能穷举用户安装的应用。检测到应用本身不是故障结论；Diagnostics 通过单变量前后对照确认，无改善立即恢复。第一档需要 Clash 占用系统代理，Windows 的产品机制也不同，两者都不照搬这个组合。不得逐站加例外、改写 PAC、直接编辑 AdGuard 设置或停用、退出、卸载 AdGuard。

国内请求误走海外是第一档共享故障，档位 1、2、3 都处理。目标在国内数据集、实时连接却命中海外代理、而大陆 DoH 与直连稳定时，直接修复全部订阅的共同提供器、DNS 引用和路由引用，不为 Kimi、欧陆词典等单站加例外。证书身份错误单独归类：先核对系统代理所有权，把 CFNetwork 的 PAC 查询中断、回环端口所有者、TLS 失败和 Clash `ProxyConfigHelper` 活动放进同一时间线；只有目标域名使用的假地址与 Mihomo 当前映射到其他域名的地址一致时，才走上述 AdGuard Fake-IP 修复。没有该证据就建立观察窗口，不改出站代理。绝不点击忽略证书、添加 Apple/iCloud 规则、关闭全局 HTTPS 过滤或归咎于订阅节点。

## 平台架构

两端按“用户可获得的能力”保持对等，客户端机制可以不同：都必须支持用途档位、Diagnostics、配置历史、安全更新、档位 3 策略、实时分流和浏览器验收；同一公开功能必须有相同的成功条件、失败语义和机器结果。Windows 客户端运行时的普通备份恢复只能比较和准备，不能停止客户端或把文件恢复假装成运行内核恢复；这属于执行时机不同，恢复能力与验收要求不变。Windows Computer Use 已在 2026-07-09 的桌面版中提供；当前会话实际启用时，Windows 与 macOS 都用它完成客户端开关、原应用复现和浏览器测试。Windows 只能操作前台桌面，设备需保持解锁；没有工具时不能声称已自动验收。脚本和本地控制器能可靠完成的步骤不改走界面。

### macOS

备份恢复必须先读取有效的已保存用途档位，再按该档位校验；档位缺失或损坏时零写入。

三个档位都检查 Mihomo，并处理当前使用的本地目录或 iCloud 容器；普通安装先生成、二次转换并用 Mihomo 校验整批候选，任何一份失败时全部不写。用户明确改档时，基础环境检查和初始快照通过后先用私有临时文件替换用途档位，并同步文件和父目录；失败时恢复旧档位。随后才修改自动更新和订阅。三个档位都把 ClashX Meta 的 `kAutoUpdateEnable` 设为 `0` 并回读确认；只有原值已确认开启时才保存所有权状态。首次安装后续失败恢复自动更新和旧档位；已有任一档位时保留关闭状态。第一、二档只写共同国内域名直连基线，第三档再应用完整增强。安全卸载把安装文件删除、自动更新恢复和所有权语义释放放进同一个可恢复事务，失败或中断时同时保留用途档位、关闭状态和所有权。所有权状态采用仅追加的 `prepared`、`installed`、`released` 事件；`released` 文件仍可保留，读取方按最后一条完整事件判断，中断尾段在下次追加时修复。事件追加锁定并核对原文件身份和全部旧字节，并发替换时保留新文件并停止。首条记录先在同目录私有临时文件中完整同步，再以不可覆盖的原子改名发布并同步父目录；目录同步失败就停止，成功前不得写 `defaults`。不得安装永久监听、LaunchAgent、`WatchPaths` 或计划任务。当前订阅写入后自动刷新并清除 Fake-IP 与 DNS 缓存；失败立即恢复。

已有 `prepared`/`installed` 所有权的三个档位重试都直接续写同一记录，不经过先开启、释放、再关闭的窗口。首次安装在关闭自动更新子进程启动前登记回退责任并暂存信号；已有保存档位则保留关闭状态。自动更新回读或恢复失败时返回 `partial`，按同一档位重试。

普通 Patch 与安全更新的最终 Ruby 子流程共用信号交接：执行期间暂存 TERM、HUP 与 INT；没有信号的普通失败按原规则补偿，确认成功时先提交保存档位和自动更新所有权，再以 `partial/operation_committed_interrupted` 处理等待信号。前台进程组信号同时终止子流程、无法确认提交状态时返回 `partial/operation_interrupted_recovery_intent`，保留新档位、自动更新关闭状态和所有权作为恢复意图。

最终子流程使用固定长度的私有提交收据跨越“配置提交—结果输出”边界。Shell 预分配 pending 收据；Ruby 在文件和运行配置事务完成后、输出前原位改成 committed 并同步。stdout 或 JSON 结果文件失败时，外层凭 committed 收据返回 `partial/operation_committed_result_failed`；事务成功但收据发布失败时，Ruby 用专用内部退出状态传递同一结果。收据损坏、不可读或子进程异常终止而无法确认提交状态时返回 `partial/operation_result_unknown_recovery_intent`。这些路径都保留外层状态；只有有效 pending 收据加普通失败才执行补偿。

macOS 安全卸载先完整写入并同步所有自有文件及元数据，再同步 `READY`，之后才允许删除。删除安装文件后同步安装目录；失败时从已同步暂存恢复并再次同步。边界前中断只清理不完整暂存；边界后恢复以不可覆盖的原子文件发布完成，任何时刻被强制结束都不能留下半文件，下一次卸载可从同一事务继续。

macOS 普通安装、安全更新、安全卸载和变更型 Ruby 入口共用备份目录中的跨进程操作锁，锁从读取用途档位持续到最终提交。子流程验证继承的锁描述符、固定锁文件身份和锁仍被实际持有，伪造环境标志不能跳过互斥。普通 Patch 与安全更新在锁内核对显式档位和固定用途档位文件，任何下载或写入前不一致就停止；自动更新变更只由已验证锁的安装、卸载和恢复子流程调用。并发写操作最多等待 5 秒，超时后以 `operation_in_progress` 零修改退出。Ruby 内部锁继续保护单次配置事务；外层锁负责档位、自动更新所有权、订阅修改与卸载删除之间的顺序，避免卸载在最终核对后误删另一个安装刚发布的新状态。卸载在 `READY` 后中断时，下一次安装或安全更新先在锁内完成公开卸载；自动更新已经处于本工具拥有的关闭状态时，`already_disabled_owned` 作为幂等成功继续。只有成功收据和暂存目录清理都可验证时才继续，失败则保留恢复状态并停止。

帮助、读取档位和无效参数不得创建锁或修改状态。所有写操作只使用 ClaudeEasy 当前状态目录与 wrapper lock；文件描述符跨入口委托保持持有。已有待恢复卸载时，先调用公开卸载流程完成恢复，再进入本次安装的档位和环境检查，避免半卸载状态被无关的安装前置条件挡住。

macOS 安全卸载发现未完成的配置事务时，先恢复原文件并重新加载当前原订阅，完成缓存、TUN、代理组、DNS 和连接检查。恢复失败时，在删除安装文件、清除用途档位或恢复订阅自动更新之前停止，并保留配置事务、用途档位和自动更新所有权。

Windows 自动查找 AppHome 时，如果 Roaming 与 Local 两个受支持候选同时存在，所有公开操作都必须拒绝并要求明确指定当前目录；不得通过候选顺序猜测客户端正在使用哪一套数据。

Windows 所有写操作都通过 `.claude-easy.lock` 串行化，并在同一锁内恢复未完成事务、预检用途档位、安装状态、自动更新所有权、安全更新清单和备份目录。

安全更新是独立的显式事务。三个档位都会关闭订阅自动更新。网络正常时不主动建议频繁更新；连接异常、服务商通知订阅变化，或距离上次更新已数月时，引导用户说：“请帮我安全更新全部订阅”。本次只执行一次获取和更新，不长期重新开启周期自动更新。它从客户端清单读取全部远程订阅，先为全部当前文件建立带日期时间的备份，再下载、解析、按档位转换并校验全部候选；macOS 每份响应最多 32 MiB。只有全部成功才统一替换；任一份失败时尝试恢复全部目标，确认所有目标都恢复后才能说“全部保持原样”，恢复本身失败时继续处理其余目标并明确报告。macOS 回滚确认后订阅又被外部刷新时，保留新内容并返回 `safe_update_rollback_superseded`；若运行内核仍待恢复，运行恢复状态优先并继续保留事务，同时说明新内容已保留。若进程在当前订阅加载候选后被强制结束，下一次安全更新必须先恢复文件并重新加载恢复后的当前订阅，运行内核无法恢复时在下载前停止。三个档位都对全部候选重打共同国内域名直连基线，档位 3 再打完整补丁；完成验收后再次确认自动更新关闭。项目不保留订阅后台监听。

用户已经说明服务商订阅开关已打开或倒计时仍有效时，代理必须立即执行安全更新，不得检查或操作服务商后台，也不得使用 Chrome、Browser 或 Computer Use 登录控制面板、检查开关或验证倒计时。正常更新必须先于原因猜测；有多份订阅时尝试每份候选，并逐一报告哪些订阅下载与校验成功、哪些失败。任何候选失败都会阻止整批写入，因此成功候选要报告为“下载与校验成功但未写入”。只有实际更新失败且没有明确的本机故障时，才提醒用户可能存在服务商订阅开关，请用户登录服务商网站，在控制面板找到并打开开关，并明确说明开关关闭时无法更新；不得声称已经检查或确认开关状态。

安全更新与普通 Patch 共用事务恢复入口：从当前存储目录的全部顶层配置识别活动项，包括不在远程订阅目标中的 `config.yaml`。事务同时记录逻辑路径、真实路径、原文件身份、原字节和完整候选；发布前确认逻辑路径与真实路径都仍位于同一个规范配置根目录，符号链接指向目录外时拒绝。文件提交、备份回退与运行加载都继续核对同一路径、身份和候选摘要，报告成功或删除事务记录前再核对整批目标；外部同字节替换或重指符号链接时保留新目标。v2 事务只有同一原 inode 上的完整候选才自动恢复，完整原字节只确认；空文件或任一原字节、候选截断前缀必须保留目标与事务并返回待恢复。没有文件身份的旧版事务不自动覆盖候选。恢复旧事务或回滚本次更新时，原文件重新加载并通过缓存、TUN、代理组、DNS 与连接检查后才提交事务；代理组检查只保留目标配置中仍存在的 Selector，目标仍保留的用户组不能丢失或改选。控制器或运行检查失败时保留记录，阻止下载和新写入，供下一次公开操作继续。

macOS 普通 Patch、安全更新、备份恢复和未完成事务恢复在每次控制器加载前重新核对当前订阅和存储位置。候选校验、下载或写入期间发生切换时绝不加载旧订阅；首次加载前发现变化会恢复本次文件批次，候选已加载后才发现变化则不再加载旧路径并保留事务，等下一次稳定运行恢复。显式配置目录仍绑定调用方指定的规范目录，只复核当前订阅。

当前订阅或存储偏好读取失败时不能按默认值继续；缺少 `selectConfigName` 与偏好导出、XML 解析或目标字段类型失败必须区分。偏好中无关的合法日期、二进制等 plist 字段不得阻止读取字符串类型的 `selectConfigName`。当前目录只有恰好匹配一个活动配置时才能进入写入或运行恢复，零匹配和多匹配都保留未完成事务并停止。

配置历史也是 Diagnostics 的证据。第一次运行保存初始快照，每次写入前保存带日期时间的修改前版本；出现网络故障时先列出备份，按公开的 `created_at` 选择症状出现前的候选。双平台公开备份 ID 都使用不含真实文件名的 `ce-backup-v1-<64 位十六进制>`；JSON 列表从 `items` 返回含 `id` 与 RFC 3339 `created_at` 的对象，JSON 比较返回该 ID、是否相同、备份哈希和当前哈希，使恢复能直接复用同一 ID 与比较时哈希。旧原始编号只保留输入兼容，不再输出。配置差异只输出变化字段与哈希；时间只用于筛选候选，不能代替故障证据。回滚前再次备份当前版本，校验备份、目标与当前哈希；恢复后复测原始症状，恢复或验收失败时恢复回滚前版本。macOS 恢复备份与 Patch、安全更新共用操作锁，并先处理未完成的批量事务；事务恢复改变当前字节时，本次恢复按哈希冲突停止并要求重新比较。macOS 恢复当前订阅后必须通过本地控制器重新加载，保持恢复前的 TUN 与代理组选择，并完成缓存、DNS 和连接检查；文件恢复但运行内核未恢复时单独报告，非当前订阅不触发切换。Windows 客户端运行时不停止客户端来强行恢复。

Ruby 引擎使用 YAML 1.2，保护有效的 REALITY `short-id` 文本。每份候选重新解析、再次转换，并由 Mihomo 1.19.27 以上版本校验；校验最长 30 秒。文件锁有固定截止时间；首次建立私有状态目录时逐级创建并同步每个新目录及其父目录，中途失败后的重试先重新同步已出现的目录，完成前不得写恢复状态、偏好或配置。版本化备份完整写入并设好权限后同步备份目录，成功后才允许后续修改。普通安装和安全更新在第一次整批写入前保存持久事务记录，包含逻辑路径、真实路径、原文件身份、原字节和完整候选。逻辑路径与真实路径必须同时留在规范配置根目录，目录内符号链接写真实目标，指向目录外时停止。事务记录原子发布后必须同步父目录，并在成功后才写配置；事务完成时先用同目录完整临时文件原子替换成 v3 已提交标记并同步父目录，再删除和再次同步目录，删除未持久化时下次只清理标记。标记替换后的首次父目录同步失败必须报告提交状态未知，外层保留当前档位和恢复意图。配置只通过已锁定的原文件句柄先截零、再写入并同步；客户端同时原子刷新时，新 inode 保持在目标路径，本次操作检测到身份变化后停止。进程被强制结束时，v2 恢复只自动处理同一原 inode 上的完整候选；完整原字节只确认，空文件或任一原字节、候选截断前缀保持不变并返回待恢复，不同 inode 按外部刷新保留。`--dry-run` 和 `--no-reload` 只允许普通 Patch；与独立操作组合或一次指定多个独立操作时在任何写入前拒绝。

普通 Patch 的事务完成同时包含文件与运行配置。档位 3 提交前还要同时读取 `/proxies` 和 `/providers/proxies`，沿 AI 分组的当前选择确认全部同名候选都不包含直连、拒绝、兼容、重匹配、`Relay`、未知组态类型、缺失目标或循环，`LoadBalance` 的全部当前成员都必须安全；活动文件无需修改时也执行这项只读检查。备份恢复按保存档位检查；档位 3 必须包含当前策略的全部 AI 规则并位于宽泛规则之前，缺少任一规则或对应分组时失败。若进程在当前订阅加载候选后被强制结束，下一次 Patch 先恢复原文件，再通过本地控制器重新加载原订阅并完成缓存、TUN、原订阅选择器、DNS 与连接检查；只有运行恢复成功才删除事务记录并处理新候选。本次自动刷新回退未能恢复运行配置时也保留事务，失败时停止并由下次 Patch 重试；`--no-reload` 只能恢复文件、保留事务并停止新处理。

macOS 备份恢复先在同一操作锁内完成旧配置事务的文件与运行恢复，再做预期哈希判断。备份替换也先建立持久事务，并把提交真实路径与文件身份交给运行加载和失败回退；相同字节的外部替换不得覆盖。文件已经与备份相同时仍建立相同字节的运行恢复记录。当前订阅的控制器加载和运行检查属于事务提交步骤，强杀或运行回退失败时保留记录，让下次 Patch 恢复备份操作前的文件与运行配置。

### Windows

三个档位都安装带数字档位的 `profiles/Script.js`，让订阅加载或刷新时应用共同国内域名直连基线，并把 `profiles.yaml` 中每个远程订阅的 `option.allow_auto_update` 改为 `false`。`option` 位于列表项首字段或后续字段时使用同一唯一字段模型；重复字段或无法唯一归属的嵌套结构在写入前拒绝。独立状态保存本工具实际改变的远程 uid、原值和原 `option` 形态；原本关闭的项目不纳入所有权。第一、二档不执行其他增强。修改前备份并逐项回读，不依赖 Computer Use；不安装额外后台服务。

客户端运行时，三个档位都不能只写磁盘订阅清单，因为内存仍可能继续刷新，并在退出时覆盖磁盘。安装因此不改用途档位、所有权、脚本或客户端配置，客户端未运行后再重试；档位 3 返回 `client_running_profile_three_deferred`，档位 1、2 返回 `client_running_auto_update_deferred`。客户端未运行时，PowerShell 安装程序可以事务式更新订阅清单和所有权状态；档位 3 另更新应用级 TUN 与 IPv6 设置。同一应用目录的公开写操作用目录内独占锁文件互斥并持有配置目录句柄，路径别名或目录改名不能绕过。每个目标只允许一个最终动作，全部目标父目录和非链接、非硬链接目标先用句柄统一锁定并核对，再通过原文件句柄写入、删除或失败恢复；首次修改前保存持久事务记录，进程被强制结束时由下次操作先恢复。删除事务重建缺失目标时，先在同目录以私有 ACL 创建临时文件，完整写入原字节并 `Flush(true)`，确认最终路径仍缺失后原子发布。目标换成不同文件身份时，只有完整原字节可以直接确认且不得改写，空内容、原文前缀或其他内容都保留目标与事务并失败。版本化备份先写同目录临时文件，完成同步和私有权限设置后才原子发布正式名称；中断的临时文件不会进入列出、初始快照判断或恢复入口。备份目标键使用相对应用目录的规范路径。状态文件使用严格结构和一次读取的字节版本，不能通过普通单文件备份接口恢复。卸载恢复订阅自动更新时只处理仍为本工具写入值的项目；客户端运行且存在应用设置恢复状态时整批不改并返回 `partial`，用途档位继续阻止降档；流程不要求退出、停止或重启客户端。已有脚本只有一个同步 `function main`，且唯一声明之外没有任何裸 `main` 引用时才组合；属性访问、别名、对象简写、结构不明确、异步、递归、额外绑定入口、动态执行、点号函数构造器或值为 `constructor` 的计算属性字符串，在写入前整批拒绝。模板字符串文本保持原样，表达式按普通代码递归检查。组合器先用私有 setup 捕获受管引擎、真实全局以及内置对象和原型的描述符；改名后的旧脚本不进入回调，仍在 Clash 的真实 `try`/Script 顶层执行，保留顶层 `var`、函数、`globalThis`、`this` 和开头 `"use strict"` 字符串的客户端语义。旧顶层结束后先恢复内置对象，再把全局 `main` 封闭为不可配置的受管访问器。受管入口先调用旧 `main`，并在 `finally` 中再次恢复内置对象；旧函数正常返回后才运行受管变换。安全更新只忽略专用边界内的用户代码正文，逐字核对受管引擎和组合结构，并要求受管区块外只有空白或注释；重装可以在组合检查通过后把区块外旧代码迁入专用边界并保留。

存在应用设置恢复状态的 Windows 卸载，把客户端未运行作为文件事务的提交条件。候选和备份生成后，事务取得全部目标句柄并核对身份与原字节，再在发布事务记录前执行该条件；客户端在窗口内启动时事务不写不删，公开入口返回 `partial` 并保留恢复状态。

Windows 三个档位安装、备份恢复和卸载（含安全卸载）中要求客户端未运行的写入，都复用同一个事务提交条件。安全卸载只要需要恢复 `profiles.yaml`、移除全局脚本或删除任何用途档位、所有权、安装状态，就必须等待客户端未运行。事务锁定并核对全部目标后再检查客户端；条件拒绝时不发布事务记录、不写受保护目标，并删除本次事务创建的空目标与准备记录。入口开始前的状态检查只用于提前返回，不能代替提交前检查。

中断的客户端敏感事务恢复也受同一运行边界约束。事务记录和新建文件准备记录持久保存恢复权限；普通安装、卸载、备份恢复及旧版记录默认要求客户端停止，不能根据相同路径反推事务用途。恢复时先独占锁定并核对全部恢复目标，再次检查客户端，确认仍未运行后才批量写入、重建或删除；客户端已运行或在提交检查前启动时返回 `partial/transaction_recovery_pending`，不改中断字节、不删除恢复记录。缺失删除目标的原字节只写入同目录私有临时文件并完成同步，提交条件通过且最终路径仍缺失后才原子发布，条件拒绝或写入中断不会制造可见的空目标或前缀。以后任一公开命令再次进入时继续恢复。只有用户明确触发的安全更新可标记运行中恢复权限，且全部目标必须限定为 `profiles` 目录直属的 `.yaml`/`.yml` 远程订阅和本次验收清单。

Windows 卸载在建立任何恢复候选前检查安全更新清单。清单尚未验收时返回 `safe_update_pending`，保留订阅、备份、清单、全局脚本、用途档位和全部所有权状态，让 `-VerifySafeUpdate` 仍能完成验收或整批恢复；卸载不得制造只有清单、没有验收前提的状态。

同一原文件句柄中的替换写入和失败恢复都先截为零长度，再写入目标字节并同步。较短内容替换较长文件时，即使进程在任意写入边界被强制结束，也只会留下空文件或目标内容前缀；下一次公开操作按持久事务记录恢复精确原字节。

原本不存在的事务目标使用两阶段记录。第一阶段在任何最终路径出现前原子发布私有准备记录，只登记规范相对路径；全部新文件取得句柄、主事务记录写入并同步后，删除准备记录，才开始写入内容。第一阶段中断后，下一次公开操作先删除仍为空且身份稳定的新目标；非空、链接、硬链接或身份变化一律视为外部内容并停止。这样，首次安装和首次建立安全更新清单不会因强杀留下没有恢复记录的空状态文件。

安全更新前从 `profiles.yaml` 核对全部远程 uid 与本地文件；读取索引后持有它和全部远程订阅的只读版本锁，当前每份订阅先确认有非空代理组并通过 YAML、Mihomo，再从锁内同一版本建立脱敏清单和备份、记录 `updated`，清单发布后才释放锁；`updated: null` 表示客户端尚未记录更新时间，按空基线处理。客户端先写订阅、后保存索引的更新若已写出订阅但尚未保存索引，订阅必须先通过基线校验；索引写入在版本锁期间失败，只有清单发布后重试成功才成为本轮时间戳凭据。未通过校验的中间文件不会成为更新前备份。Computer Use 触发“全部更新”后，PowerShell 先要求清单中的每份订阅都以文件 SHA-256 变化或更晚的 `updated` 时间戳证明本轮已经刷新；内容不变但时间戳更新可以通过，两者都不变时保留清单和文件并返回 `safe_update_refresh_pending`。随后确认已安装的受管全局脚本与当前安装包及保存档位一致，并要求受管区块外只有空白或注释；可执行前缀、后缀或额外 `main` 不能判为当前版本。重装可在组合检查通过后迁移并保留区块外旧代码。脚本检查通过后再逐份确认顶层 `proxy-groups` 是非空的块状或行内列表，然后验证 YAML、Mihomo 和自动更新状态；缺少代理组或列表为空时整批恢复。PowerShell 不复制一套不完整的 YAML/JavaScript 解释器，也不把结构前提检查写成已经执行了全局脚本。`profiles.yaml` 映射未变但订阅文件缺失时，从清单绑定且哈希匹配的备份原子重建，并与清单删除一起提交；同一路径重新出现时不覆盖，清单继续保留。只有订阅内容缺失或检查失败，且 `profiles.yaml` 与受管脚本仍与初始快照相同，才在持续锁住两者时整批恢复；索引、脚本或其他验收状态并发变化时返回 `safe_update_verification_retry_pending`，当前订阅和清单保持不变。订阅文件本身并发变化时也不会被覆盖。旧版 v1 清单仍可凭内容变化验收，且不再依赖不会用于自动恢复的旧备份；内容没变但当前订阅完整通过检查时，删除旧清单并返回 `safe_update_legacy_snapshot_required`，允许下一次建立 v2 快照。验收失败时返回 `safe_update_legacy_recovery_pending`，保留当前订阅和清单，不自动写回来源无法确认的旧备份。允许整批恢复 v2 快照时，旧订阅写回与本次清单删除由同一个持久写删事务提交；强制中断后不能把旧订阅当成本次更新结果再次验收。Windows 使用自己的 `verify_routes.ps1` 从 `/rules` 的最后一个 `MATCH` 绑定当前运行配置的主代理组，再结合 `/proxies`、`/providers/proxies`、`chains` 和 `providerChains` 验证本次连接的实际叶子类型，与 macOS 一样用 curl 的独立源端口、TCP、目标域名和新连接 ID 绑定每次测试请求。`Selector`、`URLTest`、`Fallback` 和 `LoadBalance` 四类运行代理组都按实际链验收；八类直连或拒绝出站即使使用自定义名称也不得通过。

两端的分流验证都从 `/rules` 最后一个 `MATCH` 读取当前主代理组，并从 `/proxies` 的当前内存状态识别 AI 分组；四类代理组、八类非代理终点、四个测试目标、1–60 秒观察窗口、`routes_verified` / `route_verification_failed` 结果码以及 `passed` / `failed` / `not_observed` 检查状态必须一致。macOS 参数为 `--main-group`、`--ai-group`、`--observation-seconds`；Windows 对应为 `-MainGroup`、`-AiGroup`、`-ObservationSeconds`。两端的中文输出只报告代理组识别结果和各目标检查状态，不显示代理组名称、当前节点或连接链节点。Windows 分流验证的 `-ControllerUrl` 只允许本机回环 HTTP/HTTPS，不接受 userinfo、查询或片段。控制器密钥只经标准输入交给 `-SecretStdin`，非空 `-Secret` 必须拒绝；请求禁用代理和重定向，命令行、环境变量、输出与日志都不能包含密钥。

## 公开接口与代码组织

所有公开命令都提供 JSON v1：macOS 使用 `--json`，Windows 使用 `-Json`。默认中文输出保持兼容，成功或失败都必须给出统一处理后的摘要；JSON 模式的标准输出只有一个对象，`exit_code` 与实际退出码一致，`code` 和 `operation` 可供自动化稳定判断。`command` 只取 `install`、`uninstall`、`patch`、`verify_routes`，字段和类型由 `claude-easy/references/result-contract.json` 定义。安装包任一必需模块缺失或损坏时都必须在修改 AppHome 前统一返回退出码 `6` 和 `incomplete_package`。两种输出的动态文本都不能包含 URL、密码、UUID、私钥、控制器密钥、完整本机路径或节点名称。Skill 调用脚本时优先读取机器输出。

ClaudeEasy 的公开入口固定在 `claude-easy/`；参数和调用方式不因内部调整而改变。macOS 与 Windows 的大脚本按配置转换、备份与事务、Mihomo 校验、订阅处理、安全更新、运行状态和 CLI 拆分；入口只做编排。模块边界不能改变先校验后写入、失败恢复、并发保护和客户端运行边界。

## 生效与验收

当前订阅只有本地控制器自动刷新和运行检查都通过，才能说补丁已经生效。随后先用 Mihomo 实时连接确认国内网站获得大陆 CDN 并走 `DIRECT`、Google 走主代理组或订阅明确提供的非 AI 专用代理组、OpenAI/Anthropic/Claude 走 AI 节点，再检查两项 WebRTC 页面和 DNS 深度测试。Google 不能走 `DIRECT`；有独立主组时也不能走 AI 分组，只有 AI 分组兼任主组时允许共用。有 Computer Use 时由代理完成网页操作；没有时给用户中文步骤并要求返回失败截图。只有分流正确、三项网页都没有红色提示，且没有未代理公网 IP、私网地址或本地运营商 DNS，才能说验证通过。

Claude 联网只由分流验证脚本完成。任何 Patch、Diagnostics、复测或安全更新都不得用 Computer Use、浏览器自动化或系统浏览器打开 `claude.ai`，也不得进入已登录账号、读取账号页面或发送测试消息。用户要求“完整流程”“确认 Claude 可用”或“不要停”都不扩大这项授权；浏览器只打开本地区域检测页和三项 DNS/WebRTC 页面。

## 测试策略

`tests/fixtures/main_group_cases.json` 是 macOS Ruby 与 Windows JavaScript 共用的配置转换 conformance 案例。每个案例用人工确认后的 `expected_config_sha256` 锁定完整结果，两端必须读取同一输入、分别匹配该摘要，再对完整输出做深比较；每个发生变化的案例都要再执行一次，并确认第二次不再变化。

覆盖率随拆分后的全部生产模块统计：macOS 纯配置转换核心、独立 Ruby 分流验证器与 Windows JavaScript 转换引擎要求 100% 行覆盖，JavaScript 同时要求 100% 函数覆盖；包含操作系统适配、文件事务和 CLI 的 macOS 生产模块合计行覆盖不得低于既有门槛。代码移到新模块不能让统计范围缩小，门槛只能上调。PowerShell、Shell 与 CMD 以真实参数、退出状态、文件副作用和禁止副作用的行为测试为准，不用源码字符串或无断言执行凑百分比。备份先于写入、版本与路径门槛、二次转换、并发变化、自动更新、整批恢复、SHA-256 恢复保护、运行/未运行边界、机器输出协议、脱敏和超时都必须有回归场景。CI 同时禁止在生产脚本加入覆盖率忽略标记。

需要使用本机安装 Mihomo 的测试属于显式集成测试，不计入可重复覆盖率；默认测试使用受控内核模拟验证相同的命令、超时和失败状态。CI 的 macOS 真实内核 runner 必须验收绑定内核 SHA-256 与本次随机 nonce 的完成凭据，确认档位 1、2、3 的原始配置和补丁产物六次校验全部完成；提前返回、缩短循环或缺少任一阶段都失败。本机集成测试失败必须单独报告，不能通过降低断言或伪造通过来处理。

## 固定文档

- `README.md`：面向用户的完整功能说明：安装、用途档位、补丁内容、诊断方式、平台机制、安全更新、恢复与限制。
- `claude-easy/SKILL.md`：代理必须执行的流程。
- `claude-easy/references/patch-policy.md`：详细产品规则、异常和状态。
- 本文档：产品目标与架构。
- `AGENTS.md`：开发、测试和发布规则。
- `tests/baseline.md`：现行自动化测试范围，不定义产品功能。

不得自行增加新的需求入口或汇总文档。需求变化时直接更新上述固定文件。
