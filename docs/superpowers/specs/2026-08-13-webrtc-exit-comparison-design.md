# WebRTC 出口对照设计

## 目标

本地区域指纹页不能把代理出口误报成真实 IP 泄漏。WebRTC 项只在检测地址绕过网页代理出口，或浏览器直接暴露本地网络地址时贡献 10 分。

## 判定机制

用户点击检测按钮后，页面同时通过已披露的三个 STUN 端点收集 ICE 候选，并通过一个 HTTPS 请求读取网页正常访问所用的公网出口。所有比较只在页面内存中完成，不显示、记录或发送 STUN 候选地址。

- 没有公网候选：0 分，显示“未检测到 WebRTC 公网出口”。
- 公网候选全部与同协议族网页出口一致：0 分，显示“WebRTC 与网页代理出口一致”。
- 任一公网候选与同协议族网页出口不同：10 分，显示“WebRTC 出口与网页代理出口不一致”。
- 暴露可解析的私网或链路本地 host 候选：10 分，显示“WebRTC 暴露本地网络地址”。
- HTTPS 出口读取失败、缺少同协议族参照或探测失败：该项无法读取，10 分作为未知权重，不生成可比较总分。
- relay 候选、mDNS 主机名和重复候选不参与泄漏判定。

## 隐私与界面

按钮点击前不创建 WebRTC 连接，也不发出 HTTP 请求。按钮前明确说明 Google、Cloudflare 会看到 STUN 连接源公网 IP；HTTPS 出口服务会看到正常网页请求的公网出口，但不会收到 STUN 候选。页面、控制台和结果不展示具体 IP。

本地页是快速筛查；两项专用 WebRTC 页面仍是完整档位 3 的独立验收依据。

## 测试

Node 测试覆盖出口相同、出口不同、无候选、私网、IPv4/IPv6 不可对应、relay、重复候选和出口读取失败。真实浏览器测试覆盖 Safari/WebKit 与 Chrome，确认点击前零网络请求、点击后只有披露端点、页面无 IP 文本、重新扫描清除旧结果。策略合同同步锁定相同语义。
